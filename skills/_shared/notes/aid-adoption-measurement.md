# Замер внедрения AID в макетах — черновик методики

> Статус: Draft · v0.1.0 · обновлено 2026-10-14

Задача AID-21, куратор — PD. Отправная точка — аудит AID-LU-13 от
2026-10-13 (пять страниц Rider и Driver): 0,2 % экземпляров из AID, 86 % —
из старой библиотеки; у Driver для 76–87 % экземпляров старой библиотеки
есть одноимённый аналог в AID; в библиотеке Rider — 19 компонентов. Сам
отчёт пока в папке чата LU; копия запрошена в #205. Пока её нет, правила
счёта ниже — предложение, и их нужно сверить с тем, как считал аудит:
иначе первая точка ряда и следующие будут несравнимы.

## 1. Что измеряем

Одна главная цифра — **доля экземпляров компонентов из библиотек AID** в
выбранных макетах продукта. Рядом — то, что объясняет её и показывает
путь к росту.

| Метрика | Формула | Зачем |
|---|---|---|
| Внедрение AID | `aid / всего` | главная цифра для Presentbook |
| Старая библиотека | `legacy / всего` | сколько осталось заменить |
| Локальные | `local / всего` | компоненты, которых нет ни в одной библиотеке |
| Готово к замене | `legacy с аналогом в AID / legacy` | сколько старого заменяется без новых компонентов (у Driver сейчас 76–87 %) |

`всего = aid + legacy + local + other`. `other` — экземпляры из
библиотек, не относящихся ни к AID, ни к старой библиотеке продукта;
показываются отдельно, если их больше 1 %.

## 2. Правила счёта

- **Единица — экземпляр компонента** (`INSTANCE`) на странице макета.
- **Только верхний уровень.** Экземпляр внутри другого экземпляра не
  считается: вложенное — часть родителя, иначе одна кнопка в карточке
  посчитается дважды. Вложенные экземпляры — отдельный срез по желанию,
  в главную цифру не входят.
- **Источник экземпляра** определяется по его главному компоненту:
  - `aid` — главный компонент в опубликованной библиотеке AID продукта;
  - `legacy` — в старой библиотеке продукта;
  - `local` — в том же файле, не из библиотеки;
  - `other` — в любой другой библиотеке.
  Списки библиотек — по ключу библиотеки, а не по имени: имена
  повторяются и меняются.
- **Иконки — отдельно.** Их на порядок больше, чем остальных компонентов,
  и они смешали бы главную цифру. Отдельная строка с той же формулой.
- **Отсоединённые экземпляры** (detach) надёжно не распознаются: это
  обычные фреймы. В замер не входят; если аудит считал их по-другому —
  записать, как.
- **Скрытые слои** не считаются.

## 3. По каким страницам

- **Выборка фиксирована** на продукт: список «файл → страница», которые
  дизайнеры считают рабочими макетами (не черновики, не архив, не сама
  библиотека). Первая выборка — пять страниц аудита AID-LU-13.
- Выборка меняется только явно, с новой версией выборки; цифры по разным
  выборкам на одном графике не сравниваются.
- Ключи файлов Figma в публичном репозитории допустимы (решение D-17 чата
  Style Migration: без прав в Figma ключ доступа не даёт). Имён дизайнеров
  в выборке и отчёте нет — только роль, если нужна.

## 4. Как повторяем

- **Периодичность** — раз в месяц и перед релизом библиотеки AID; дата
  замера — дата снятия, не публикации.
- **Инструмент** — скан через Figma Plugin API по выборке. Чем сканировать
  — открытый вопрос (§6): у нескольких продуктов AID уже есть сканеры
  макетов.
- **Каждая точка ряда несёт версию методики и версию выборки.** Меняется
  правило счёта — MINOR методики и пометка разрыва ряда в Presentbook.

## 5. Формат данных для Presentbook

Предложение. Формат станет стыком «Замер внедрения» между стандартами
(данные) и Presentbook (показ), меняется только согласованно.

Файл на точку замера: `products/<id>/adoption/<YYYY-MM-DD>.json`.

```json
{
  "product": "driver",
  "date": "2026-10-13",
  "methodVersion": "0.1.0",
  "sample": {
    "version": 1,
    "pages": [{ "fileKey": "…", "page": "…" }]
  },
  "components": { "aid": 0, "legacy": 0, "local": 0, "other": 0 },
  "icons": { "aid": 0, "legacy": 0, "local": 0, "other": 0 },
  "legacyWithAidAnalog": 0,
  "source": "AID-LU-13"
}
```

- Хранятся только **счётчики**, проценты считает Presentbook: так нет
  округлений, которые расходятся между файлом и страницей.
- `source` — откуда точка: номер задачи или аудита.
- Presentbook читает папку целиком и строит ряд по `date`. Новый вход
  сборки вне портала требует строки в `paths` workflow
  `presentbook-yc.yml` — это общий файл, через PD.

## 6. Открытые вопросы к PD

1. Сверка правил §2 с отчётом AID-LU-13 — после копии из #205. Если аудит
   считал иначе (например, вложенные экземпляры), первая точка либо
   пересчитывается, либо помечается как точка по другой методике.
2. Чем сканировать: сканер одного из плагинов AID, Figma MCP или
   отдельный скрипт. Скан — код продукта, делается в его чате.
3. Где списки библиотек (`aid`, `legacy`) с ключами: предлагаю поле в
   `products/<id>/product.json`; это меняет формат манифеста, который
   читает Presentbook, — согласованно с его чатом.
4. Кто снимает замер по расписанию: AI Ops · Standards по поручению или
   владелец сканера.
