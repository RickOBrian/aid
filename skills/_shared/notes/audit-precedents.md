# Прецеденты аудитов

Зачем: не выдумывать решение заново, если такой случай уже был. Это сырьё для
стандартов — повторяющийся прецедент становится правилом гейта или стандарта.

**Что записываем:** решение, которое обобщается — тип расхождения и как с ним
поступили. **Не записываем:** решения про конкретный экран, разовые правки,
цифры (они в JSON аудита).

Запись — 3–4 строки:

```
### <тип случая>
Случай: что расходится, в общем виде.
Решение: что делаем. Почему: довод PD.
Откуда: <аудит>, находка N, дата.
```

### Системный статус-бар старого поколения
Случай: в макете статус-бар старого iPhone (44, «чёлка»), в библиотеке продукта — современный (54, Dynamic Island).
Решение: берём современный из библиотеки; фон компонента прозрачный; Dynamic Island не рисуем — это рамка устройства, не интерфейс. Почему: целимся в актуальные устройства, один статус-бар на продукт.
Откуда: rider-1, Navigation, находка 1, 2026-10-18.

### Подложка под статус-баром
Случай: под статус-баром градиент или заливка для читаемости поверх карты.
Решение: это слой макета, не часть компонента статус-бара; стиль — из библиотеки продукта, нет подходящего — кандидат в стиль по правилам нейминга.
Откуда: rider-1, Navigation, находка 1, 2026-10-18.

### Зазор под статус-баром меньше привычного
Случай: после замены статус-бара на более высокий зазор до верхних кнопок сократился (16 → 6).
Решение: кнопки не двигаем, если фон под ними неоднородный (карта, градиент) — малый зазор оптически компенсирован. Почему: глаз не считывает 6 px на неровном фоне.
Откуда: rider-1, Navigation, находка 1, 2026-10-18.

### Компонент не переключается между режимами
Случай: цвета системного компонента (статус-бар) заданы hex — в тёмном режиме не перекрашиваются.
Решение: меняем компонент — цвета на токены. Где цвет должен следовать режиму и где оставаться постоянным (белый статус-бар на фото в обоих режимах) — разные токены, тип разносится через Property по стандартам.
Откуда: rider-1, Navigation, находка 1, 2026-10-18.

### Градиент из библиотеки и тёмный режим
Случай: подложка-градиент в макете; кажется, что стиль-градиент без режимов.
Решение: стиль градиента — один, его точки привязаны к переменным коллекции `gradients` (`<Имя>/Step N`, режимы Day/Night); режим красит градиент сам. Проверять привязку точек, а не только стиль.
Откуда: rider-1, Navigation, находка 1, 2026-10-18; образец — `tokens/driver-gradients-changelog.json`.
