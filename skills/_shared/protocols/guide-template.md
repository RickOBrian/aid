# Шаблон гайда

> Статус: Alpha · v1.0.1 · обновлено 2026-09-20

Этот файл описывает форму, а не содержание. Эталон оформления по-прежнему —
`semantic-color-tokens-guide.md`; здесь зафиксировано то, что к нему
добавляется для публикуемой альфы стандартов.

Сам файл не является гайдом и не попадает в аудит `guide-lint`
(он не подходит под маску `*-guide.md`).

---

## 1. Frontmatter

Порядок полей обязателен. Новые поля помечены звёздочкой.

```yaml
---
destination: skills/_shared/
name: <имя файла без расширения>
metadata:
  version: "2.0.0"
  status: alpha              # * draft | alpha | beta | stable | deprecated
  platforms: [web, ios, android]
  owner: design-system-team
  lastReviewed: "2026-09-20" # * дата последней сверки содержания
  machineFile: <id>.json     # * машинный слой рядом, либо null
description: >
  Многострочное описание на русском.
---
```

Правила:

- `name` совпадает с именем файла.
- `version` — SemVer по `semver-guide.md`.
- `status` дублируется в строке статуса под заголовком — это единственное
  разрешённое дублирование.
- `lastReviewed` двигается только при сверке содержания, не при правке
  опечатки.
- `machineFile` — `null`, пока машинного слоя нет. Пустая строка недопустима.

Чего во frontmatter **не бывает**: волны, признака «входит в альфу»,
маршрута публикации, списка зависимостей. Это живёт в
`standards-registry.json` и дублированию не подлежит.

## 2. Шапка документа

```markdown
# Название гайда

> Статус: Alpha · v2.0.0 · обновлено 2026-09-20
```

Формат строки статуса: `Статус: <Status> · v<version> · обновлено <дата>`.

Статус пишется с заглавной, значение совпадает с `metadata.status`.
Версия в строке статуса обязана совпадать с `metadata.version` — сейчас
это расходится в `platforms.md` (frontmatter 1.1.0, заголовок v1.0.0).

После строки статуса — горизонтальный разделитель.

## 3. Порядок разделов

Обязательный скелет стандарта:

| № | Раздел | Обязателен | Назначение |
|---|--------|-----------|------------|
| 1 | Назначение | да | Зачем документ и где его границы |
| 2 | Связь с другими гайдами | да | Таблица: гайд → что оттуда берётся |
| — | Содержательные разделы | да | Нумерация сквозная |
| N−1 | Проверка | для стандартов | Чеклист готовности или контрольные вопросы |
| N | Changelog | да | Последний раздел, всегда |

Правила:

- Все разделы верхнего уровня нумерованы: `## 1.`, `## 2.`, далее по порядку.
- Глубина — не ниже `###`. Нужен четвёртый уровень — раздел пора делить.
- «Связь с другими гайдами» указывает, **что именно** берётся из соседа, а
  не просто называет файл. Ссылка без предмета заимствования — повод
  задуматься, нужна ли она.
- Раздел не пересказывает содержание соседнего гайда. Дельта — да,
  пересказ — нет: два пересказа неизбежно разойдутся.

## 4. Changelog

- **1.0.1** — 2026-09-20. guide-lint: нормализация формы.
Последний раздел, обратный хронологический порядок:

```markdown
## 5. N. Changelog

- **2.0.0** — 2026-09-20. Что изменилось и почему, одним абзацем.
- **1.1.0** — 2026-08-15. Первая версия.
```

- Формат записи: `- **X.Y.Z** — YYYY-MM-DD. Описание.`

- MAJOR-запись обязана называть, что именно сломалось для читателя.
- Гайд без раздела Changelog не может быть опубликован.

## 6. Разметка

Гайд публикуется рендерером из markdown (ADR-002), поэтому разметка
ограничена тем, что рендерер умеет:

**Разрешено:** заголовки `##`/`###`, абзацы, списки, таблицы,
блоки кода с явным языком, цитаты-блоки, горизонтальные разделители,
inline-код, ссылки.

**Запрещено:** сырой HTML, `<style>`, `<div>`, `<details>`, `<img>`.

**Исключение:** гайды с живыми свотчами токенов
(`semantic-color-tokens-guide.md` — `<style>` + блоки `token-color`,
рендерятся через `token-viz.js`). Такие страницы остаются на React
и в общий рендерер не переводятся. Исключение фиксируется в
`standards-registry.json`, а не решается на месте.

Оформление:

- Таблицы выровнены пробелами, не минимальным pipe-синтаксисом.
- Токены — дефисная нотация: `bg-accent-main`, не `bg.accent.main`.
- Блоки кода всегда с языком: ` ```tsx `, ` ```swift `, ` ```kotlin `, ` ```json `.
- Пути к файлам и имена пропов — в inline-коде.

## 7. Связь с машинным слоем

Когда у гайда есть `machineFile`, действует правило разделения:

| Слой | Что содержит |
|------|-------------|
| `.md` | Объяснение, границы, примеры, обоснование решений |
| `.json` | Перечисления, таблицы соответствий, правила как данные |

- Версии `.md` и `.json` совпадают всегда. Разошлись — блокер.
- Факт существует в одном месте. Если список состояний лежит в JSON,
  гайд на него ссылается и может показать, но не заводит второй список
  «для удобства».
- Правка правила начинается с JSON, потом отражается в прозе.

## 8. Проверка перед публикацией

- [ ] Frontmatter полон, порядок полей соблюдён
- [ ] `metadata.version` и версия в строке статуса совпадают
- [ ] `metadata.status` и слово в строке статуса совпадают
- [ ] Разделы пронумерованы, глубина не ниже `###`
- [ ] Есть «Назначение» и «Связь с другими гайдами»
- [ ] Changelog — последний раздел, запись о текущей версии есть
- [ ] Сырого HTML нет либо исключение зафиксировано в реестре
- [ ] Все ссылки на файлы ведут в существующие пути
- [ ] Запись в `standards-registry.json` соответствует файлу
- [ ] При наличии `machineFile` — версии совпадают

## 9. Что требуется доработать в guide-lint

Скилл `guide-lint` v1.0.0 проверяет более раннюю редакцию формы. Расхождения,
которые нужно внести (задача W3-5):

| Пункт | Сейчас в guide-lint | Нужно |
|-------|--------------------|-------|
| Строка статуса | `Статус: Draft\|Stable · vX.X.X` | Пять статусов + дата обновления |
| Новые поля | не знает | `status`, `lastReviewed`, `machineFile` |
| Сходимость версий | не проверяет | frontmatter ↔ строка статуса ↔ реестр |
| Ссылки на файлы | не проверяет | все пути существуют |
| Машинный слой | не знает | версии `.md` и `.json` совпадают |
| Область аудита | `*-guide.md` | `component-standards.md` под маску не подпадает |

Отдельно: контекстный блок скилла ссылается на `skills/_shared/protocols/git-workflow.md`,
которого больше нет — файл консолидирован в `skills/_shared/protocols/git-workflow.md`
(2026-09-08). Ссылку нужно починить.
