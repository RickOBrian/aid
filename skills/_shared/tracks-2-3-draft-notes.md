## Трек 3 — синхронизация Cursor и Perplexity

### Принятый принцип

При расхождении между Project Files в Space и реальным состоянием репозитория — **репозиторий (то, что видит и меняет Cursor) считается источником правды**.

### Поведение Perplexity (c 05.09.2026)

- Не считать расхождение автоматически багом — это норма асинхронных сессий.
- Если Project File устарел — явно предупреждать, не считать его актуальным.
- Не считать багом, если Cursor создал/изменил что-то без участия Perplexity.

### Что не решено

1. Зафиксировать общий принцип в `space-context.md` — предложено, не подтверждено.
2. Приносить обновлённые версии ключевых файлов в Space перед большим промтом.
3. Помечать в файлах дату последней синхронизации с Perplexity Space.
