# Core Space Tokens Guide

Гайд описывает Core-уровень пространственных токенов: примитивную шкалу значений (`spacing-N`), набор фиксированных размеров (`size-N`) и Core-радиусы (`shape-corner-N`). Core-токены не несут семантики — они являются source of truth для Semantic-уровня.

Semantic-уровень (`inset-*`, `gap-*`, `radius-*`) описан в `semantic-space-tokens-guide.md`.

---

## 1. Принципы Core-уровня

- **Только значения, никакой семантики.** `spacing-8` — это 8px/pt/dp. Не «маленький padding кнопки». Семантика появляется только на следующем уровне.
- **Нелинейная шкала.** Micro-зона растёт с шагом 2 (покрывает тонкую настройку компонентов), Base — с шагом 4, Macro — с шагом 8 и 16.
- **Совместимость с типографической сеткой.** Значения 8, 12, 16, 20, 24 совпадают с `type-lh-*` шкалой Core Typography — вертикальный ритм согласован без дополнительных усилий.
- **Платформенная единица = числовое значение.** `spacing-N` означает `N px` на Web, `N pt` на iOS, `N dp` на Android. Конвертация не требуется.
- **Core не знает про компоненты.** Токены `spacing-button-padding` или `spacing-card-gap` на Core-уровне запрещены — это нарушение слоёности.

## 2. Токены `spacing-N` — примитивная шкала

### 2.1. Структура имени

```
spacing-{N}
```

Где `N` — числовое значение в платформенных единицах. Именование `spacing-N` зафиксировано в `token-rules.md` как прецедент (`spacing-4`).

**Правильно:** `spacing-4`, `spacing-16`, `spacing-48`
**Неправильно:** `spacing-small`, `spacing-padding-m`, `spacing-card`

### 2.2. Шкала

| Токен | Значение | Зона | Типичное применение |
|---|---:|---|---|
| `spacing-0` | 0 | — | Явный сброс отступа |
| `spacing-2` | 2 | Micro (шаг 2) | Минимальный зазор между связанными элементами |
| `spacing-4` | 4 | Micro (шаг 2) | Внутренний отступ мелких контролов |
| `spacing-6` | 6 | Micro (шаг 2) | Компактный вертикальный inset в плотных компонентах |
| `spacing-8` | 8 | Micro (шаг 2) | Базовый gap между элементами в строке |
| `spacing-10` | 10 | Micro (шаг 2) | Вертикальный padding кнопок среднего размера |
| `spacing-12` | 12 | Base (шаг 4) | Горизонтальный padding кнопок size-s, плотные list row |
| `spacing-16` | 16 | Base (шаг 4) | Стандартный padding компонентов |
| `spacing-20` | 20 | Base (шаг 4) | Горизонтальный padding кнопок size-l |
| `spacing-24` | 24 | Base (шаг 4) | Диалоги, карточки, блоки контента |
| `spacing-32` | 32 | Macro (шаг 8) | Крупные контейнеры и острова |
| `spacing-40` | 40 | Macro (шаг 8) | Вертикальные отступы секций |
| `spacing-48` | 48 | Macro (шаг 8) | Крупные layout-gap |
| `spacing-64` | 64 | Macro (шаг 16) | Расстояния между большими блоками страницы |
| `spacing-80` | 80 | Macro (шаг 16) | Hero / page-level spacing |

### 2.3. Проверка на кнопках

Шкала покрывает типичную тройку размеров ButtonText без хардкодов:

| Размер | padding-v | padding-h |
|---|---|---|
| size-s | `spacing-6` | `spacing-12` |
| size-m | `spacing-10` | `spacing-16` |
| size-l | `spacing-12` | `spacing-20` |

### 2.4. Логика границ зон

Граница Micro/Base — на `spacing-12`. Ниже этого значения нужна точность шага 2, выше достаточно шага 4. Значения `spacing-10`, `spacing-14`, `spacing-18` в шкалу не входят: если продукту такое значение регулярно требуется — это сигнал к пересмотру дизайна или расширению шкалы, а не к стихийному добавлению токена.

### 2.5. Зачем нужен `spacing-0`

Нулевой токен нужен для явных reset-сценариев и для semantic-алиасов вроде `inset-none → spacing-0`. Магическое число `0` в коде компонента выпадает из системы именования.

## 3. Токены `size-N` — фиксированные размеры

### 3.1. Что описывает `size-N`

`size-N` — это габарит объекта, не расстояние между объектами. В современных интерфейсах большинство компонентов работает через Hug / intrinsic sizing, поэтому size-шкала намеренно небольшая.

`size-N` нужен только для:
- Иконок и пиктограмм — всегда фиксированный квадрат
- Минимального touch target — требование accessibility
- Аватаров и других фиксированных круглых элементов

Высота и ширина обычных компонентов (кнопки, инпуты, карточки) через `size-N` не задаются. Их размер определяется контентом, типографикой и `inset-*` токенами Semantic-уровня.

### 3.2. Структура имени

```
size-{N}
```

### 3.3. Шкала

| Токен | Значение | Применение |
|---|---:|---|
| `size-16` | 16 | Иконки xs — inline-графика, вспомогательные |
| `size-20` | 20 | Иконки s |
| `size-24` | 24 | Иконки m — основной размер в UI |
| `size-32` | 32 | Иконки l — крупные акцентные |
| `size-40` | 40 | Иконки xl, аватары s |
| `size-44` | 44 | Минимальный touch target — iOS (44pt) |
| `size-48` | 48 | Минимальный touch target — Android (48dp), аватары m |
| `size-64` | 64 | Аватары l |

> **`size-44` — единственное значение вне кратности 8.**
> iOS HIG требует минимум 44pt для touch target. Кратность принесена в жертву платформенному требованию. Android-минимум 48dp ложится в шкалу органично.

### 3.4. Политика: `spacing-N` ≠ `size-N`

`spacing-24` и `size-24` могут иметь одинаковое число, но это **разные токены с разной семантикой**: расстояние против габарита. Они хранятся в разных неймспейсах и не являются алиасами друг друга.

Рекомендуемая структура в JSON / Style Dictionary:

```json
{
  "spacing": { "24": { "value": 24 } },
  "size":    { "24": { "value": 24 } }
}
```

Это важно: рефактор spacing-шкалы не должен неожиданно затрагивать размеры иконок, и наоборот.

## 4. Токены `shape-corner-N` — Core-радиусы

### 4.1. Почему они в этом гайде

`shape-corner-N` уже зафиксирован как Core-токен в `token-rules.md` наравне с `spacing-4`. Радиусы относятся к пространственной геометрии и служат source of truth для semantic-алиасов `radius-*` из `semantic-space-tokens-guide.md`.

### 4.2. Структура имени

```
shape-corner-{N}
shape-corner-full
```

`shape-corner-full` — специальное значение для pill-форм (9999 или платформенный эквивалент бесконечного радиуса).

### 4.3. Шкала

| Токен | Значение | Типичное применение |
|---|---:|---|
| `shape-corner-0` | 0 | Без скругления — таблицы, разделители |
| `shape-corner-4` | 4 | Мелкие контролы: Badge, Tag, Checkbox |
| `shape-corner-8` | 8 | Кнопки, Input, маленькие карточки |
| `shape-corner-12` | 12 | Карточки среднего размера |
| `shape-corner-16` | 16 | Острова, компактные sheets |
| `shape-corner-24` | 24 | Bottom Sheet, Modal, крупные контейнеры |
| `shape-corner-full` | 9999 | Pill-кнопки, аватары, fully rounded |

Шкала намеренно разреженнее, чем `spacing-N`. Визуальная чувствительность к малому шагу у радиуса ниже — разница между 4 и 6px практически не воспринимается.

### 4.4. Что Core не описывает: топология углов

Core-радиус задаёт только **значение**, не к каким углам применяется. Bottom Sheet скруглён только сверху — это решается на уровне компонента, не через отдельные Core-токены вроде `shape-corner-top-24`.

```swift
// iOS — применение Core-токена на конкретных углах
.clipShape(.rect(
    topLeadingRadius: DSTokens.shapeCorner24,
    topTrailingRadius: DSTokens.shapeCorner24,
    bottomLeadingRadius: 0,
    bottomTrailingRadius: 0
))
```

## 5. Платформенные нюансы

| Аспект | Web | iOS | Android |
|---|---|---|---|
| Единица | `px` | `pt` | `dp` |
| Числа в токенах | Совпадают | Совпадают | Совпадают |
| `shape-corner-full` | `border-radius: 9999px` | `.infinity` или большое число | `RoundedCornerShape(50%)` |
| Touch target | `size-44` → 44px | `size-44` → 44pt | `size-48` → 48dp |

**Web: px vs rem** — Core хранит только число. Формат экспорта (`16px` или `1rem`) определяется платформенным конфигом, не Core-гайдом.

## 6. Антипаттерны

| Антипаттерн | Проблема | Решение |
|---|---|---|
| `spacing-N` для размера иконки | Рефактор шкалы сломает иконки | `size-N` |
| `size-N` для высоты кнопки или карточки | Компонент не адаптируется к контенту | Hug + semantic `inset-*` |
| Хардкод `10px`, `15px`, `22px` | Выход из сетки, потеря ритма | Ближайший `spacing-N` или эскалация в шкалу |
| `spacing-button-padding` на Core | Семантика на уровне примитивов | Semantic-уровень |
| `shape-corner-top-24` как Core-токен | Взрыв числа токенов | Логика углов — в коде компонента |
| `spacing-24` вместо `size-24` для иконки | Разные неймспейсы смешаны | Явная политика из раздела 3.4 |

## 7. Связанные задачи

- **`ds-component-spec.md`** — в шаблоне таблицы токенов строки `padding-h → spacing-4` и `border-radius → shape-corner-8` имеют пустую Semantic-колонку. После финализации `semantic-space-tokens-guide.md` эти строки должны ссылаться на semantic-токены. Прямое использование Core-токена в компоненте является блокером по правилам `token-rules.md`.
- **`platforms.md`** — touch targets прописаны хардкодом. После принятия `size-44` и `size-48` стоит добавить ссылки на токены, чтобы не было двух source of truth.
