# Гайд по состояниям компонентов — v1.1.0

Единые правила нейминга и логики состояний для Figma, Web, iOS и Android.
Состояние — это часть контракта компонента. Нарушение правил нейминга
или комбинирования — блокер в спеке и ревью.

---

## Таблица состояний

Имя состояния в Figma — источник истины.
Разработчики используют термин своей платформы по этой таблице как маппингу.

| Figma    | Web      | iOS         | Android  | Когда используется                              |
|----------|----------|-------------|----------|-------------------------------------------------|
| default  | default  | normal      | enabled  | Базовое состояние                               |
| hovered  | hover    | —           | —        | При наведении курсора (ТОЛЬКО Web)              |
| pressed  | active   | highlighted | pressed  | Зажали, но не отпустили                         |
| focused  | focused  | —           | —        | Фокус клавиатуры (Tab, скринридер)              |
| selected | selected | selected    | selected | Выбран (tab, чекбокс, пункт списка)             |
| disabled | disabled | disabled    | disabled | Недоступен                                      |
| loading  | loading  | loading     | loading  | Спиннер внутри компонента                       |
| skeleton | skeleton | skeleton    | skeleton | Серые заглушки при первичной загрузке           |
| error    | error    | error       | error    | Ошибка валидации — только для контролов форм   |

> **Нотация:** в спеке компонента — имена из столбца **Figma**.
> В коде — имена из столбца соответствующей платформы.
> Пример: `bg-accent-states-hover` — имя токена; `hovered` — имя состояния в Figma.

## Маппинг состояний → токены

| Состояние (Figma) | Semantic-токен                    | Примечание                                 |
|-------------------|-----------------------------------|--------------------------------------------|
| hovered           | `bg-accent-states-hover`          | Только Web                                 |
| pressed           | `bg-accent-states-pressed`        | Все платформы                              |
| selected / active | `bg-accent-states-active`         | selected в Figma = active в токене         |
| disabled          | `bg-accent-states-disable`        | Все платформы                              |
| focused           | `bg-accent-states-focused`        | Web                                        |
| focused (iOS)     | `bg-accent-states-focused-ios`    | iOS                                        |
| ripple (Android)  | `bg-accent-states-ripple-android` | Android                                    |
| skeleton          | `bg-component-skeleton-default`   | Фон заглушки; shimmer — отдельный токен    |
| skeleton shimmer  | `bg-component-skeleton-shimmer`   | Слой анимации поверх skeleton-default      |
| error             | `bg-component-states-form-error`  | Только контролы форм (input, select и др.) |

> **selected vs active:** имя состояния в Figma — `selected`.
> Соответствующий семантический токен называется `bg-accent-states-active` —
> так сложилось исторически (в ките не было компонентов в selected-состоянии
> на момент создания токена). Это маппинговый факт, не противоречие.

> **error — только для форм:** `error` — это состояние контрола формы
> (инпут с красной рамкой и сообщением об ошибке). Красная кнопка «Удалить» —
> это не `error`-стейт, а `variant="destructive"` (appearance компонента).

Полная таблица токенов по платформам — в `token-rules.md`.

## Шпаргалка

- **default** = «живой» компонент, обычный вид
- **hovered** = курсор на компоненте (ТОЛЬКО Web)
- **pressed** = палец или кнопка мыши нажата прямо сейчас (все платформы)
- **focused** = рамка фокуса (Tab на клавиатуре или скринридер)
- **selected** = ✓ галочка стоит / таб активный / пункт выбран
- **disabled** = ❌ серый, не интерактивен
- **loading** = 🔄 спиннер вместо текста (короткое ожидание, 2–3 сек)
- **skeleton** = ⏳ серые заглушки при первой загрузке (компонент ждёт данных)
- **error** = ⚠️ ошибка валидации формы (красная рамка + текст под полем)

## Приоритет при комбинировании

Состояния накладываются друг на друга. Порядок приоритета (сверху вниз):

1. **disabled** — поглощает все интерактивные состояния
2. **loading** — поглощает все интерактивные состояния
3. **pressed** — важнее hovered и focused
4. **selected** / **error** — долгосрочные состояния
5. **hovered** + **focused** — могут быть одновременно

### Допустимые и недопустимые комбинации

| ✅ Допустимо         | ❌ Недопустимо     | Примечание                      |
|---------------------|--------------------|---------------------------------|
| pressed + focused   | pressed + disabled | Space/Enter удерживается        |
| selected + hovered  | loading + pressed  | Активный таб + курсор           |
| hovered + focused   | disabled + loading | Курсор + клавиатура             |
| selected + pressed  | skeleton + focused | Повторный клик на таб           |
| selected + error    | error + disabled   | Поле с ошибкой выбрано          |
| error + focused     | skeleton + loading | Фокус на поле с ошибкой         |

## Платформенные особенности

### 1. Hover на мобиле не существует

- ❌ Не рисуй `hovered` состояния для iOS/Android
- ✅ На мобильных платформах — только `pressed`, `focused`, `selected`

### 2. Focused — это не hover

- `hovered` = курсор мыши парит над компонентом
- `focused` = Tab на клавиатуре или скринридер
- ❌ Не отключай `focused` ради «минимализма» — это блокер доступности
- ✅ Используй `focus-visible` (Web) — показывает рамку только при навигации с клавиатуры

### 3. Loading ≠ Skeleton

- `loading` = кнопка «Сохраняем…» (2–3 сек, спиннер внутри компонента)
- `skeleton` = компонент ждёт данных, показывает серые заглушки

**Кто управляет `skeleton` и `loading`:**
- Компонент **принимает проп** (`isSkeleton`, `isLoading`) и рендерит нужный вид
- Экран или CollectionView **решает когда** передать этот проп — исходя из состояния данных
- Компонент не знает об источнике данных; экран не знает как рендерить заглушку

### 4. Pressed — моментальный отклик

- ❌ Не держи `pressed` дольше 200 мс после отпускания
- ✅ 100–200 мс в `pressed` → сразу переходи в `default` / `selected`

### 5. Error — только для контролов форм

- Применяется к: Input, Select, Checkbox, Radio, FieldCheckbox, FieldRadio
- Не применяется к: Button, Badge, Tag, навигации
- Всегда сопровождается текстовым сообщением под компонентом (не только цветом)
- Для деструктивных действий используй `variant="destructive"`, не стейт `error`

## Skeleton-токены

Skeleton — это не просто серый фон, а двуслойная анимация:

| Токен                          | Назначение                                      | Core-ссылка        |
|--------------------------------|-------------------------------------------------|--------------------|
| `bg-component-skeleton-default`| Базовый фон заглушки                            | `color-neutral-100` (light) / `color-neutral-800` (dark) |
| `bg-component-skeleton-shimmer`| Светлая волна поверх default (анимация shimmer) | `color-neutral-50` (light) / `color-neutral-700` (dark)  |

> **Нотация:** оба токена живут в группе `bg-component-*`, так как это
> состояние отображения компонента, а не акцентный или базовый фон экрана.

## Какие уровни несут состояния

Согласно архитектуре компонентов (см. `ds-component-architecture-guide.md`):

| Уровень             | Состояния                                                                          |
|---------------------|------------------------------------------------------------------------------------|
| **Item**            | Нет собственных. Получает цвет/opacity от родителя через токены                    |
| **Surface View**    | default, hovered, pressed, focused, selected, disabled, loading, skeleton, error   |
| **Structural View** | Те же + expanded/collapsed; отдельные слоты могут быть в loading независимо       |
| **Layout**          | Нет. Решение что рендерить (skeleton/loading/error) — на стороне вызывающего экрана |
