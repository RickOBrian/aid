# Core Typography Tokens — Архитектурный гайд

> Этот документ описывает **Core-уровень типографических токенов**:
> числовые шкалы размеров, межстрочных интервалов, насыщенности и трекинга,
> а также правила их именования и применения. Он не фиксирует конкретные
> значения для брендов или продуктов — только общие принципы.

---

## 1. Область применения

Core-типографические токены — это **сырые числовые значения без семантики**:

- размеры шрифта;
- межстрочные интервалы (line-height);
- насыщенность (font-weight);
- трекинг (letter-spacing);
- семейства шрифтов (опционально, если нужны Core-наборы).

Этот гайд описывает:

- как устроены Core-типографические шкалы;
- как их именовать;
- как адаптировать их к платформам (Web, iOS, Android);
- какие есть стоп-правила (блокеры).

Semantic-типографические токены (ролей `display/heading/body/label`) описываются
в отдельном документе `semantic-typography-tokens-guide.md`.

---

## 2. Модель Core-типографики

Core-типографические токены описывают **только значение**, не роль:

```text
type-size-14        = 14px / 14pt / 14sp
type-lh-24          = 24px / 24pt / 24dp
type-weight-500     = medium
type-tracking-0     = 0px
type-family-sans-1  = системное UI-семейство (пример)
```

Semantic-уровень (`heading-m`, `body-s`, `label-m`) собирается из Core-токенов
и определяет роль, а не числовое значение.

**Аксиома Core-уровня:**

- имя Core-токена отражает только числовое или классификационное значение;
- роль/назначение текста на Core-уровне не описывается.

---

## 3. Core-шкала размеров (type-size-*)

### 3.1. Принцип дискретных ступеней

Размеры шрифта задаются как дискретная шкала `type-size-*`:

```text
type-size-10
type-size-12
type-size-14
type-size-16
type-size-20
type-size-24
type-size-28
type-size-32
type-size-36
...
```

Принципы:

- ступени образуют **понятную лестницу иерархии** (видимая разница между соседями);
- количество ступеней ограничено реальными нуждами UI (нет десятков почти одинаковых значений);
- мелкие размеры могут иметь более плотный шаг, крупные — более редкий.

### 3.2. Именование размеров

Правила именования:

- `type-size-[N]`, где `[N]` — числовой индекс, отражающий относительный размер;
- `[N]` выбирается так, чтобы масштаб не зависел от платформенных единиц:

```text
type-size-10  →  10px / 10pt / 10sp
type-size-12  →  12px / 12pt / 12sp
type-size-14  →  14px / 14pt / 14sp
...
```

**Блокер:** имена вроде `type-size-body`, `type-size-caption`, `type-size-large-title` — это семантика, им место на semantic-уровне.

---

## 4. Core-шкала межстрочного интервала (type-lh-*)

### 4.1. Кратность базовому шагу сетки

Line-height задаётся дискретной шкалой `type-lh-*`, кратной базовому шагу
spacing-сетки (например, 4 или 8):

```text
type-lh-16
type-lh-20
type-lh-24
type-lh-28
type-lh-32
type-lh-36
...
```

Принципы:

- `type-lh-[N]` всегда выражается в абсолютных единицах (px/pt/dp/sp);
- значение `[N]` кратно базовому шагу сетки (нет дробных значений типа 21.5);
- соседние ступени обеспечивают ровную вертикальную ритмику для параграфов и UI.

**Блокеры:**

- `line-height: 120%`, `line-height: 1.5`, `line-height: auto`;
- дробные значения (`21.5px`, `19.2pt`, `17.3dp`).

Все такие значения должны быть приведены к ближайшему допустимому `type-lh-*`
и использоваться через semantic-токены.

---

## 5. Насыщенность (type-weight-*)

Насыщенность описывается Core-токенами `type-weight-*`:

```text
type-weight-400   → regular
type-weight-500   → medium
type-weight-600   → semibold
type-weight-700   → bold
...
```

Принципы:

- `[N]` отражает стандартный weight-индекс шрифта;
- допустимая шкала ограничивается реальными весами используемого семейства;
- экстремальные веса (`100`, `200`, `900`) используются только при реальной необходимости.

Именование:

- `type-weight-400`, `type-weight-500`, `type-weight-600`, `type-weight-700`;
- любые alias типа `strong`, `weak` живут только на semantic-уровне.

**`type-weight-700` уже существует на Core-уровне** — отдельный
«core-токен для XS-лейбла» заводить не нужно: Core-токен по определению
role-agnostic (раздел 2, «Аксиома Core-уровня» — роль на этом уровне не
описывается). Присвоение `type-weight-700` конкретной роли (например
усиленному варианту `label-xs`) — задача semantic-уровня, см.
`label-xs-weight-strong` в `semantic-typography-tokens-guide.md`.

---

## 6. Трекинг (type-tracking-*)

Трекинг (`letter-spacing`) задаётся шкалой `type-tracking-*`:

```text
type-tracking--0_5   →  -0.5px
type-tracking--0_2   →  -0.2px
type-tracking-0      →   0px
type-tracking-0_2    →  +0.2px
type-tracking-0_3    →  +0.3px
type-tracking-0_4    →  +0.4px
type-tracking-0_6    →  +0.6px
...
```

**Шаги `0_4` и `0_6` добавлены в v1.1.0** для замены существующих
хардкодов `letter-spacing` в системе (значение в `em` конвертировано в
px под фактический размер текста компонента, где применялось):

- `0.04em` при `font-size: 11px` (`.chip`, meta-xs) → `0.44px` → ближайшая
  ступень `type-tracking-0_4`
- `0.05em` при `font-size: 12px` (`.table-wrap th`, label-xs) → `0.6px` →
  ступень `type-tracking-0_6`

Единый механизм трекинга остаётся в абсолютных единицах — второй,
параллельной шкалы в `em` не вводится (см. блокер ниже).

Принципы:

- Core-токен отражает **размер смещения в абсолютных единицах** (px/pt);
- имя может кодировать знак и дробную часть (`--0_2`, `0_3`), но не роль.

**Блокеры:**

- имена вроде `type-tracking-link`, `type-tracking-caption`;
- использование юнитов `em`/`%` вместо абсолютных внутри Core-токенов.

## 7. Семейства шрифтов (type-family-*)

Core-уровень допускает задание семейств шрифта как технических идентификаторов:

```text
type-family-sans-1   → системное UI-семейство (SF / Segoe / Roboto / Inter)
type-family-sans-2   → брендовое UI-семейство
type-family-mono-1   → моноширинное семейство
type-family-serif-1  → текстовое семейство (для контентных задач)
```

Принципы:

- имена семейства на Core-уровне **нейтральны** (`sans-1`, `mono-1`, `serif-1`);
- семантика (brand vs ui vs numeric) задаётся на semantic-уровне.

**Блокер:** `type-family-brand`, `type-family-ui`, `type-family-numeric` как Core —
это уже семантические имена, им место в semantic-типографике или конфиге продукта.

---

## 8. Платформенные единицы

Core-типографика должна быть пригодна для трёх платформ:

- Web — px;
- iOS — pt;
- Android — sp/dp.

Правило:

- числовой индекс `[N]` в имени токена одинаков, но фактические единицы
  и значения адаптируются к платформам через tooling.

Пример:

```text
type-size-14:
  Web:     14px
  iOS:     14pt
  Android: 14sp

type-lh-24:
  Web:     24px
  iOS:     24pt
  Android: 24dp
```

Semantic-токены (`heading-m`, `body-s`, `label-m`) ссылаются на одни и те же
Core-идентификаторы, а платформа решает, в каких единицах их выразить.

---

## 9. Связь с semantic-типографикой

Core-типографические токены **никогда не используются напрямую в компонентах**.

Компоненты работают только с semantic-типографикой, например:

```text
heading-m →
  type-size-20
  type-lh-28
  type-weight-600
  type-tracking-0

label-m →
  type-size-14
  type-lh-20
  type-weight-600
  type-tracking-0
```

Этот гайд описывает только Core-слой. Как из него собирать semantic-токены,
описывает `semantic-typography-tokens-guide.md`.

---

## 10. Блокеры Core-уровня

| Нарушение                      | Пример                      | Как исправить                     |
|--------------------------------|-----------------------------|-----------------------------------|
| Семантика в имени Core-токена | `type-size-body`            | `type-size-14`                    |
| Процентный или auto LH        | `line-height: 120%`         | `type-lh-24`                      |
| Дробный LH                    | `line-height: 21.5px`       | `type-lh-20` или `type-lh-24`    |
| Прямое использование Core     | `button → type-size-14`     | `button → label-m` (semantic)    |
| Непоследовательная шкала      | случайный набор размеров    | согласовать ступени и индексы    |
| Неконтролируемые веса         | все веса шрифта включены    | ограничить до необходимых        |
