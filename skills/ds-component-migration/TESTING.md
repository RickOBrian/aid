## Сценарий 1 — Table/TableRow, legacy `.table-wrap`

Контекст: в скоупе есть HTML-таблицы на классе `.table-wrap` +
`.table-wrap__row`, каноническая спека `TableRow` утверждена
(`memory/ds-component-spec/log.*.json`, `stage: final`).

- [ ] Discovery нашёл все вхождения `.table-wrap` / `.table-wrap__row` в
      заданном скоупе, сгруппировал на точные/похожие/неоднозначные
- [ ] Вывод Discovery компактный: счётчики + до 3 примеров путей на
      группу, не полный список файлов и не diff
- [ ] Выбраны 1–3 pilot-кандидата с явным обоснованием выбора
- [ ] Mapping построил таблицу props/слотов `TableRow` от полей legacy
      `.table-wrap__row` (используя спеку из памяти, не догадки по коду)
- [ ] `/migrate_component pilot` мигрировал ровно 1–2 файла, не больше
- [ ] Для каждого pilot-файла показаны компактные «Было» / «Стало»,
      список удалённых legacy-классов, список новых props/слотов
- [ ] После pilot задан явный вопрос об одобрении перед Rollout
- [ ] `/migrate_component rollout` (после подтверждения) применил mapping
      к оставшимся файлам, вывод — список путей + одна строка на файл,
      без полных diff'ов
- [ ] `/migrate_component cleanup` дал follow-up: что осталось (если
      осталось), что требует manual review, какие storybook-примеры
      нужно добавить

## Сценарий 3 — неоднозначный mapping, обязательная остановка

Контекст: legacy-маркер встречается в двух непохожих контекстах (один —

- [ ] Discovery отнёс второй контекст в «похожие паттерны» или
      «неоднозначные случаи», не смешал с «точными совпадениями»
- [ ] Mapping задал вопрос **до** каких-либо изменений файлов
- [ ] Вопрос — максимум 1 из до 3, короткий, варианты A/B/C без длинных
      пояснений внутри варианта (совместимо с форматом `AskQuestion`)
- [ ] Skill не выбрал вариант самостоятельно и не начал Pilot до ответа
- [ ] После ответа mapping обновлён (`status: confirmed`), только затем
      разрешён `/migrate_component pilot`

      (Шаг 0.2) → вынесен в «вне скоупа», предложен отдельный запуск

## Ограничения и экономия токенов

- [ ] Ни один запуск, кроме подтверждённого `/migrate_component rollout`,
      не изменил больше 2 файлов за раз
- [ ] Повторный `/migrate_component status` или `/migrate_component
      [ComponentName]` с тем же скоупом/маркерами не вызвал повторный
      full-repo скан — переиспользованы данные `discovery.groups` из
      памяти по `scope_signature`
- [ ] Discovery/Rollout вывод не содержит полных diff'ов файлов — только
      summary и списки путей
- [ ] Pilot вывод содержит только сокращённые фрагменты «Было/Стало», не
      содержимое всего файла

## Git и память

- [ ] Запись в `memory/ds-component-migration/log.<имя>.json` создаётся
      при Discovery и обновляется после каждой фазы (`phase` меняется)
- [ ] `git push` не выполнен без явного подтверждения — предложены
      команды вместо автозапуска
- [ ] Перед push использован `git pull --rebase`, не `--merge`
- [ ] Коммит памяти и коммит изменённого кода pilot/rollout — раздельные
      коммиты, не смешаны в один

## Формат вывода

- [ ] Discovery/Mapping/Pilot/Rollout/Cleanup каждый выводится строго по
      своему шаблону из SKILL.md, пустые секции содержат «нет», а не
      пропущены
- [ ] Ни на одном этапе audit/spec-логика (вердикт Match/New/Ambiguous,
      генерация полной спеки) не подмешана в вывод миграции
