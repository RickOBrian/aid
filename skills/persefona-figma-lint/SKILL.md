## 1. Как запускать

1. Загрузить скилл `figma-use`. Код вызова `use_figma` = [`figma-prelude/prelude.js`](../figma-prelude/prelude.js)
   целиком, затем [`lint.js`](lint.js) целиком; в `lint.js` заменить
   только `CONFIG`. Вместе — около 38 КБ из 50 000 знаков лимита.
2. **Файл:** `MODE: 'file'`, `PRODUCT`, `KIND`. Проверяет список страниц и
   содержание `Cover`; в выводе `pages` (имя · зона) и `next` — id страниц
   для второго шага.
3. **Страницы:** `MODE: 'page'`, `PAGE_ID` из `next` — по одному вызову на
   страницу, все вызовы одним сообщением (figma-use: одна смена страницы
   на вызов).
4. Отчёт пользователю — таблица «страница · нарушение · как исправить»
   из `findings` (`page`, `msg`, `fix`), сначала `error`. Ссылка на узел —
   `node`. При `counts` больше `CAP` — сказать, сколько скрыто.

| Поле `CONFIG` | Значение |
|---|---|
| `PRODUCT` | `rider`, `driver`, `persefona` |
| `KIND` | `components`, `tokens`, `icons`, `mockups` (файл макетов: проверяются страницы PRD) |
| `LIBRARY_FOLDER` | `true` для файлов папки `638447836`: латиница в именах (§1) |
| `MAPPING_MERGED` | `true` после мержа #365: страница `Mapping`, до — `Маппинг` |
| `LINE_SCENE` | `true` после мержа #524: рамка клона на холсте |
| `RAW_OK` | имена узлов (regex), у которых сырой цвет принят записью |

Страницы аудита и сборки проверяет ещё и `ds-component-check`
(`references/figma-check.js`: варианты, привязки, описания, блоки
протокола). Здесь — только оформление: секции, фон, цвета, шапка. Один
и тот же факт два скрипта не проверяют.

## 2. Коды

Уровни: `error` — нарушение правила; `warn` — похоже на нарушение,
решает человек; `info` — проверить глазами.

| Код | Режим | Что ловит | Норма |
|---|---|---|---|
| L1 | file | Значок не из §5 (одна находка на значок со списком страниц); старое служебное имя (`Обложка`, `Архив`, `_archive`…); вид не из словаря (`аудит`, `сборка`, `build`); кириллица, `:` `/` скобки, версия в имени объекта; лишний значок; объект совпадает со служебным; `Mapping`/`Маппинг` против состояния #365 | §4.1–4.3 |
| L2 | file | Значок не по виду: аудит не 👀, сборка не 🚧/✅, readyfordev не ✅, update/proposals не 🚧; ✅ вне компонентов; 🚧/👀 без вида | §5 |
| L3 | file | Зоны: смешанная группа, порядок 0–5, пустая группа между `---`; `Cover` первой после зоны 0; `Thumbnail` последней и `---` перед ней; две `Cover`; зона 0 вне компонентов | §3 |
| L4 | file | Порядок: зона 0 по алфавиту и на самом верху; зона 2 — по алфавиту (компоненты, иконки) или списком §6.4 (токены); зона 3 — сборки, аудиты, update, proposals, Drafts, внутри по алфавиту компонента | §3, §6.4, §6.4.1 |
| L5 | file | Страница `· audit` у компонента, у которого есть сборка или readyfordev | §7.1 |
| L6 | file | После PRD-страниц есть другие; PRD-страница в файле библиотеки | §6.7, §6.8 |
| L7 | file | Миниатюра файла не на `Thumbnail` | §4.3 |
| L8 | file | Persefona Components: свои переменные или стили | §10.4 |
| L9 | file | Содержание `Cover`: страницы зон 0, 2, 3 без ссылки, ссылки вне этих зон, порядок не как в файле, ссылка на удалённый узел | §6.1 |
| L10 | page | Узел вне секции; секции пересекаются; зазор меньше 80. Больший зазор не ловится: разнесение бывает намеренным, чейнжлог не на месте ловит L20 | §6.3 |
| L11 | page | Дочерний узел выходит за рамку секции (по `absoluteRenderBounds`); пересечение вложенных секций | §6.3 |
| L12 | page | Фон секции: нет заливки, голый цвет, не `bg-surface-main` у документа или не `bg-surface-muted` у холста экранов | §6.3 |
| L13 | page | Холст: у клона нет прямоугольника `line-scene` 1 px позади, на 1 px шире (только при `LINE_SCENE`) | §6.3 |
| L14 | page | Голый цвет в заливке или обводке вне экземпляров и клонов | §6.6, §9 |
| L15 | page | Текст без стиля типографики или со смешанными стилями | §6.6 |
| L16 | page | Светлый текст (яркость > 0,85) на светлом ближайшем фоне | §6.3 (Ф2а) |
| L17 | page | Экземпляр без главного компонента, в клонах тоже | §9, §10.4 |
| L18 | page | Гиперссылка на удалённый узел; ссылка текстом «см. страницу…» | §6.2, §6.3 |
| L19 | page | Нет `HeaderPage` на странице зон 0, 2, 3; метка статуса в шапке не совпадает со значком; у компонента после сборки есть метка статуса | §6.2, §5 |
| L20 | page | Секции `Changelog · <Артефакт>` нет в зоне 2, у сборки и readyfordev; есть там, где таблиц нет; стоит не справа от артефакта верх к верху с отступом 80 | §6.5 |
| L21 | page | Секция `· audit` на странице сборки или readyfordev (`warn`: по прежнему правилу — в `Archive` при ближайшей работе); секция аудита в `Archive` без даты | §7.1, §7.3 |

**Клон на холсте** — прямой потомок секции на странице-холсте (PRD
audit, PRD idea, Flow, Where, Tech audit, Tech idea), который не
экземпляр, не текст, не прямоугольник и не секция. Внутри клонов
проверяются только экземпляры без мастера (L17): клон повторяет макет как
есть (§6.7).

**Что скрипт не проверяет** — руками на приёмке: грамматика имён
компонентов и свойств (`naming-conventions`, это `ds-component-check`
D3), `figmaTable` в JSON и колонки таблицы (`changelog-guide`), блоки и
номера пунктов PRD audit (§6.7), анимация в гайде (§6.9), заголовок и
бейдж версии шапки по #552, подписи пунктов содержания обложки.

Известные ложные срабатывания: `L16` при полупрозрачной или градиентной
подложке (берётся ближайший сплошной фон); `L14` у слоёв-контракта
плагина в таблице чейнжлога — их цвет задаёт Token Comparator: добавить в
`RAW_OK` и записать в отчёт.

## 3. Правила

- **Только чтение.** Скрипт не меняет файл. Исправляет исполнитель по
  колонке «как исправить»; Cover обновляется руками (§6.1).
- **Правится только через PR** в `skills/persefona-figma-lint/` с новой
  версией в первой строке `lint.js` и записью в changelog; приёмка —
  Standards · Persefona. Правило изменилось — код меняется в том же PR,
  что и правило, или следующим.
- **Новое правило в §9** — новый код здесь или строка в «Что скрипт не
  проверяет».
