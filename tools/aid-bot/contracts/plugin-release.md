# Контракт: плагин Token Comparator в боте

> Статус: Draft · v0.1.0 · 2026-10-02
> Сторона AID — Principal Designer, сторона бота — автор бота.
> Меняется только через PR в `RickOBrian/aid`; автор бота — ревьюер.

Пилот из `PLAN.md`: бот всегда отдаёт актуальную версию Token Comparator и
сам объявляет о новом релизе. После релиза плагина руками в боте ничего не
делается.

---

## 1. Источник

Один источник релизов — GitHub Releases публичного репозитория
`RickOBrian/aid`. Отдельного манифеста версии нет и не заводится (Q-07).

| Что | Откуда |
|---|---|
| Последний релиз | `GET https://api.github.com/repos/RickOBrian/aid/releases/latest` |
| Версия | поле `tag_name`, формат `vX.Y.Z` |
| Дата | поле `published_at` (ISO 8601, UTC) |
| Заметки | поле `body` (Markdown) |
| Страница релиза | поле `html_url` |
| Файл | из того же ответа: `assets[]` с `name == "token-comparator.zip"` → `browser_download_url` |
| Постоянная ссылка | `https://github.com/RickOBrian/aid/releases/latest/download/token-comparator.zip` — только как текстовый запасной вариант для человека |

Файл берётся из `assets` того же ответа, а не по постоянной ссылке: так
версия и файл гарантированно от одного релиза, даже если Latest сменится
между двумя запросами.

Авторизация не нужна: репозиторий публичный. Лимит GitHub для запросов без
токена — 60 в час на IP; бот делает 2. Заголовок `User-Agent` обязателен
(требование GitHub), например `aid-ds-bot`.

### Что гарантирует сторона AID

Это правило стыка, владелец — Token Comparator (корневой `CLAUDE.md`):

- каждый релиз Token Comparator кладёт в GitHub Release файл
  `token-comparator.zip` и получает метку Latest;
- тег — `vX.Y.Z` по semver;
- релизы других продуктов (AID Style Migration) выходят **без** Latest.

Изменение любого пункта — сначала PR в этот контракт.

## 2. Цикл проверки

Фоновый цикл asyncio в процессе бота, по образцу `reminder_loop`.

1. Раз в `PLUGIN_CHECK_MINUTES` минут — запрос из раздела 1. Первый запрос —
   через минуту после старта бота.
2. Ответ не 200, нет `tag_name` или нет нужного файла в `assets` — сбой
   (раздел 5). Остальное не трогается.
3. `tag_name` совпадает с сохранённым — ничего не делать.
4. `tag_name` новый:
   1. скачать файл по `browser_download_url`;
   2. проверить: размер больше 0 и совпадает с `assets[].size`, первые
      байты — `PK` (ZIP);
   3. сохранить как `plugin/token-comparator-<tag_name>.zip`;
   4. записать состояние (раздел 4) — только после успешного сохранения;
   5. удалить файлы старше предыдущей версии: на диске остаются текущая и
      одна предыдущая;
   6. анонс (раздел 3), если новая версия **больше** сохранённой по
      semver. Если меньше (Latest откатили) — файл обновить, анонс не
      делать, записать в лог `WARNING`.
5. Первый запуск, состояния нет — скачать и сохранить, **без анонса**:
   иначе бот объявит релиз, который давно вышел.

Скачивание и проверка — до записи состояния: если файл не скачался, на
следующем цикле бот попробует снова.

## 3. Что видит пользователь

### `/plugin` и кнопка «📎 Скачать плагин»

Поведение `deliver_plugin` меняется так:

| Ситуация | Ответ |
|---|---|
| Есть текущий файл | Файл. Подпись: `Token Comparator <tag_name> · <дата релиза ДД.ММ.ГГГГ>` и прежняя инструкция по установке |
| Текущего нет, есть предыдущий | Предыдущий файл с его версией в подписи |
| Файлов нет | Текст: постоянная ссылка из раздела 1 |

Файл из корня проекта (`token-comparator.zip` v0.1.0) и папка
`figma-token-comparator/` с копией исходников удаляются. Исходники живут в
`RickOBrian/aid`, `tools/figma-token-comparator/`.

### Анонс нового релиза

Куда:

- пост в канал `TARGET_CHAT_ID`;
- ЛС каждому из `RELEASE_NOTIFY_IDS`.

Уходит сразу, тихие часы не действуют — это событие, а не напоминание.

Текст (HTML, как остальные сообщения бота):

```
🧩 Token Comparator <tag_name>
Релиз от <ДД.ММ.ГГГГ>

<заметки>

Скачать: /plugin в боте
Что нового целиком: <html_url>
```

- `<заметки>` — `body` релиза: экранировать под HTML, заголовки `### X` →
  `<b>X</b>`, списки `- ` → `• `. Длиннее 1500 символов — обрезать по
  границе строки и добавить `…`.
- В канале — без inline-кнопок: в канале бота они прячут комментарии.
- В ЛС — та же кнопка «📎 Скачать плагин», что в меню (`file:plugin`).
- Если получатель не нажимал `/start` и ЛС не доставилась — запись в лог
  `WARNING`, без повторов.

## 4. Состояние

В `bot_state.json`, рядом с существующими полями:

| Поле | Значение |
|---|---|
| `plugin_tag` | `tag_name` текущего сохранённого файла |
| `plugin_published_at` | `published_at` этого релиза |
| `plugin_prev_tag` | версия предыдущего файла, если он есть |
| `plugin_checked_at` | unix-время последней успешной проверки |
| `plugin_fail_count` | сбоев подряд |
| `plugin_fail_alert_at` | unix-время последнего алерта о сбоях |

Папка `plugin/` — данные сервера, в git не попадает (`.gitignore` бота).

---

## 5. Сбои

| Что | Реакция |
|---|---|
| Сеть, 5xx, таймаут (30 с) | `WARNING` в лог, `plugin_fail_count + 1`, ждать следующий цикл |
| 403 или 429 от GitHub (лимит) | то же; при наличии заголовка `x-ratelimit-reset` следующий запрос не раньше этого времени |
| В релизе нет `token-comparator.zip` | `ERROR` в лог — нарушено правило стыка (раздел 1); алерт `ADMIN_ID` один раз на этот `tag_name` |
| Файл не прошёл проверку | `ERROR` в лог, состояние не меняется, повтор на следующем цикле |
| 12 сбоев подряд (6 часов при 30 мин) | одна ЛС `ADMIN_ID`: «Не могу проверить релизы плагина: <последняя ошибка>», не чаще раза в сутки |
| Успешная проверка | `plugin_fail_count = 0` |

Сбой проверки никогда не мешает `/plugin`: пользователь получает последний
сохранённый файл.

## 6. Переменные окружения

Новые. Описать в `.env.example` без значений и в `BOT-OVERVIEW.md`.

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `PLUGIN_RELEASE_REPO` | репозиторий релизов | `RickOBrian/aid` |
| `PLUGIN_ASSET_NAME` | имя файла в релизе | `token-comparator.zip` |
| `PLUGIN_CHECK_MINUTES` | период проверки, мин | `30` |
| `RELEASE_NOTIFY_IDS` | кому ЛС об анонсе, через запятую | пусто — только канал |
| `PLUGIN_ANNOUNCE_CHANNEL` | `0` — не постить анонс в канал (для проверки) | `1` |

Секретов среди них нет. Токен GitHub не нужен.

---

## 7. Чего бот не делает

- Не публикует релизы, не меняет метку Latest, не пишет в `RickOBrian/aid`.
- Не раздаёт AID Style Migration — пока плагин не готов. Когда будет готов:
  у его релизов нет Latest, поэтому вместо `/releases/latest` нужен список
  релизов с фильтром по префиксу тега. Это следующая версия контракта.
- Не хранит плагин в git.

---

## 8. Как проверить

Тестового бота нет, поэтому проверка на боевом — с выключенным каналом.

1. Деплой с `PLUGIN_ANNOUNCE_CHANNEL=0`, в `RELEASE_NOTIFY_IDS` — только
   автор бота.
2. Первый запуск: в `bot_state.json` появился `plugin_tag` = текущий Latest,
   в `plugin/` — файл, анонса нет.
3. `/plugin` отдаёт файл с версией текущего Latest в подписи.
4. Остановить бота, в `bot_state.json` поставить `plugin_tag` на
   предыдущую версию, запустить: в течение минуты — ЛС автору с анонсом,
   форматирование заметок читается.
5. Вернуть `PLUGIN_ANNOUNCE_CHANNEL=1` и боевой `RELEASE_NOTIFY_IDS`.

## 9. Готово, когда

- Шаги раздела 8 пройдены, `/plugin` отдаёт текущий Latest, а не v0.1.0.
- После следующего настоящего релиза Token Comparator в течение
  `PLUGIN_CHECK_MINUTES` анонс появился в канале и в ЛС, `/plugin` отдаёт
  новую версию, руками ничего не делалось.
- Стык «бот читает Latest Token Comparator» записан в корневой `CLAUDE.md`,
  а проверка бота — в релизный чек-лист Token Comparator.
