# AID Bot — план

Живой план интеграции бота с продуктами AID. Вопросы, которые блокируют
шаги, — в `OPEN-QUESTIONS.md`.

---

## Роли

Бота развивают параллельно двое, у каждого свой аккаунт Claude. Память
чатов у них не общая, поэтому всё, что должен знать второй, записывается в
репозиторий.

| Кто | Отвечает за | Где работает |
|---|---|---|
| Инженер (автор бота) | Техническая часть: код, хостинг, деплой, хранилище, секреты | Репозиторий бота |
| Principal Designer | Оркестрация: сценарии бота с Figma, плагинами, Presentbook; контракт данных | `tools/aid-bot/` этого репозитория |

Граница между ними — контракт сценария: что бот принимает, что вызывает,
какие данные отдаёт. Его описывает оркестрация, реализует инженер; меняют
только вдвоём. Один репозиторий или два — открыто (Q-02), граница от этого
не зависит.

---

## Принципы

- Плагины Figma (Token Comparator, AID Style Migration) работают только
  внутри клиента Figma, извне их не вызвать. Бот работает с тем, что вокруг
  них: сервер `aid-registry-api`, GitHub (PR `registry/propose-*`,
  релизы), REST API и вебхуки Figma, страницы Presentbook.
- Бот не принимает решений, которые принадлежат людям: не мержит и не
  закрывает `propose-*` (ADR-035), не публикует релизы и не трогает метку
  Latest.
- Стык с продуктом заносится в корневой `CLAUDE.md`, когда появляется на
  деле, — через Principal Designer.

### Что известно о боте (кратко)

Из описания автора на 2026-10-02:

- Python, aiogram, long polling, один процесс на VPS. HTTP-сервера нет —
  вебхуки извне принять не может. Фоновые задачи — циклы asyncio внутри
  процесса: на них можно опрашивать внешние API.
- Заявки дизайнеров: RIDER/DRIVER → вопрос, баг, правка, новый компонент →
  согласование → исполнитель DS. Хранилище — JSON-файлы, внешнего трекера нет.
- Поля заявки (тип, компонент, ссылка на Figma) отдельно не хранятся —
  только внутри HTML поста. Любая структурная интеграция упирается в это
  (Q-09).
- Бот раздаёт плагин Token Comparator ZIP-файлом с диска, версия 0.1.0.
  Latest в GitHub Releases — v1.6.0.
- В работе у автора: «слияние» с Token Comparator и Presentbook, архив и
  поиск задач. Раздачу плагина, `/start` с параметром и `requests.json`
  менять только по согласованию с ним.

### Кандидаты в сценарии

| Сценарий | Направление | Что трогает | Что нужно в боте |
|---|---|---|---|
| Раздача плагина по постоянной ссылке Latest, версия из GitHub API | бот → GitHub | чтение Releases, существующий стык | заменить файл с диска на скачивание |
| Релиз плагина → анонс со ссылкой | GitHub → бот | чтение Releases | цикл опроса |
| Новый PR `registry/propose-*` → уведомление | GitHub → бот | чтение PR | цикл опроса |
| Кнопка в плагине «Создать запрос в DS» с подстановкой ссылки на Figma | плагин → бот | код Token Comparator | deep link `/start <payload>` |
| Запрос со ссылкой на Figma → превью фрейма | бот → Figma | Figma REST API | токен Figma, структурные поля |
| «Что за токен X» → ссылка на Presentbook | бот → Presentbook | чтение Presentbook | новая команда |

Предварительный пилот — раздача плагина по ссылке Latest: это уже часть
«слияния», бот сейчас отдаёт устаревшую версию, вебхук не нужен, правок в
продуктах AID нет. Следом — уведомления через опрос GitHub: репозиторий
публичный, токен для чтения не нужен.
