# Токен Figma для бота

Что заводим, кто, где хранится и как живёт. Значение токена нигде в
документах, коде, логах и чатах не появляется — только имя переменной.

Тариф AID — Enterprise: доступны переменные через REST API
(`file_variables:*`).

---

## 1. Чей токен

Personal access token (PAT) действует от имени пользователя, который его
создал, и видит **все** файлы этого пользователя — ограничить набор файлов
нельзя (Figma Help, «Manage personal access tokens»). Скоупы ограничивают
только тип действий.

Поэтому токен создаётся не от личного аккаунта дизайнера или инженера, а
от **служебного аккаунта** в организации AID:

- отдельный email команды, не личный;
- доступ «can view» только к файлам, с которыми работает бот
  (библиотеки AID, файлы токенов);
- без прав редактирования, пока сценарий их не потребует.

Решение за Principal Designer: заводить ли служебное место в Enterprise
(это место в тарифе) или временно — PAT от аккаунта Principal Designer с
ротацией на служебный, когда он появится. Личный токен видит все личные
файлы владельца — это компромисс, его фиксируем явно.

---

## 2. Скоупы

Сценария с Figma ещё нет (пилот — раздача плагина и анонс релиза).
Поэтому на старте — только чтение:

| Скоуп | Зачем |
|---|---|
| `file_content:read` | узлы файла: превью фрейма по ссылке из заявки, имена компонентов |
| `file_metadata:read` | имя файла, последнее изменение |
| `file_variables:read` | переменные (токены) — сверка с реестром AID. Только Enterprise |
| `library_content:read` | опубликованные компоненты и стили библиотеки |

Не выдаём, пока нет сценария:

- `file_variables:write` — правка переменных. Автопатч токенов — решение
  уровня релиза токенов, через `token-change-gate`, не фоновое действие бота;
- `webhooks:*` — у бота нет HTTP-адреса, вебхукам некуда приходить;
- `file_comments:write`, `file_dev_resources:write` — запись в файлы.

Новый скоуп = новый токен: перевыпуск, а не правка.

---

## 3. Как создать

Делает владелец служебного аккаунта:

1. Figma → Settings → Security → Personal access tokens → Generate new token.
2. Имя: `aid-bot-<год>-<месяц>`, например `aid-bot-2026-10` — видно, когда
   выпущен.
3. Срок — выбрать при создании; дату окончания записать в раздел 6.
4. Отметить скоупы из раздела 2.
5. Скопировать токен — Figma покажет его один раз.

---

## 4. Куда положить

Только на сервер бота, в его `.env` (права 600, в git не попадает):

```
FIGMA_TOKEN=
```

- Передать автору бота значение — не через Telegram-канал, не через
  репозиторий и не через чат Claude. Менеджер паролей с общим доступом
  или лично.
- Описать переменную в `.env.example` бота без значения и в разделе
  «Переменные окружения» описания бота.
- Бот передаёт токен заголовком `X-Figma-Token`; в логах — ни токена, ни
  заголовков запроса.

---

## 5. Ротация и отзыв

- Перевыпуск — до окончания срока: новый токен → `.env` → перезапуск бота →
  отзыв старого (Settings → Security → Revoke access).
- Немедленный отзыв: токен попал в лог, чат, коммит или скриншот; ушёл
  человек, от чьего аккаунта выпущен токен.
- Бот при ответе Figma `403` пишет лиду в ЛС «токен Figma недействителен»,
  а не молча пропускает.
