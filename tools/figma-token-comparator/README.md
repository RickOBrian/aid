# Token Comparator (MVP)

Figma-плагин, который **детерминированно** сравнивает цвета текущего макета
(файл A) с эталонной библиотекой Figma Variables из другого файла (файл B,
Enterprise team library) и строит интерактивную таблицу маппинга
«Было → Стало → Новое» прямо в UI плагина.

**Никаких LLM/AI API не используется.** Всё сравнение — точные и
перцептивные (Delta E) алгоритмы над hex/alpha значениями.

Категория **Colors** реализована полностью. Архитектура (`ITokenComparator`)
подготовлена для последующего добавления Typography, Spacing, Radii,
Effects, Gradients — каждая категория — отдельный модуль в
`src/comparators/`.

---

## 1. Установка зависимостей и сборка

```bash
cd tools/figma-token-comparator
npm install
npm run build
```

Команда `npm run build` собирает TypeScript в JS через esbuild:

- `src/code.ts` → `dist/code.js` (главный поток плагина, Plugin API)
- `src/ui.ts` + `src/ui.html` → `dist/ui.html` (UI, единый самодостаточный
  HTML-файл — Figma не позволяет `<script src="...">` во внешние файлы, поэтому
  собранный JS инлайнится прямо в HTML на шаге сборки)

Для разработки с автопересборкой при изменении файлов:

```bash
npm run watch
```

Проверка типов (strict-режим) без сборки:

```bash
npm run typecheck
```

## 2. Импорт плагина в Figma

1. Откройте Figma Desktop-приложение (импорт по manifest недоступен в браузере
   без десктоп-клиента).
2. Меню **Plugins → Development → Import plugin from manifest…**
3. Выберите файл `tools/figma-token-comparator/manifest.json` из этого репозитория.
4. Плагин появится в **Plugins → Development → Token Comparator**.
5. После любого изменения кода — `npm run build` (или держите `npm run watch`
   запущенным) и перезапустите плагин в Figma (Cmd/Ctrl+Alt+P или через меню).

## 3. Получение Personal Access Token

Плагину нужен **Personal Access Token (PAT)** пользователя, у которого есть
доступ к библиотечному файлу — токен используется для чтения переменных через
Figma REST API (`GET /v1/files/:file_key/variables/local`).

1. В Figma откройте **Settings** (иконка профиля → Settings).
2. Вкладка **Security**.
3. Раздел **Personal access tokens** → **Generate new token**.
4. Дайте токену понятное имя (например, `token-comparator`), выберите срок
   действия.
5. Убедитесь, что у токена есть доступ на чтение переменных файлов
   (`file_variables:read` / соответствующий scope в вашей организации —
   для Enterprise-библиотек может требоваться доступ уровня организации).
6. Скопируйте токен **сразу** — повторно посмотреть его нельзя.
7. Вставьте токен в поле **Personal Access Token** на вкладке «Настройки»
   плагина и нажмите **Сохранить настройки**.

Токен хранится только локально, в `figma.clientStorage` (изолированное
хранилище плагина в рамках вашей машины/аккаунта), и никогда не уходит
куда-либо, кроме прямого запроса к `api.figma.com`.

### Где взять file_key библиотеки

`file_key` — это сегмент URL библиотечного файла:

```
https://www.figma.com/design/AbCdEfGhIjKlMnOpQrStUv/My-Library-Name
                              ^^^^^^^^^^^^^^^^^^^^^^ это file_key
```

Вставьте его в поле **File key библиотеки** и нажмите **Загрузить
библиотеку**.

## 4. Как пользоваться плагином

1. **Вкладка «Настройки»** — вставьте PAT и file_key библиотеки, сохраните,
   нажмите «Загрузить библиотеку». Внизу появится статус: сколько цветовых
   переменных загружено и когда. Кнопка «Загрузить библиотеку» — она же
   «Обновить библиотеку» (повторный клик перезапрашивает REST API и обновляет
   кэш).
2. **Вкладка «Сканирование»** — выберите скоуп (весь файл / текущая страница /
   выделение) и нажмите «Сканировать цвета». Плагин обходит ноды, собирает
   fills/strokes/text fills, группирует одинаковые значения и сравнивает с
   библиотекой.
3. **Вкладка «Результаты»** — таблица со статусами (`Mapped`, `Exact match`,
   `Value match`, `Name match`, `Conflict`, `Name match (value unknown)`,
   `Approximate match`, `Layout only` / `Hardcoded (no analog)`). Колонки
   «Сейчас» и «Предлагаем» показывают значения **по обоим режимам сразу**
   (Day, затем Night) — так сразу видно, совпадение/расхождение только в
   Day, только в Night или в обоих режимах. Для hardcoded/style/ghost
   значение одно и то же в обоих режимах (оно не зависит от переменной).
   Клик по имени слоя — выделяет и приближает ноды в макете. Для каждой
   строки доступно действие:
   - **Использовать существующую переменную** — автокомплит по библиотеке;
   - **Игнорировать** — обязателен комментарий;
   - **Оставить как есть (hardcoded)** — намеренное исключение;
   - **Отметить как новый токен-кандидат** — только маркировка, плагин **не**
     создаёт переменные в библиотеке автоматически.

   Кнопка «Применить решение» сохраняет выбор в `clientStorage` (переживает
   повторные сканирования и перезапуск Figma) и помечает строку зелёной
   галочкой.
4. Кнопки **Экспортировать CSV / JSON** — выгружают текущую таблицу маппинга
   (см. формат ниже) через `Blob` + временную ссылку `<a download>` внутри
   UI-iframe плагина.

## 5. Формат экспорта

Колонки (одинаковые для CSV и JSON):

```
Layer | Node Path | Сейчас | Сейчас Day | Сейчас Night | Binding |
Предлагаем | Предлагаем Day | Предлагаем Night | Решение | Комментарий |
Дата решения
```

JSON — массив объектов:

```json
[
  {
    "layer": "Rectangle 12",
    "nodePath": "Page 1 / Frame / Rectangle 12",
    "before": "bg-accent-main",
    "beforeDay": "#2D6CDF @ 80%",
    "beforeNight": "#5C8AF2 @ 80%",
    "binding": "Variable",
    "target": "bg-accent-main (Colors/Semantic)",
    "targetDay": "#2D6CDF @ 80%",
    "targetNight": "#5C8AF2 @ 80%",
    "decision": "Mapped",
    "comment": "",
    "timestamp": "2026-09-01T14:32:00.000Z"
  }
]
```

## 6. Архитектура

```
src/
  code.ts                    — главный поток: Plugin API, REST API, storage, оркестрация
  ui.html / ui.ts            — UI плагина (без фреймворков)
  messages.ts                — типизированный протокол code.ts <-> ui.ts
  comparators/
    types.ts                 — общий контракт ITokenComparator + типы (для ВСЕХ категорий)
    colorComparator.ts        — comparator категории Colors (реализован)
  lib/
    scanner.ts                — обход нод макета, сбор и группировка цветовых свойств
    figmaRestApi.ts            — обёртка над GET /v1/files/:file_key/variables/local
    colorUtils.ts               — hex/rgb конверсия, форматирование, Delta E (Lab/CIE76)
    storage.ts                  — обёртка над figma.clientStorage
    exporter.ts                  — сборка строк экспорта + CSV/JSON сериализация
```

### Почему `figma.clientStorage`, а не `figma.root.setPluginData`

`setPluginData` привязан к конкретному документу и ограничен 100kb **на
файл**. PAT-токен, кэш библиотеки (может быть сотни/тысячи переменных) и
история решений должны:

- переживать открытие разных файлов макетов одним и тем же пользователем;
- не быть ограничены по размеру документа.

`clientStorage` даёт до ~5MB на плагин, привязан к плагину+машине/аккаунту, а
не к документу — то, что нужно здесь.

### Как добавить новую категорию (Typography, Spacing, Radii, Effects, Gradients)

1. Создать `src/comparators/<category>Comparator.ts`, реализующий
   `ITokenComparator` из `types.ts` (тот же контракт: `scanLayout` →
   `compareWithLibrary` → `ComparisonResult[]`).
2. Определить форму `comparisonValue` для этой категории (для Colors — это
   `{ hex, alpha }`; для Typography это может быть, например,
   `{ fontFamily, fontWeight, fontSize, lineHeight }`).
3. Добавить сбор соответствующих свойств в отдельный модуль
   `src/lib/<category>Scanner.ts` (по аналогии с `scanner.ts`).
4. Расширить `figmaRestApi.ts` фильтром по нужному `resolvedType`
   (`FLOAT`, `STRING`, `BOOLEAN` — для Spacing/Radii/Typography; Effects и
   Gradients не являются типами Figma Variables и потребуют отдельного
   источника правды, например paint styles / effect styles через REST
   `GET /v1/files/:file_key/styles`).
5. Подключить новый comparator в `code.ts` рядом с `colorComparator`,
   добавить вкладку/фильтр категории в UI.

Такое разделение позволяет добавлять категории без изменения существующей
логики Colors.

## 7. Известные ограничения MVP

- Обрабатываются только **сплошные (`SOLID`) заливки/обводки**. Градиенты и
  изображения в заливках сознательно пропускаются — это отдельная будущая
  категория (Gradients).
- Текстовые ноды с **разным цветом по символам** (`fills === figma.mixed`)
  пропускаются — плагин не разбирает посимвольные диапазоны в этой версии.
- Alpha берётся из `paint.opacity` конкретного paint-слоя, без учёта
  композиции с общей `node.opacity` слоя — для MVP это осознанное упрощение.
- «Ноды внутри masks» интерпретируются как: сама нода с `isMask === true`
  пропускается целиком (её цвет — техническая маска, не дизайн-решение).
  Полный алгоритм распространения маскирования на последующие sibling-ноды
  не реализован в MVP.
- Boolean-операции (`BOOLEAN_OPERATION`) учитываются как единый узел; их
  внутренние vector-компоненты не сканируются отдельно.
- REST API отдаёт **локальные** переменные файла библиотеки
  (`/variables/local`). Если библиотека сама ссылается на переменные из
  ещё одной библиотеки (алиасы за пределами файла), значение такой
  переменной не резолвится — но токен **не отбрасывается**: он остаётся
  доступным для поиска по имени, и строка макета с тем же именем переменной
  получает статус `Name match (value unknown)` вместо ложного
  `Layout only`. В колонке «Предлагаем» показывается пояснение «значение не
  получено (внешняя ссылка)» вместо hex — пользователь решает вручную
  (оставить как есть / замаппить на другую переменную / отметить кандидатом).
- Rate limit (`429`) от Figma REST API не реализует автоматический retry —
  пользователю показывается сообщение с просьбой повторить позже.
- Day/Night значения **макета** (колонка «Сейчас») резолвятся через Plugin
  API по всем режимам коллекции bound-переменной — в отличие от REST API
  здесь нет ограничения "внешний алиас не резолвится", так как переменная
  принадлежит текущему файлу. Если коллекция переменной содержит только
  один режим (нет отдельного Day/Night), вторая строка не показывается.
  Для hardcoded/style/ghost значение одно и то же в Day и Night (оно не
  привязано к переменной, режим не влияет на результат).
