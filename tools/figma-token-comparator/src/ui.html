Кнопка Применить решение на вкладке «Результаты» фиксирует ваш выбор по выбранной строке таблицы. Сначала кликните строку (подсветится голубым), выберите действие в выпадающем списке «Действие», при необходимости заполните дополнительные поля — затем нажмите кнопку под таблицей.

Плагин сейчас — инструмент аудита и учёта решений, а не автомат миграции. «Применить решение» не меняет макет Figma: цвета не перепривязываются, переменные не создаются, стили не заменяются.

Общее для всех вариантов

  • Решение сохраняется локально в clientStorage плагина и переживает перезапуск Figma.
  • Ключ записи — id группы (свойство + hex + тип привязки + имя источника). При повторном скане та же группа подтянет сохранённое решение автоматически.
  • В строке появляется отметка ✓, обновляется счётчик «обработано: N/M».
  • Решение попадает в экспорт CSV, JSON и MD (колонки «Решение», «Комментарий», «Дата решения»).

Варианты действия

1a. Использовать предложенный

  • Требование: у строки есть предложенный токен (колонка «Предлагаем» не пуста). Доп. полей нет — используется именно этот токен, без выбора вручную.
  • Сохраняется: id/имя/коллекция предложенного токена, метка Mapped (suggested).
  • При перескане: строка исчезает из таблицы (считается обработанной).
  • Не делает: не привязывает fill/stroke к переменной в макете.

1b. Выбрать токен из AID

  • Требование: выберите токен в поле «Начните вводить имя токена/стиля…» из списка библиотеки. Без точного совпадения Apply не сработает.
  • Сохраняется: id и имя выбранного токена библиотеки, метка Mapped (custom).
  • При перескане: строка исчезает из таблицы (считается обработанной).
  • Не делает: не привязывает fill/stroke к переменной в макете.
Использовать предложенный vs Выбрать токен из AID: первый — быстрый путь, когда предложение плагина в колонке «Предлагаем» подходит без изменений. Второй — когда предложенный токен не подходит (или его нет вовсе) и нужен другой токен из библиотеки AID.

2. Игнорировать

  • Требование: обязателен комментарий с обоснованием.
  • Сохраняется: решение Ignored и ваш комментарий.
  • При перескане: строка исчезает из таблицы.
  • Смысл: расхождение осознанное — hex/стиль остаётся как есть, токен не нужен, править не будем.

3. Отметить как новый токен-кандидат

  • Требование: дополнительных полей нет.
  • Сохраняется: решение Candidate.
  • При перескане: строка остаётся в таблице (токена в библиотеке пока нет).
  • Не делает: не создаёт переменную в файле библиотеки.

4. Предложить правку значения в библиотеке

  • Когда доступно: только если найден target-токен (Value match, Name match, Conflict, Approximate match и т.п.) — не для Hardcoded (no analog) без совпадения.
  • Доп. поля: режим библиотеки (из modes target-переменной), предлагаемое значение (hex, предзаполняется из «Сейчас»), комментарий (необязателен).
  • Сохраняется: решение Value fix proposed + все поля правки.
  • При перескане: строка остаётся (правка в библиотеке ещё не сделана).
  • Не делает: не меняет variable в библиотеке и не меняет макет.
Candidate vs Value fix proposed: Candidate — подходящего токена в библиотеке ещё нет. Value fix proposed — токен уже есть, но значение в конкретном режиме нужно поправить вручную дизайнеру библиотеки.

Бейдж в колонке «Статус» показывает, как значение в макете соотносится с загруженной библиотекой. Строки, где всё уже корректно (переменная из этой библиотеки), в таблицу не попадают.

  • Style binding

    Цвет задан через paint style, а не через variable. Плагин не может автоматически заменить стиль на токен — нужно ваше решение.

  • Ghost style

    Слой ссылается на стиль, которого уже нет в файле («ghost» / битая ссылка). Цвет может отображаться, но привязка потеряна.

  • Hardcoded (no analog)

    Сплошной hex без совпадения в библиотеке — ни по имени, ни по значению, ни по близости (Delta E). Кандидат на новый токен или осознанный hardcode.

  • Value match

    Hex и alpha точно совпадают с одним из режимов токена библиотеки (Day или Night), но имя или привязка в макете другие — например hardcoded с тем же цветом, что у переменной.

  • Name match

    Имя переменной или стиля в макете совпадает с токеном библиотеки, но значения различаются умеренно (Delta E ≤ 20). В «Предлагаем» показан библиотечный токен с тем же именем.

  • Name match (value unknown)

    Имя совпало, но значения режимов библиотеки не удалось получить через REST API — часто это алиас на переменную из другого файла. Сравнение по hex недоступно; решение принимается вручную.

  • Conflict

    Имя совпало с токеном библиотеки, но цвет существенно отличается (Delta E > 20). Типичный случай: в макете устаревшее значение или переименованный токен с другим hex.

  • Approximate match

    Точного совпадения нет, но найден ближайший цвет в библиотеке в пределах порога Delta E (при совпадающей alpha). В бейдже показывается ΔE — чем меньше, тем ближе оттенок.

  • Правка предложена (Night)

    Не статус сканирования, а применённое решение Value fix proposed: для target-переменной предложена ручная правка значения в указанном режиме. Показывается вместо исходного бейджа; в tooltip — исходный статус (Conflict, Name match и т.д.).

После «Применить решение» с вариантами Mapped (suggested/custom) или Ignored строка при следующем скане скрывается. Candidate и Value fix proposed остаются с исходным статусом (или бейджем «Правка предложена») до изменений в библиотеке.

Кнопки Экспорт CSV, Экспорт JSON и Экспорт MD на вкладке «Результаты» открывают меню из двух пунктов: Скачать — сохранить файл соответствующего формата на компьютер, Напечатать — построить визуальную таблицу в текущем Figma-файле на странице «Маппинг». Это отчёт для аудита, ревью и передачи решений команде — плагин не отправляет данные никуда и не меняет макет.

Напечатать строит одну и ту же таблицу независимо от кнопки (CSV/JSON/MD влияют только на формат «Скачать»). Страница «Маппинг» создаётся автоматически, если её нет; каждая новая таблица встаёт правее предыдущих — история отчётов не затирается. Лимит печати — 300 строк: если видимых строк больше, печатаются первые 300 и появляется предупреждение, а «Скачать» отдаёт полный набор.

Зачем нужны

  • Зафиксировать результат сканирования: что в макете, что предлагает библиотека, какие решения уже приняты.
  • Передать список расхождений дизайнерам, разработчикам или в трекер задач без доступа к Figma.
  • Сохранить промежуточный или финальный чеклист миграции на токены (до/после правок в библиотеке).
  • Подключить данные к скриптам и автоматизации — через JSON; в таблицы и Google Sheets — через CSV.
  • Показать отчёт прямо в Figma — через «Напечатать», без выгрузки файлов и внешних инструментов.

Типичный флоу

  1. Настройки → загрузить библиотеку.
  2. Сканирование → выбрать скоуп и запустить скан.
  3. Результаты → пройти строки, при необходимости применить решения.
  4. Экспорт → «Скачать» (CSV, JSON или MD) либо «Напечатать» (таблица на странице «Маппинг»).
  5. При следующем скане или после правок макета — повторить и сравнить новый экспорт со старым.

CSV, JSON или MD?

Все три формата содержат одни и те же данные, отличается только представление:

  • CSV (token-comparator-mapping.csv) — таблица с заголовками колонок, UTF-8. Удобно открыть в Excel, Google Sheets, Numbers; делиться с нетехническими ролями.
  • JSON (token-comparator-mapping.json) — массив объектов с теми же полями. Удобно парсить в скриптах, CI, внутренних утилитах DS.
  • MD (token-comparator-mapping.md) — Markdown-таблица с теми же колонками. Удобно вставить в Notion, GitHub, Confluence или PR-описание без ручной вёрстки.
