# Иконки — этап 0: проверка отпечатков формы (2026-09-19)

Проверка метода подбора иконки по форме до кода плагина (план — трекер,
раздел «v1.5.0 — иконки»). Тестовый набор — 443 SVG из Presentbook
(`pages/driver-color-tokens/public/icons`): экспорт того же файла иконок
Driver в Figma, плюс иконки Rider. В плагине иконки будут сравниваться с
библиотекой, которую подключит дизайнер; SVG здесь — только способ проверить
метод на настоящих иконках без Figma и токена.

Модуль — `src/lib/iconShape.ts` (тесты — `test/iconShape.test.ts`):
растеризация геометрии в маску N×N с нормализацией в квадрат, похожесть —
IoU масок. Скрипт прогона одноразовый, в репозиторий не входит.

## Что показал прогон

### Метод работает

| Проверка | Результат |
|---|---|
| Сдвиг и масштаб ×1.37 | похожесть на себя **1.000** у всех 443 |
| Стрелка из двух слоёв (хвостик + указатель) против цельной | совпадает (тест) |
| Скорость | **4.3 мс** на отпечаток 32×32 → библиотека из 500 иконок ≈ 2 с |
| Размер маски 24 / 32 / 48 | 32 не хуже 48 и вдвое быстрее; 24 путает чуть чаще — берём **32** |

### В реальной библиотеке много неразличимых по форме иконок

65 пар с похожестью ≥ 0.99 — три разных случая:

| Случай | Пар | Пример | Чем различать |
|---|---|---|---|
| Та же форма, другая прозрачность слоёв — состояния | 30 | `navigator/lane_forward_0` (прозрачность 0.5) / `lane_forward_1` | прозрачность слоёв иконки в макете |
| Тот же рисунок другого размера на том же холсте | 12 | `controls/close` / `rider/controls/delete` — оба 24×24, крестик разного размера | абсолютный размер рисунка в px |
| Полные дубликаты под разными именами | 23 | `informative/box` / `operations/delivery` | ничем — «спорный вариант», выбор за дизайнером |

Значит, «спорные варианты» — не редкость, а норма: без правил выбора среди
равных по форме подбор был бы случайным.

### Без дубликатов иконки различаются уверенно

330 иконок вне групп дубликатов: лучшая похожесть на другую иконку —
медиана **0.715**, p90 **0.916**, p99 **0.987**. У 43 есть другая с
похожестью ≥ 0.90 (близкие, но разные рисунки — например, направления
манёвров).

Устойчивость к ручной перерисовке (координаты сдвинуты на ±0.2 px):
медиана **0.960**, p5 **0.884**. Отвязанная копия и экземпляр чужой
библиотеки с тем же рисунком дают ≈ 1.0.

### Разные рисунки одной иконки форма не находит

Одноимённые иконки Driver и Rider — один смысл, разные рисунки. Похожесть
от **0.09** (стрелки) до **1.0**, медиана **0.66**: это ниже, чем у
случайных разных иконок. Для такого случая работает только **имя**.

## Выводы для плана

1. **Пороги.**
   - ≥ **0.97** — «Совпала форма» (копия, отвязанная иконка, тот же рисунок
     в чужой библиотеке).
   - **0.85–0.97** — «Похожая форма», только если лучший кандидат обгоняет
     второго хотя бы на 0.05; иначе — «Спорный вариант».
   - < **0.85** — по форме не предлагаем.
2. **Выбор среди равных по форме** (≥ 0.99), по порядку: ближе по
   абсолютному размеру рисунка в px → совпадает прозрачность слоёв → ближе
   имя. Не разрешилось — «Спорный вариант» со списком всех.
3. **Имя важнее, чем казалось.** Если имя совпало, а форма нет, — это чаще
   всего «другой рисунок той же иконки» (иконка из другой библиотеки), а не
   ошибка. Предлагаю вместо «Конфликт» статус **«Другой рисунок»** с
   предложением по имени — решение за Principal Designer.
4. **Нормализация — по контуру самого рисунка** (у отвязанного вектора нет
   холста); размер рисунка — отдельный признак для выбора среди равных.
5. **Отчёт для владельца библиотеки** реален уже сейчас: в библиотеке Driver
   23 полных дубликата, 30 пар состояний, 12 пар размеров.

## Что проверить на этапе 1

SVG — экспорт, а плагин прочитает геометрию из API (`geometry=paths`):
обводки там могут прийти отдельно, а не контуром. Пороги перепроверить на
первой подключённой библиотеке иконок.
