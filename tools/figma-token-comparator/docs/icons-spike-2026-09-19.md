# Иконки — этап 0: проверка отпечатков формы (2026-09-19)

Проверка метода подбора иконки по форме до кода плагина (план — трекер,
раздел «v1.5.0 — иконки»). Тестовый набор — SVG из Presentbook
(`pages/aid-portal/public/icons`): экспорт иконочных файлов Figma.
В плагине иконки будут сравниваться с библиотекой, которую подключит
дизайнер; SVG здесь — только способ проверить метод на настоящих иконках без
Figma и токена.

**Прогон — по каждому продукту отдельно.** Driver и Rider — разные продукты
со своими библиотеками; в одном сканировании они не встречаются, и
совпадать ни по форме, ни по именам не обязаны. Driver — 314 иконок (все
папки, кроме `rider`), Rider — 129 (папка `rider`).

Модуль — `src/lib/iconShape.ts` (тесты — `test/iconShape.test.ts`):
растеризация геометрии в маску N×N с нормализацией в квадрат, похожесть —
IoU масок. Скрипт прогона одноразовый, в репозиторий не входит.

## Что показал прогон

### Метод работает

| Проверка | Результат |
|---|---|
| Сдвиг и масштаб ×1.37 | похожесть на себя **1.000** у всех иконок обоих продуктов |
| Стрелка из двух слоёв (хвостик + указатель) против цельной | совпадает (тест) |
| Скорость | **4–5 мс** на отпечаток 32×32 → библиотека из 500 иконок ≈ 2 с |
| Размер маски 24 / 32 / 48 | 32 не хуже 48 и вдвое быстрее; 24 путает чуть чаще — берём **32** |
| Ручная перерисовка (координаты ±0.2 px) | похожесть на себя: медиана **0.96**, p5 **0.87–0.89** |

### В библиотеке продукта есть неразличимые по форме иконки

Пары с похожестью ≥ 0.99:

| Случай | Driver | Rider | Пример | Чем различать |
|---|---|---|---|---|
| Та же форма, другая прозрачность слоёв — состояния | 30 | 0 | `navigator/lane_forward_0` (прозрачность 0.5) / `lane_forward_1` | прозрачность слоёв иконки в макете |
| Тот же рисунок другого размера на том же холсте | 5 | 3 | крестик 24×24 разного размера | абсолютный размер рисунка в px |
| Полные дубликаты под разными именами | 9 | 11 | `informative/box` / `operations/delivery` | ничем — «спорный вариант», выбор за дизайнером |

«Спорные варианты» — не редкость: без правил выбора среди равных по форме
подбор был бы случайным.

### Без дубликатов иконки различаются уверенно

| | Driver (234) | Rider (104) |
|---|---|---|
| Лучшая похожесть на другую иконку — медиана | 0.669 | 0.704 |
| p90 | 0.897 | 0.940 |
| p99 | 0.967 | 0.987 |
| Путает с другой сильнее, чем с собой после перерисовки ±0.2 px | 2 | 4 |

Отвязанная копия и экземпляр чужого компонента с тем же рисунком дают
похожесть ≈ 1.0.

## Выводы для плана

1. **Пороги.**
   - ≥ **0.97** — «Совпала форма» (копия, отвязанная иконка, тот же рисунок
     в чужом компоненте).
   - **0.85–0.97** — «Похожая форма», только если лучший кандидат обгоняет
     второго хотя бы на 0.05; иначе — «Спорный вариант».
   - < **0.85** — по форме не предлагаем.
2. **Выбор среди равных по форме** (≥ 0.99), по порядку: ближе по
   абсолютному размеру рисунка в px → совпадает прозрачность слоёв → ближе
   имя. Не разрешилось — «Спорный вариант» со списком всех.
3. **Нормализация — по контуру самого рисунка** (у отвязанного вектора нет
   холста); размер рисунка — отдельный признак для выбора среди равных.
4. **Отчёт для владельца библиотеки** реален уже сейчас: в Driver — 9 полных
   дубликатов, 30 пар состояний, 5 пар размеров; в Rider — 11 дубликатов и
   3 пары размеров.

## Что проверить на этапе 1

SVG — экспорт, а плагин прочитает геометрию из API (`geometry=paths`):
обводки там могут прийти отдельно, а не контуром. Пороги перепроверить на
первой подключённой библиотеке иконок.
