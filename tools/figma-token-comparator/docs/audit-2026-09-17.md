# Аудит Token Comparator — 2026-09-17

Трекер работ по результатам аудита кода плагина. **Это точка входа для новой
сессии:** прочитать этот файл, взять нужный батч, сделать, обновить статус в
том же коммите.

## Как работаем

1. **Один батч — одна сессия — один коммит.** За пределы своего батча не
   выходим: замеченное попутно записываем сюда в «Замечено попутно», а не
   чиним на месте.
2. **Сначала тест, который падает,** потом правка, потом тест зелёный. Для
   известных дефектов уже стоят заглушки `it.todo` с номером находки —
   батч начинается с превращения `todo` в настоящий тест.
3. **Ворота перед коммитом:** `npm run typecheck`, `npm run build`,
   `npm test` в плагине, `npm test` в `server/`. Для UI-батчей — ещё прогон
   в браузере.

```bash
cd tools/figma-token-comparator
npm run typecheck && npm run build && npm test
cd server && npm test
```

### Батч 3 — типографика

| № | Находка | Где | Статус |
|---|---|---|---|
| 4 | Переопределения библиотечных стилей отфильтровываются, бейдж «Переопределён» недостижим | `src/comparators/typographyComparator.ts` | **fixed** |
| 5 | Вес шрифта угадывается по имени начертания; флаг `fontWeightApproximate` при сравнении не учитывается | `src/lib/typographyUtils.ts` | **fixed** |
| 6 | Обратное преобразование веса в начертание теряет курсив и нестандартные имена | `src/lib/typographyApply.ts` | **fixed** |
| 10 | `typographyUnresolved: typographyUnresolved \|\| true` — константное выражение | `src/lib/scanner.ts` | **fixed** |

Сделано 2026-09-18:

- **№4.** Решение по открытому вопросу — переопределения **показываем**. Сама
  привязка библиотечного стиля больше не закрывает строку: `findRecordStatus`
  сверяет значения слоя со значениями стиля и при расхождении выдаёт
  `name-match` / `conflict` с перечнем разошедшихся свойств, а
  `requiresTypographyUserAction` закрывает строку только при статусе `exact`.
  Пользователь видит в колонке «Что расходится» ровно переопределённые
  свойства.
- **№5.** `inferFontWeightFromFontName` переписан таблицей «от специфичного к
  общему» — «Demi Bold» больше не попадает под проверку на «bold».
  `typographyValuesEqual` исключает вес из сравнения, если хотя бы одна
  сторона помечена `fontWeightApproximate`. **`typographyValueKey` при этом не
  тронут** — он определяет идентификаторы записей, к которым привязаны
  сохранённые решения.
- **№6.** `resolveFontNameForApply` берёт начертание с самого слоя, когда
  семейство не меняется (основной сценарий), и собирает его из веса только
  при смене семейства, перенося наклон. `fontNameFromTypographyValue` удалён
  за ненадобностью.
- **№10.** Константное выражение убрано.

Тесты: `test/typographyComparator.test.ts`, `test/typographyUtils.test.ts`,
`test/typographyApply.test.ts`. Проверено мутацией: возврат старого поведения
роняет 2 теста.

**Побочный эффект №4, за которым стоит последить.** Переопределения —
частая штука в реальных файлах, и теперь они попадают в таблицу. Если
типографика окажется зашумлённой, лечится это фильтром по статусу из
находки №15 (батч 6), а не возвратом старого поведения: данные теперь верные.

### Батч 5 — бэкенд

| № | Находка | Где | Статус |
|---|---|---|---|
| 9 | Реестр пополняется дубликатами подписей; нет идемпотентности и защиты от гонки версий | `server/api/_lib/mergeRegistryEntries.ts` | **fixed частично** |

Сделано 2026-09-18. Решение по открытому вопросу: **новое решение заменяет
старое**. Реестр хранит текущее решение по каждой подписи, история правок
остаётся в git — она видна в диффе pull request'а.

- Слияние вынесено в `mergeRegistryEntries.ts` и покрыто тестами: замена по
  подписи с сохранением места записи в файле (чтобы дифф читался как правка
  одной строки, а не удаление из середины), схлопывание дубликатов внутри
  одного запроса и дубликатов, накопившихся в реестре раньше.
- Повторная отправка уже записанного решения не заводит pull request:
  сравнение идёт по содержанию решения, без `proposedAt` / `proposedBy`.
  Бэкенд отвечает `{ success: true, unchanged: true }`, плагин показывает
  «Эти решения уже записаны в реестре» вместо «ждёт согласования».

**Не закрыто.** Повторная отправка при **открытом** pull request всё ещё
создаёт второй: слияние идёт от состояния `main`, где решений ещё нет.
Чтобы закрыть, нужно искать открытые PR с теми же подписями — это заметно
больше работы, чем остальная находка.

**Счётчик `registryVersion` остаётся неточным.** Два предложения, созданные
от одного состояния `main`, получают одинаковый номер; git сольёт обе правки
без конфликта, и номер окажется занижен. Ни одна ветка логики на нём не
завязана — он только показывается в статусной строке плагина, поэтому
оставлено как есть с комментарием в коде.

**Изменение не в проде.** Бэкенд деплоится из `main`, а правка лежит в ветке
`feat/token-comparator-typography` — она заработает после мержа.

## Замечено попутно

Сюда пишем то, что нашли вне своего батча, чтобы не отвлекаться.

- Версия `0.1.1` проставлена только в собранном архиве релиза; коммитом в
  репозитории не зафиксирована. Поправить при следующем настоящем релизе.
- `styleId` библиотечного стиля — это `node_id` из REST, а не идентификатор
  стиля (`src/lib/figmaStylesRestApi.ts:232`). Работает за счёт запасного
  матча по `key`, но название вводит в заблуждение.
