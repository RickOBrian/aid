# Что происходит по кнопке «Применить решение»

По кнопке **«Применить решение»** плагин **не меняет макет Figma** — он только фиксирует ваш выбор по **уже выбранной строке** таблицы результатов.

---

## Что нужно сделать до нажатия

1. Кликнуть строку в таблице (она подсветится).
2. В колонке **«Действие»** выбрать вариант в выпадающем списке.
3. При необходимости заполнить доп. поля (токен, комментарий, режим и hex для value fix).
4. Нажать **«Применить решение»** под таблицей.

Кнопка активна только если строка выбрана.

---

## Что происходит в UI (`ui.ts`)

Обработчик читает выбранное действие и валидирует его:

| Действие | Проверка перед отправкой |
|---|---|
| **Использовать предложенный** | У строки должен быть `target` из колонки «Предлагаем» |
| **Выбрать токен из AID** | Токен выбран в combobox (точное совпадение с библиотекой) |
| **Игнорировать** | Комментарий обязателен |
| **Новый кандидат** | Доп. полей нет |
| **Предложить правку значения в библиотеке** | Выбран токен, режим, валидный hex `#RRGGBB` |

Если валидация не прошла — показывается ошибка, в `code.ts` ничего не уходит.

Если всё ок — в главный поток уходит сообщение:

```ts
post({ type: "apply-decision", payload: { recordId, decision, ...поля } })
```

---

## Что происходит в плагине (`code.ts`)

1. **Сохранение в `figma.clientStorage`**  
   Запись пишется в историю решений (`tc_mapping_history`) по ключу `recordId` (id группы записей из скана). Сохраняются:
   - тип решения (`mapped_suggested`, `mapped`, `ignored`, `candidate`, `value_fix_proposed`);
   - timestamp;
   - при необходимости: `targetVariableId`, имя/коллекция токена, комментарий, режим и предлагаемое значение для value fix.

2. **Пересчёт строки**  
   Та же запись снова сравнивается с библиотекой через `colorComparator.compareWithLibrary`, уже с учётом сохранённого решения.

3. **Ответ в UI**  
   Отправляется `decision-applied` с обновлённым `ComparisonResult` для этой строки.

---

## Что меняется на экране

- Строка перерисовывается с учётом решения.
- Для **Mapped / Ignored / Candidate** — в колонке «Статус» появляется ✓ (кроме value fix).
- Для **Value fix proposed** — бейдж **«Правка предложена (Mode)»** вместо исходного статуса.
- Обновляется счётчик **«обработано: X/Y»**.

---

## Чего плагин не делает

- Не привязывает fill/stroke к variable в макете.
- Не создаёт и не меняет переменные в файле библиотеки.
- Не меняет цвета на канвасе.

---

## Что будет при следующем скане

| Решение | Строка в таблице |
|---|---|
| **Mapped (suggested/custom)** | Исчезает |
| **Ignored** | Исчезает |
| **Candidate** | Остаётся |
| **Value fix proposed** | Остаётся (правка в библиотеке ещё не сделана) |

Решение попадает в экспорт CSV/JSON/MD и сохраняется между перезапусками плагина, пока сигнатура группы (свойство + hex + binding + имя источника) не изменится.
