# Token Comparator — чат плагина

Figma-плагин: сканирует макет, сравнивает цвета, типографику и иконки с
библиотекой, помогает принять решение и отправить его на согласование в
общий реестр. Корневой `CLAUDE.md` действует тоже — особенно разделы
«Три продукта — три чата», «Стыки между продуктами» и «Git-полномочия».

## Где работаю

- Папка чата — `~/Projects/aid-plugin` (git worktree). Правлю только
  `tools/figma-token-comparator/`. Всё остальное — чужие продукты: см.
  «Стыки» в корневом `CLAUDE.md`.
- Сервер плагина — `server/`, https://api.aidteam.pro: Яндекс Облако,
  каталог `registry-api` (ADR-038). Мерж в `main` с правкой `server/`
  выкатывает его workflow `registry-api-deploy`. Прежний адрес
  https://aid-registry-api.vercel.app работает для старых установок до
  этапа 7 ADR-038 и деплоится оттуда же.
- Облако — только под профилем `yc --profile registry-api`; правила для
  секретов и профилей — `docs/hub/ORCHESTRATION.md` §4 «Секреты».
- Новую ветку — от свежего `origin/main`:
  `git fetch && git switch -c <ветка> origin/main`.

## Проверки перед тем, как считать работу готовой

```bash
npm run typecheck && npm test && npm run build
cd server && npm run typecheck && npm test
```

Те же шаги гоняет CI, задача «Плагин». `dist/` — результат сборки, в git
не хранится и руками не правится.

## Версии и «Что нового»

- Номер версии — по `semver-guide.md`: новая возможность — MINOR,
  исправление — PATCH.
- «Что нового» в плагине — `src/lib/changelog.ts`. Новая запись
  добавляется **без даты**; дата и версия в `package.json` и
  `package-lock.json` ставятся только при выпуске. Тест
  `test/changelog.test.ts` требует, чтобы у текущей версии была дата.

## Сборка для проверки в Figma

Не из рабочей папки и не в GitHub Release: снимок ветки через
`git archive` во временную папку, там `npm ci` и `npm run release:pack`.
Архив отдать Principal Designer; кнопка в Presentbook при этом по-прежнему
отдаёт последний релиз.

## Релиз — только по явной команде Principal Designer

1. ветка `release/vX.Y.Z` от `origin/main`: версия, дата в
   `changelog.ts`, запись «Выпущено …» в трекере;
2. проверки, PR, мерж — мерж делает Principal Designer;
3. из обновлённого `main`: `npm run release:pack`;
4. GitHub Release `vX.Y.Z`, **Latest**, два одинаковых файла:
   `token-comparator-vX.Y.Z.zip` и `token-comparator.zip`; описание — для
   людей: «Новое / Изменено / Исправлено / Обновление»;
5. **скачать по ссылке кнопки Presentbook**
   (`releases/latest/download/token-comparator.zip`) и проверить, что в
   `README-install.txt` новая версия. Без этой проверки релиз не закончен.

Если менялся `manifest.json` — в описании релиза сказать, что плагин
нужно импортировать заново.

## Интерфейс плагина — компактный

Плагин и так занимает много места в Figma, крупный UX разбавляет контент
(Principal Designer, 2026-09-18).

- Где можно — кнопка-иконка вместо текстовой, плотные строки, без лишних
  подписей и счётчиков. Подпись остаётся, только если без неё непонятно
  состояние.
- Все кнопки без текста — одна система: примитив `.ds-icon-btn` в
  `src/ui.html`; значок — SVG 16px, линия 1.5, `currentColor`, у кнопки
  `aria-label` и `title`. Размер, цвет, hover, focus и раскрытое состояние —
  только в примитиве. Текстовые символы вместо значков не использовать.
- Название библиотеки — имя её файла в Figma.
- Прозрачность в подписи цвета — через «·»: `#2D6CDF · 80%`.

## Секреты

Ключ бэкенда вводится в настройках плагина и в сборку не попадает.
`.env`, `.env.local` и значение ключа не читать, не печатать, не
коммитить; в архиве релиза их быть не должно.
