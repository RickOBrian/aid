# Token Comparator — полный гайд

Figma-плагин для **детерминированного аудита цветов** в макете: сравнивает fills/strokes/text fills текущего файла с эталонной библиотекой Figma Variables из другого файла и показывает интерактивную таблицу расхождений.

**Не использует LLM/AI.** Сравнение — точные совпадения hex/alpha и перцептивная близость (Delta E).

**MVP покрывает только категорию Colors.** Плагин — прежде всего инструмент **аудита и учёта решений**, а не автомат миграции. **Единственное исключение** — действие **«Применить в макет»** (раздел 8): по явному подтверждению пользователя оно реально привязывает найденную переменную библиотеки к fill/stroke/text fill затронутых нод. Все остальные действия (сканирование, «Применить решение», превью, экспорт, печать) макет **не меняют**.

## 1. Установка и импорт

### Сборка (для разработчиков)

```bash
cd tools/figma-token-comparator
npm install
npm run build
```

Результат сборки:

| Артефакт | Назначение |
|---|---|
| `dist/code.js` | Главный поток плагина (Plugin API, REST API, storage) |
| `dist/ui.html` | UI плагина (HTML + инлайн JS) |

Для разработки с автопересборкой: `npm run watch`.

### Импорт в Figma Desktop

1. Откройте **Figma Desktop** (импорт по manifest недоступен в браузере без десктоп-клиента).
2. **Plugins → Development → Import plugin from manifest…**
3. Выберите файл:
   ```
   /Users/desexpert/Projects/aid/tools/figma-token-comparator/manifest.json
   ```
4. Плагин появится в **Plugins → Development → Token Comparator**.
5. После изменений кода: `npm run build` → перезапустите плагин в Figma.

## 3. Сквозной флоу (от нуля до экспорта)

```
┌─────────────────────────────────────────────────────────────────┐
│ 1. НАСТРОЙКИ                                                   │
│    PAT + file key → Сохранить → Загрузить библиотеку            │
└────────────────────────────┬────────────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│ 2. СКАНИРОВАНИЕ                                                 │
│    Скоуп (файл / страница / выделение) → Сканировать цвета      │
└────────────────────────────┬────────────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│ 3. РЕЗУЛЬТАТЫ                                                   │
│    Фильтр по статусу → клик по строке → выбор «Действие»        │
│    → Применить решение (по строкам)                             │
└────────────────────────────┬────────────────────────────────────┘
                             ▼
┌─────────────────────────────────────────────────────────────────┐
│ 4. ЭКСПОРТ / ПЕЧАТЬ                                             │
│    Экспорт CSV / JSON / MD → «Скачать» (файл)                   │
│                            → «Напечатать» (страница «Маппинг»)  │
└─────────────────────────────────────────────────────────────────┘
                             │
                             ▼ (после правок в макете или библиотеке)
                    Повторить шаги 2–4 и сравнить экспорты
```

**Важно:** решения сохраняются локально и подтягиваются при повторном скане. Строки с решениями Mapped (suggested/custom) / Ignored **исчезают** из таблицы при следующем скане. Candidate **остаётся**.

## 4. Флоу: Настройки и загрузка библиотеки

### Шаг 1 — Personal Access Token (PAT)

Плагин читает переменные библиотеки через Figma REST API:
`GET https://api.figma.com/v1/files/:file_key/variables/local`

**Как получить PAT:**

1. Figma → **Settings** → **Security** → **Personal access tokens** → **Generate new token**.
2. Убедитесь, что у токена есть scope **`file_variables:read`** (для Enterprise может потребоваться доступ уровня организации).
3. Скопируйте токен сразу — повторно посмотреть нельзя.
4. Вставьте в поле **Personal Access Token** на вкладке «Настройки».

PAT хранится локально в `figma.clientStorage` и уходит **только** на `api.figma.com`.

### Шаг 2 — File key библиотеки

`file_key` — сегмент URL библиотечного файла:

```
https://www.figma.com/design/AbCdEfGhIjKlMnOpQrStUv/My-Library-Name
                              ^^^^^^^^^^^^^^^^^^^^^^
                              это file_key
```

Можно вставить полный URL — плагин извлечёт ключ автоматически.

### Шаг 3 — Сохранить настройки

Кнопка **Сохранить настройки** записывает PAT и file key в `clientStorage`. При следующем запуске плагина поля подставятся автоматически (PAT показывается как `•••••••• (сохранён)`).

### Шаг 4 — Загрузить библиотеку

Кнопка **Загрузить библиотеку**:

1. Отправляет запрос к REST API с PAT и file key.
2. Загружает все **COLOR**-переменные файла библиотеки.
3. Резолвит значения по режимам (Day/Night и др.) через цепочки алиасов **внутри файла**.
4. Кэширует результат в `clientStorage`.
5. Показывает статус: *«Библиотека загружена: N цветовых переменных, обновлена …»*.

Повторный клик = **обновление** библиотеки (перезапрос API).

#### Что именно считается «библиотекой»

В список токенов для сравнения попадают **только локальные переменные выбранного файла** (`remote: false`).

Переменные из **других** библиотек, которые сам файл-библиотека потребляет (`remote: true`), **не добавляются** как отдельные кандидаты в «Предлагаем». Это предотвращает предложение токенов не из того файла, который вы указали в настройках.

При этом такие remote-переменные всё ещё участвуют **внутри** резолва алиасов локальных токенов.

## 5. Флоу: Сканирование макета

### Выбор скоупа

| Скоуп | Что сканируется |
|---|---|
| **Весь файл** | Все страницы документа |
| **Текущая страница** | Только `figma.currentPage` (по умолчанию) |
| **Выделение** | Только выделенные ноды на текущей странице |

### Что собирает сканер

Для каждой видимой ноды (рекурсивный обход):

| Свойство | Описание |
|---|---|
| `fill` | Заливка (для TEXT — как `text-fill`) |
| `stroke` | Обводка |
| `text-fill` | Заливка текста |

**Учитывается только `SOLID` paint.** Градиенты и изображения пропускаются.

### Тип привязки (Binding)

Для каждого paint определяется один из типов:

| Binding | Как определяется |
|---|---|
| **Variable** | Есть `boundVariables` на этот paint |
| **Style** | Есть `fillStyleId` / `strokeStyleId`, нет variable binding |
| **Ghost** | Style binding, но стиль удалён / недоступен |
| **Hardcoded** | Нет ни variable, ни style — сплошной hex |

### Группировка

Одинаковые случаи **группируются** в одну строку таблицы:

```
ключ группы = hash(свойство + hex + alpha + bindingType + sourceName)
```

Для группы хранится:

- `count` — сколько раз встретилось (колонка **Uses**);
- `representativeNodeName` / `representativeNodePath` — представитель для навигации;
- `nodeIds` — до 500 id слоёв для выделения в макете.

### Day/Night в макете («Сейчас»)

Для **Variable** binding плагин резолвит значения **по всем режимам** коллекции переменной через Plugin API (Day, Night и др.).

Для **hardcoded / style / ghost** значение одно — оно не зависит от режима; в UI показывается одинаково.

### После сканирования

1. Каждая группа сравнивается с загруженной библиотекой.
2. Подтягивается история решений из `clientStorage`.
3. Строки, не требующие действия пользователя, **отфильтровываются**.
4. UI переключается на вкладку **Результаты**.

## 6. Флоу: Таблица результатов

### Колонки

| Колонка | Содержимое |
|---|---|
| **Статус ▾** | Бейдж типа расхождения (или «Правка предложена») + ✓ для решений кроме value fix |
| **Слой** | Имя слоя (кликабельно — переход к нодам в макете) + путь |
| **Сейчас** | Что в макете: имя variable/style или hex; Day/Night для variables |
| **Предлагаем** | Предложенный токен библиотеки + Day/Night; «нет совпадения» если аналога нет |
| **Uses** | Количество вхождений группы |
| **Действие** | Выпадающий список решения + доп. поля |

### Визуальные детали «Сейчас»

| Binding | Свотч |
|---|---|
| **Style** | **Круглый** |
| Variable / Hardcoded / Ghost | Квадратный |

### Выбор строки

1. Клик по строке (не по кнопкам/инпутам) — строка подсвечивается голубым.
2. Кнопка **Применить решение** внизу таблицы активна только для **выбранной** строки.

### Переход к слою

Клик по имени слоя в колонке «Слой»:

1. Переключает `currentPage` на страницу ноды.
2. Выделяет все ноды группы (до лимита).
3. Приближает viewport (`scrollAndZoomIntoView`).

### Показать превью

Кнопка **Показать превью** в колонке «Действие» доступна для строк со статусами **Value match**, **Name match**, **Conflict** и **Approximate match** — то есть там, где у строки есть library target с резолвленным значением. Для **Hardcoded (no analog)**, **Style binding**, **Ghost style** и **Name match (value unknown)** кнопки нет — сравнивать не с чем.

По клику плагин строит два PNG-снимка одного участка макета:

1. Находит представительную ноду группы; если она мелкая (площадь < 24×24px) или это самостоятельная VECTOR-иконка без визуального контекста — поднимается к ближайшему предку FRAME/COMPONENT/INSTANCE/GROUP, чтобы на снимке было видно окружение, а не голый квадрат 1×1.
2. Создаёт **один временный клон** этого контейнера и переносит его далеко за пределы видимого контента (на текущей странице, без переключения `figma.currentPage`).
3. Сопоставляет режимы макета и библиотеки через **index-pairing** (`lib/modePairing.ts`): сначала по совпадению имени или синонимам day↔light / night↔dark, иначе попарно по индексу после стабильной сортировки (например Mode 1↔Day, Mode 2↔Night). Нерезолвленные режимы библиотеки пропускаются. Для Hardcoded/Style/Ghost (значение не зависит от режима) «Было» одно и то же для каждого резолвленного режима библиотеки.
4. На **том же клоне**, по очереди для каждой пары режимов: ставит текущее значение макета → экспортирует PNG («Было») → ставит предлагаемое значение библиотеки для этого режима → экспортирует PNG («Будет»).
5. Удаляет клон **один раз** в конце и присылает в UI по паре снимков на каждый режим как `data:image/png;base64,...`.

**Оригинальный макет не меняется ни на миг** — все правки применяются только к клону, который гарантированно удаляется (try/finally) сразу после экспорта, при любом исходе, включая ошибки. Пока превью строится — модальное окно показывает индикатор загрузки; готовые снимки сгруппированы по режиму (подпись: имя режима библиотеки или «библиотека · макет», если имена различаются), внутри каждой группы — пара «Было» / «Будет»; окно закрывается кнопкой × или Esc. Если построить превью не удалось — в том же окне показывается текст ошибки (с указанием режима, если сбой произошёл на нём) без поломки остальной таблицы.

Построение превью **не параллелится**: пока идёт одна сборка, кнопки «Показать превью» у других строк заблокированы — активировать вторую можно только после завершения первой.

### Фильтр «Статус ▾»

- Чекбоксы по каждому статусу, присутствующему в результатах.
- «Все» / «Снять все».
- Счётчик над таблицей учитывает фильтр: *«N из M случаев (фильтр по статусу), обработано: X/Y»*.

### Счётчик над таблицей

| Состояние | Текст |
|---|---|
| Нет результатов | *«Все в порядке — расхождений не найдено…»* |
| Фильтр скрыл все строки | *«0 из N случаев — выберите статусы…»* |
| Есть строки | *«N случаев требуют решения, обработано: X/N»* |

## 7. Флоу: Применить решение

### Порядок действий

1. Кликнуть строку в таблице.
2. В колонке **Действие** выбрать вариант в выпадающем списке.
3. При необходимости заполнить дополнительные поля.
4. Нажать **Применить решение** под таблицей.

### Варианты решения

#### 1a. Использовать предложенный (Mapped, suggested)

| | |
|---|---|
| **Доп. поле** | Нет — используется токен из колонки «Предлагаем» (`result.target`) как есть |
| **Требование** | Доступно только если у строки есть предложенный токен (колонка «Предлагаем» не пуста) |
| **Сохраняется** | `decision: mapped_suggested`, id/имя/коллекция target-токена, timestamp |
| **При перескане** | Строка **исчезает** из таблицы |
| **Не делает** | Не привязывает fill/stroke к variable в макете |

#### 1b. Выбрать токен из AID (Mapped, custom)

| | |
|---|---|
| **Доп. поле** | Combobox «Начните вводить имя токена/стиля…» — выбор из загруженной библиотеки |
| **Требование** | Точное совпадение с токеном из списка; без выбора Apply не сработает |
| **Сохраняется** | `decision: mapped`, id и имя выбранного токена, timestamp |
| **При перескане** | Строка **исчезает** из таблицы |
| **Не делает** | Не привязывает fill/stroke к variable в макете |

Под combobox есть своя кнопка **«Показать превью»** — включается сразу
после выбора токена из списка, ещё **до** нажатия «Применить решение».
Открывает ту же модалку «Было / Стало» (§ «Показать превью»), но строит
target напрямую из выбранного токена (`build-preview` с явным
`variableId`), а не из истории решений — сохранять решение для этого не
нужно. Это даёт паритет с «Использовать предложенный», где превью
доступно сразу, поскольку `result.target` уже известен автоматически.
Кнопка снова блокируется, если очистить поле ввода или пока строится
другое превью (общий лимит «не параллелится», см. § «Показать превью»).

**Использовать предложенный vs Выбрать токен из AID:** первый — быстрый путь, когда предложение плагина («Предлагаем») подходит без изменений. Второй — когда предложенный токен не подходит (или его нет вовсе), и нужен другой токен из библиотеки AID.

#### 2. Игнорировать (Ignored)

| | |
|---|---|
| **Доп. поле** | Комментарий (**обязателен**) |
| **Сохраняется** | `decision: ignored`, comment, timestamp |
| **При перескане** | Строка **исчезает** |
| **Смысл** | Расхождение осознанное — hex/стиль остаётся как есть, токен не нужен, править не будем |

#### 3. Отметить как новый токен-кандидат (Candidate)

| | |
|---|---|
| **Доп. поле** | Нет |
| **Требование** | Доступно для любой строки, в т.ч. без target в библиотеке |
| **Сохраняется** | `decision: candidate`, timestamp |
| **При перескане** | Строка **остаётся** (токена в библиотеке пока нет) |
| **Не делает** | Не создаёт variable в файле библиотеки |

#### 4. Предложить правку значения в библиотеке (Value fix proposed)

| | |
|---|---|
| **Доп. поле** | Селектор **режима** target-переменной; поле **предлагаемого hex** (предзаполняется из «Сейчас» для выбранного режима); **комментарий** (опционально) |
| **Требование** | Доступно только если найден target-токен: Value match, Name match, Name match (value unknown), Conflict, Approximate match. Mode обязателен; hex валидируется (`#RRGGBB`) |
| **Сохраняется** | `decision: value_fix_proposed`, targetVariableId/Name/CollectionName, proposedModeId/Name, currentLibraryValue, proposedValue, comment?, timestamp |
| **При перескане** | Строка **остаётся** (правка в библиотеке ещё не выполнена вручную) |
| **Не делает** | Не пишет в REST API библиотеки; не меняет макет; не вызывает Plugin API setValueForMode |

**Candidate vs Value fix proposed:** Candidate — подходящего токена в библиотеке **ещё нет**. Value fix proposed — токен **уже есть** и подходит по смыслу, но значение в **конкретном режиме** (Day/Night) нужно поправить вручную дизайнеру библиотеки.

### Сводная таблица

| Вариант | Меняет макет | Исчезает при перескане | Доп. требование |
|---|---|---|---|
| Использовать предложенный | Нет | Да | Нужен предложенный токен (target) |
| Выбрать токен из AID | Нет | Да | Выбор из списка библиотеки |
| Игнорировать | Нет | Да | Комментарий обязателен |
| Новый кандидат | Нет | Нет | — |
| Правка значения в библиотеке | Нет | Нет | Режим + предлагаемый hex |

### Что происходит после Apply

1. Решение записывается в `clientStorage` (`tc_mapping_history`).
2. Ключ — `LayoutRecord.id` (hash группы).
3. В колонке «Статус»: ✓ для mapped_suggested/mapped/ignored/candidate; бейдж **«Правка предложена (Mode)»** для value_fix_proposed.
4. Обновляется счётчик «обработано».
5. Решение попадает в экспорт (для value fix — доп. колонки «Для режима» и «Предлагаемое значение»).

**Ни один из вариантов «Применить решение» не меняет макет Figma.** Реальную запись в макет выполняет только отдельное действие «Применить в макет» (раздел 8) — и только после явного подтверждения.

## 8. Флоу: Применить в макет

### Что это

**Применить в макет** — единственное действие плагина, которое **реально изменяет макет** Figma: оно берёт найденную переменную библиотеки и привязывает её к fill/stroke/text fill затронутых нод через Figma Variables API.

Это **отдельное, самостоятельное действие** — не связано с кнопкой **Применить решение** (раздел 7) и не переиспользует её сообщение/кнопку. «Применить решение» лишь фиксирует выбор в `clientStorage` и никогда не трогает макет; «Применить в макет» выполняет реальную запись и делает это только после явного подтверждения в отдельном модальном окне.

### Когда доступно

Кнопка **Применить в макет** в колонке «Действие» показывается только когда одновременно выполнено:

- у строки статус **Mapped** — то есть решение (`decision`) `mapped_suggested` («Использовать предложенный») или `mapped` («Выбрать токен из AID»);
- у строки есть однозначный target — известны `variableId`/`key` переменной библиотеки.

Кнопки **нет** для решений **Ignored**, **Candidate**, **Value fix proposed**, и для строк вообще без решения (в т.ч. Hardcoded без совпадения) — это ожидаемо: у них нет однозначно выбранной переменной для привязки.

### Подтверждение перед записью

По клику открывается модальное окно с превью операции — без него запись не выполняется:

| Поле | Источник |
|---|---|
| Слой/группа | `representativeNodeName` |
| Свойство | fill / stroke / text fill (`property`) |
| Затронуто нод (uses) | `count` |
| Переменная | `target.name` (`target.collectionName`) |

Дополнительно в модалке:

- **Было / Стало** — значения макета и выбранной переменной библиотеки по режимам (Day/Night и др.), со swatch'ами — те же данные, что в колонках «Сейчас» и «Предлагаем».
- **Превью участка макета** — PNG-пары «Было / Стало» на временном клоне слоя (тот же механизм, что у кнопки «Показать превью»); строится автоматически при открытии модалки.

Запись выполняется только по кнопке **Подтвердить и применить**. Закрытие окна (× / Esc / «Отмена») отменяет операцию — в макете ничего не меняется.

### Что делает обработчик

1. Берёт `nodeIds` группы — они уже сохранены в `LayoutRecord` при сканировании.
2. Если переменная библиотеки ещё не импортирована в текущий файл — импортирует её через `figma.variables.importVariableByKeyAsync(key)` **один раз** для всей группы.
3. Для каждого `nodeId`:
   - находит ноду через `figma.getNodeByIdAsync` (с фолбэком на `loadAllPagesAsync`, если страница ещё не загружена);
   - если нода не найдена — пропускает и фиксирует в отчёте как «не найдено», **не прерывая** обработку остальных нод группы;
   - для `fill` / `text-fill`: читает копию `node.fills` (сами `fills`/`strokes` — read-only массивы), ищет индекс paint, чьё текущее значение (hex + alpha) совпадает с тем, что нашёл сканер, создаёт новый paint через `figma.variables.setBoundVariableForPaint(paint, "color", variable)` (не мутирует исходный объект), собирает новый массив и присваивает `node.fills = newFills`; если на свойстве был привязан paint style (`fillStyleId`) — сначала снимает эту привязку;
   - для `stroke` — та же логика через `node.strokes` / `strokeStyleId`;
   - посимвольные заливки текста (`node.fills === figma.mixed`) — нода пропускается с понятной причиной, автоматическая замена невозможна;
   - любая ошибка на конкретной ноде (в т.ч. сбой импорта переменной для всей группы) **не прерывает** обработку остальных — фиксируется как «пропущено» с причиной, итог — частичный успех, а не сбой всей операции.
4. Собирает отчёт: сколько нод обработано успешно (`applied`), сколько пропущено с причиной (`skipped`).
5. При успешном применении хотя бы к одной ноде — очищает запись этой строки в mapping history (`clientStorage`). Группа теперь реально привязана к переменной библиотеки, поэтому решение Mapped из истории больше не нужно: при следующем скане группа пересчитается заново по фактическому состоянию макета и обычно попадёт под **Exact match** (переменная реально из этой библиотеки) — то есть пропадёт из таблицы расхождений, а не будет «залипшей» на старом решении.

### После применения

Модальное окно показывает итог: «Применено к N из M нод» и, если есть пропуски, — «пропущено: K» со списком `nodeId → причина`. Таблица результатов **не обновляется автоматически** — чтобы увидеть новую классификацию строки, нужно пересканировать макет (кнопка **Сканировать цвета**).

### Ограничения

- Индекс paint для замены определяется по совпадению текущего значения (hex + alpha) с тем, что нашёл сканер при скане — если слой изменили между сканом и применением, подходящий paint может не найтись, и нода будет пропущена с причиной.
- Посимвольные (`mixed`) заливки текста не поддерживаются — нода пропускается.
- Действие необратимо средствами самого плагина — отменить можно только вручную через Figma (Cmd/Ctrl+Z) сразу после применения.
- Группа может содержать до 500 `nodeIds` (лимит сканера, см. раздел 5) — применение проходит по всем сохранённым id, без ограничения дополнительно.

## 9. Флоу: Экспорт и печать

На вкладке **Результаты** три кнопки — **Экспорт CSV**, **Экспорт JSON**, **Экспорт MD**. Каждая открывает меню из двух пунктов:

Меню закрывается по клику вне него или по `Escape`.

### Скачать

| Кнопка | Файл | Формат |
|---|---|---|
| **Экспорт CSV** → Скачать | `token-comparator-mapping.csv` | Таблица с заголовками, UTF-8 |

| **Экспорт MD** → Скачать | `token-comparator-mapping.md` | Markdown-таблица |

1. Плагин находит страницу **«Маппинг»** в текущем файле; если её нет — создаёт и кладёт в конец списка страниц.
2. Строит таблицу по единому дизайн-стандарту отчётов (Root Table → Header Block → Data Container → Table Header Row → Data Row).

**Дизайн и состав таблицы одинаковы** для всех трёх кнопок: CSV/JSON/MD влияют только на формат «Скачать». Внутри таблицы:

| **Table Header Row** | Те же названия колонок, что в CSV/MD |

Данные для всех четырёх выходов (CSV, JSON, MD, Figma-таблица) готовит **одна и та же функция** — состав полей всегда совпадает.

## 10. Статусы сканирования (бейджи)

Бейдж в колонке «Статус» показывает, как значение в макете соотносится с загруженной библиотекой.

| Бейдж | Когда |
|---|---|
| **Style binding** | Цвет через **paint style**, не variable |
| **Ghost style** | Ссылка на удалённый / недоступный стиль |
| **Hardcoded (no analog)** | Сплошной hex без совпадения в библиотеке |
| **Value match** | Hex+alpha **точно совпадают** с токеном библиотеки, но привязка/имя другие |
| **Name match** | Имя совпало, цвет отличается умеренно (ΔE ≤ 20) |
| **Name match (value unknown)** | Имя совпало, значение библиотеки не резолвится (внешний алиас REST API) |
| **Conflict** | Имя совпало, цвет **существенно отличается** (ΔE > 20) |
| **Approximate match (ΔE N)** | Ближайший цвет в библиотеке в пределах порога ΔE ≤ 5 |
| **Правка предложена (Mode)** | Применённое решение `value_fix_proposed`: предложена ручная правка target-переменной в указанном режиме. Заменяет исходный бейдж; tooltip — исходный статус |

После Apply с Mapped (suggested/custom) / Ignored строка при следующем скане скрывается. Candidate и Value fix proposed остаются до изменений в библиотеке.

## 11. Алгоритм сравнения с библиотекой

Приоритет определения статуса (реализован в `colorComparator.ts`):

```
1. Подтверждённый mapped из истории решений → статус Mapped
2. Exact match — variableId/key макета = variableId/key библиотеки
   (по всей библиотеке, без ограничения коллекцией)
3. Value match — точное совпадение hex+alpha в любом режиме токена
   коллекции color-sem
4. Name match / Conflict — совпадение имени variable/style при разных
   значениях, только среди токенов коллекции color-sem
   4a. Name match (value unknown) — имя совпало, но значения не резолвятся (REST)
5. Approximate match — минимальный Delta E ≤ 5 по коллекции color-sem
   (alpha должна совпадать)
6. Layout only → UI: Hardcoded (no analog) для hardcoded binding
```

Шаги 3–5 ищут кандидатов **только в коллекции `color-sem`** — токены
других коллекций (например `effects`) не предлагаются автоматически и не
показываются в combobox ручного выбора. Exact match (шаг 2) не ограничен
коллекцией: если в макете уже стоит переменная не из `color-sem`,
привязка остаётся видна как есть.

**Пороги:**

| Константа | Значение | Назначение |
|---|---|---|
| `APPROX_MATCH_DELTA_E_THRESHOLD` | 5 | Approximate match |
| `NAME_CONFLICT_DELTA_E_THRESHOLD` | 20 | Name match vs Conflict |

### Scope tie-break (Value / Name / Approximate)

Figma-переменная COLOR может иметь `scopes` — список свойств, где её
разрешено использовать (`STROKE_COLOR`, `TEXT_FILL`, `FRAME_FILL`,
`SHAPE_FILL`, `ALL_FILLS`, `EFFECT_COLOR`, `ALL_SCOPES`). Плагин читает
это поле из REST API (`fetchLibraryColorVariables`) и хранит в
`LibraryToken.scopes`.

Если на одном уровне совпадения (шаг 3, 4 или 5) находится **несколько**
кандидатов с одинаковым качеством — одинаковый hex при Value match,
одинаковое имя при Name match, одинаковый минимальный Delta E при
Approximate match — побеждает тот, чей `scopes` соответствует свойству
макета (`lib/variableScope.ts`, `preferScopeCompatibleCandidates`):

| Свойство макета (`LayoutRecord.property`) | Совместимые scopes |
|---|---|
| `fill` (не текстовый — frame/shape) | `FRAME_FILL`, `SHAPE_FILL`, `ALL_FILLS` |
| `stroke` | `STROKE_COLOR` |
| `text-fill` | `TEXT_FILL` |
| любое | `ALL_SCOPES` (совместим всегда) |

Это **tie-breaker внутри уровня**, не отдельный шаг приоритета:

- если кандидат только один — scope не влияет, ничего не меняется;
- если ни один кандидат не совместим со свойством — порядок остаётся как
  есть (первый найденный, без учёта scope);
- более точное совпадение без подходящего scope **всегда** важнее менее
  точного совпадения с "правильным" scope — Value match со scope
  `EFFECT_COLOR` побеждает Name match со scope `STROKE_COLOR`, потому что
  уровни (3 → 4 → 5) не смешиваются.

## 13. Хранение данных

Всё хранится в **`figma.clientStorage`** (~5 MB на плагин), а не в `pluginData` документа — данные переживают разные файлы макетов.

| Ключ | Содержимое |
|---|---|
| `tc_pat_token` | Personal Access Token |
| `tc_library_file_key` | File key библиотеки |
| `tc_library_cache` | Кэш загруженных токенов + timestamp |
| `tc_mapping_history` | История решений по `LayoutRecord.id` |

Ключ решения = hash(`property + hex + alpha + bindingType + sourceName`). Если сигнатура группы не изменилась, решение подтягивается автоматически при перескане.

## 14. Ограничения MVP

| Ограничение | Детали |
|---|---|
| Только SOLID paints | Градиенты и изображения пропускаются |
| Посимвольный цвет текста | `fills === figma.mixed` пропускается |
| Alpha | Из `paint.opacity`, без композиции с `node.opacity` |
| Маски | Нода с `isMask === true` пропускается |
| Boolean operations | Учитывается как единый узел |
| REST API алиасы | Алиас за пределы файла библиотеки → «value unknown» |
| Rate limit | При 429 — повторить позже вручную |
| «Применить решение» не меняет макет | Фиксирует выбор только локально в `clientStorage` |
| Макет меняет только «Применить в макет» | И только по явному подтверждению в модальном окне (раздел 8) |
| Не создаёт токены | Candidate — только маркировка |
| Только Colors | Typography, Spacing и др. — в roadmap |
| Применить в макет: индекс paint по значению | Заменяется paint, чьё текущее значение совпадает с найденным при скане — если слой изменили после скана, нода пропускается |
| Применить в макет: mixed-заливки текста | Посимвольные (`figma.mixed`) заливки не поддерживаются — нода пропускается с причиной |
| Применить в макет: без undo плагина | Отменить результат можно только вручную через Figma (Cmd/Ctrl+Z) |
| Печать: лимит 300 строк | Больше — печатаются первые 300 + предупреждение; для полного набора «Скачать» |
| Печать: только страница «Маппинг» | Имя страницы фиксированное; таблицы накапливаются по X, вручную не переупорядочиваются |
| Печать: шрифт | Google Sans, при недоступности — fallback на Inter / Roboto с предупреждением в консоли |
| Показать превью: лимит контейнера | Контейнер шире/выше 4000px → превью не строится, показывается ошибка |
| Показать превью: один представитель | Превью строится по **одному** представительному вхождению группы (первый `nodeIds[0]`), не по всем найденным нодам |
| Показать превью: без параллельных сборок | Пока строится одно превью, следующая активация ждёт его завершения |
| Показать превью: упрощение paint-стека | На клоне свойство (fill/stroke/text-fill) заменяется **одной** сплошной заливкой нужного цвета — если у ноды было несколько paints, на превью это не сохранится |
| Показать превью: сопоставление режимов | Режимы макета и библиотеки сопоставляются по имени/синонимам или по индексу (Mode 1↔Day и т.п.); нерезолвленные режимы библиотеки пропускаются |
| Показать превью: один клон на строку | Один клон используется для всех режимов последовательно (не создаётся отдельный клон на каждый режим) |
| Показать превью: из combobox «Выбрать токен из AID» | Доступно сразу после выбора токена в списке, без сохранения решения; `build-preview` уходит с явным `variableId` вместо автоматического `result.target` |

## 15. Типичные ошибки и что делать

| Сообщение | Причина | Действие |
|---|---|---|
| PAT недействителен / 403 | Неверный токен или нет доступа | Проверить PAT, scope `file_variables:read` |
| Файл не найден / 404 | Неверный file key или нет доступа к файлу | Проверить URL, аккаунт, scope |
| Rate limit / 429 | Слишком много запросов | Подождать минуту, «Загрузить библиотеку» снова |
| Укажите PAT и file_key | Пустые поля | Заполнить оба поля перед загрузкой |
| Выберите переменную из списка | Mapped без выбора токена | Выбрать из combobox |
| Комментарий обязателен | Ignored без комментария | Заполнить textarea |
| Слой не найден | Нода удалена после скана | Пересканировать |
| Нет строк для выбранных статусов | Фильтр скрыл всё | Открыть «Статус ▾», включить статусы |

## 16. Сценарии использования

### Аудит перед релизом макета

1. Загрузить актуальную библиотеку.
2. Сканировать **весь файл**.
3. Пройти Conflict / Name match — исправить в макете или зафиксировать Ignored.
4. Экспорт MD → приложить к PR или задаче.

### Миграция hardcoded → tokens

1. Сканировать страницу / выделение.
2. Hardcoded (no analog) → Candidate или Mapped (если есть approximate/value match).
3. Экспорт CSV → передать в backlog на создание токенов в библиотеке.
4. После добавления токенов — обновить библиотеку, пересканировать.

### Проверка одного компонента

1. Выделить фрейм компонента.
2. Скоуп **Выделение** → Сканировать.
3. Клик по слоям → правки в макете.
4. Перескан → сравнить счётчик «обработано».

### Style → Variable (ручная миграция)

1. Найти строки **Style binding**.
2. Выбрать Mapped + variable из библиотеки (учёт решения).
3. Вручную заменить style на variable в Figma.
4. Перескан — строка должна исчезнуть (variable из библиотеки).
