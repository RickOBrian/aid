# AID Team — открытые вопросы

Вопросы, без ответа на которые шаги `PLAN.md` не двигаются. Ответ
записывается под вопросом с датой, вопрос получает статус. Ответы не
содержат имён и контактов — только роли и решения.

Статусы: `open` · `answered` · `dropped`

---

## Q-00 · answered 2026-10-02
**Где живёт база с личными данными?**

**Ответ:** Яндекс Облако, облако `aidteam`, каталог `team-data` (ADR-038).
Репозиторий остаётся публичным. Требований 152-ФЗ нет.

## Q-01 · answered 2026-10-06
**Кто входит в базу на старте?**

Сколько человек и какие роли (PD, инженеры продуктов, дизайнеры?). Нужны
только роли и число — имена в репозиторий не пишутся.

**Ответ PD:** четыре человека.

| Роль | Продукты, которыми владеет | Инструмент |
|---|---|---|
| PD | Token Comparator, MCP, Style Migration, Presentbook (и системный уровень) | Claude |
| Инженер Library Updater | Library Updater | Claude |
| Инженер бота | Bot · Request | Claude |
| Инженер без продукта (менеджер команды) | продукты назначит PD позже | Cursor |

Колонка «Инструмент» — решение PD 2026-10-06; в карточке — поле `tool`.

Совпадает с `docs/hub/owners.json` для первых трёх ролей. Четвёртая роль
попадёт в `owners.json`, когда PD назначит ей продукт (решение PD, Штаб).
Логины и имена — в `team-data`, не здесь.

## Q-02 · answered 2026-10-06
**Что хранится о человеке?**

Кандидаты: имя, роль, продукты, за которые отвечает, GitHub-логин, Яндекс
ID (для входа), канал связи (Telegram, почта), часовой пояс, доступность.
Что из этого действительно нужно для передачи задач?

**Ответ PD («ок» на предложение):** как обращаться, GitHub-логин, роль,
продукты, Telegram, отметка согласия. Яндекс ID — позже, со входом в
Presentbook. Схема — `schema/people.schema.json`.

**Уточнение PD 2026-10-06:** имя — обязательно, фамилия — по желанию,
Telegram — по желанию, GitHub-логин — обязательно. Публичными данные быть
не обязаны, но Claude каждого инженера должен определять любого человека
по этим данным (схема — формат 2). Как дать чтение — Q-08.

**Уточнение PD 2026-10-06 (2):** ролей в карточке нет — аккаунты и
карточки делятся по обязательному полю, по умолчанию GitHub-логину
(схема — формат 3).

## Q-08 · answered 2026-10-06
**Как Claude каждого инженера читает `people.json`?**

Нужно чтение у всех инженеров, без публикации данных и без общего ключа.
(а) Личный ключ только на чтение бакета у каждого инженера (профиль `yc`).
(б) Функция в Облаке: инженер приходит со своим GitHub-токеном, функция
сверяет логин с `owners.json` и отдаёт файл.

## Q-03 · answered 2026-10-06
**Где живёт сама задача?**

(а) В репозитории — GitHub Issues или файл, исполнитель — роль или
GitHub-логин; контекст рядом с кодом, видно всем.
(б) В `team-data` — закрыто, но контекст отдельно от кода.
(в) Смешанно: задача и контекст — в Issues, связь «задача → человек» —
в `team-data`.

**Ответ:** GitHub Issues между Штабами, метки `hub`, `to:<продукт>`,
`decision:pd` (ADR-041). Исполнитель — роль; «роль → логин» —
`docs/hub/owners.json`. `team-data` — имена и контакты.

## Q-04 · answered 2026-10-06
**Как инженер узнаёт о новой задаче?**

GitHub-уведомление (упоминание в Issue), Telegram через AID Bot, почта —
или «увидит, когда откроет чат». От этого зависит, нужен ли стык с AID Bot.
Сейчас `/plan` Штаба собирает issues сам — то есть «увидит при запуске
`/plan`». Вопрос — нужно ли уведомление сверх этого.

**Ответ PD:** пока достаточно `/plan` Штаба инженера, который сам
собирает его issues. Telegram через AID Bot — если задачи начнут теряться.

## Q-05 · answered 2026-10-06 (частично)
**Как Claude инженера читает базу и свои задачи?**

(а) Через `gh` — если задачи в GitHub Issues.
(б) Через API в Облаке с входом по Яндекс ID.
(в) Через профиль `yc` с правами только на чтение `team-data`.
Нужно, чтобы у каждого инженера был доступ только к нужному, без общих
ключей.

**Ответ:** задачи — через `gh` (вариант а, ADR-041), проверка авторов —
по `owners.json`. Открыто: кому и как нужен доступ к `team-data` — решится
вместе с Q-07.

## Q-06 · answered 2026-10-06
**Как фиксируется согласие человека?**

Сам заполняет свою карточку (это и есть согласие), или PD вносит, а
человек подтверждает. Кто может исправить или удалить карточку.

**Ответ PD:** PD вносит карточку, человек лично подтверждает PD; в
карточке `consent.date`, без неё карточка не используется.

## Q-07 · answered 2026-10-06
**Кто пишет в базу?**

Только PD, каждый — свою карточку, или чаты Claude тоже (например,
отметка «задача взята»).

**Ответ PD:** пишет только PD (через свой вход; чат AID Team — по его
прямой просьбе). Чаты только читают. Порядок — `STORAGE.md`.

**Ответ PD:** «а». У каждого инженера — сервисный аккаунт
`reader-<github-логин>` в каталоге `team-data` (по полю карточки, не по
роли — уточнение PD 2026-10-06), право — чтение бакета по ACL; запись
проверена — отказ. Ключи создаёт PD при
передаче инженеру. Порядок — `READER.md`.
