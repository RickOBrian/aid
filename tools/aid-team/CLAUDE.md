# AID Team — чат базы инженеров и оркестрации задач

Корневой `CLAUDE.md` действует тоже — особенно разделы «Три продукта — три
чата», «Стыки между продуктами» и «Git-полномочия». Протокол работы между
чатами — `docs/hub/ORCHESTRATION.md`, его ведёт «AID · Hub · Штаб».

Вход в контекст: этот файл → `PLAN.md` → `OPEN-QUESTIONS.md`.

## Где работаю

- Чат — «AID · Ops · Team», папка — `~/Projects/aid-team` (git worktree).
  Правлю только `tools/aid-team/`. Всё остальное — чужие продукты: см.
  «Стыки» в корневом `CLAUDE.md`.
- Новую ветку — от свежего `origin/main`:
  `git fetch && git switch -c <ветка> origin/main`.
- Координацию между чатами ведёт Штаб, не этот чат. Здесь — база
  инженеров и передача задач между людьми (разные аккаунты Claude, разные
  машины): `SendMessage` между ними не работает, это и решает продукт.

## Задача

База инженеров команды и рабочая оркестрация задач между ними. Каждый
инженер работает в своём аккаунте Claude; память чатов у них не общая.

Что должно стать возможным:

- назвав имя инженера, передать ему задачу или принять задачу от него — в
  нужном инструменте;
- подхватить задачу коллеги из своего аккаунта Claude с полным контекстом:
  что сделано, что осталось, где лежит;
- формировать задачи и данные между инженерами в общем формате.

План и его шаги — `PLAN.md`. Пока на вопросы `OPEN-QUESTIONS.md` нет
ответов, ничего не строить и ни одной записи о человеке не создавать.

### Что уже есть рядом

- Каждый продукт ведёт свой вход в контекст (`CLAUDE.md` → `PLAN.md` →
  `OPEN-QUESTIONS.md`) — это уже способ передать работу между чатами.
- AID Bot (`tools/aid-bot/`) — Telegram-бот команды. Его Q-04 решён по-своему:
  контракт бота живёт в `tools/aid-bot/`, инженер ревьюит PR. Это канал
  для общего контракта, а не для личных данных — база людей остаётся здесь.
- Очередь `registry/propose-*` и GitHub PR — действующий канал передачи
  решений между инструментами и людьми.
- Вход в Presentbook через Яндекс ID по списку людей (ADR-038) будет брать
  список из этой базы.
