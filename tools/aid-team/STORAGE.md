# AID Team — хранилище базы

Где лежит база инженеров и как с ней работать. Данных здесь нет:
репозиторий публичный.

## Где

| Что | Значение |
|---|---|
| Облако / каталог | `aidteam` / `team-data` (ADR-038) |
| Бакет | `aidteam-team-data` — Object Storage, закрыт: анонимное чтение и список выключены, лимит 100 МБ |
| Файл | `people.json` — схема `schema/people.schema.json` |
| Версии | включены: каждая запись сохраняет прошлую версию файла |
| Для бота | бакет `aidteam-team-bot`, файл `telegram.json` — только «логин → Telegram» (решение PD 2026-10-07, ADR-042) |

Один файл, а не база данных: людей четверо (Q-01), запросы не нужны.
Переход на YDB — когда людей станет заметно больше.

## Кто читает и пишет

- **Пишет только PD** (Q-07), через свой админский вход в Облако. Чат
  «AID · Ops · Team» вносит правки по прямой просьбе PD в этом чате, под
  его профилем `default`.
- **Читают** PD, этот чат и Claude каждого инженера — через личный
  сервисный аккаунт `reader-<github-логин>` с правом только на чтение бакета
  (Q-08, вариант «а»). Подключение — `READER.md`. Ключи выдаёт PD.
- **Бот** «AID · Bot · Request» видит не базу, а только `telegram.json` в
  отдельном бакете `aidteam-team-bot`: сервисный аккаунт
  `reader-bot-request`, право — чтение этого бакета (ACL). К `people.json`
  доступа нет — проверено. Ключ создаёт PD и передаёт владельцу бота лично.
- «Логин → продукты» для проверки авторов issues — не здесь, а в
  `docs/hub/owners.json` (ADR-041). Здесь — зеркало и остальное.

## Карточка

Поля (Q-02, уточнено PD 2026-10-06): **имя** и **GitHub-логин** —
обязательно; фамилия и Telegram — по желанию; **инструмент** (`tool`:
`claude` или `cursor`) — обязательно; плюс продукты и отметка согласия.
Инструмент нужен, чтобы выбирать инструкции, скиллы и способ связи под
человека (решение PD 2026-10-06, формат 4). Ролей в карточке нет: человек определяется GitHub-логином
(формат 3, решение PD 2026-10-06). Claude любого инженера должен находить человека по любому из
этих полей: имени, фамилии, Telegram, логину. Яндекс ID добавится вместе
со входом в Presentbook по списку людей.

**Согласие (Q-06):** PD вносит карточку, человек лично подтверждает PD.
В карточке `consent.date`. Без неё карточка не используется ни одним
инструментом. Человек вправе попросить исправить или удалить карточку —
удаление включает старые версии файла.

## Как вносить правку

Просьба PD в чате «AID · Ops · Team», например: «внеси карточку: …,
согласие подтвердил сегодня». Чат:

1. скачивает `people.json` во временную папку сессии;
2. меняет одну карточку, проверяет файл по схеме;
3. загружает обратно и удаляет временную копию;
4. показывает PD только изменённую карточку, не весь файл;
5. **после любой правки `people.json`** — пересобрать `telegram.json`:
   из карточек с `consent.date` и `telegram` взять пары `github` →
   `telegram`, без имён и остальных полей, формат
   `{"format": 1, "source": "people.json format N", "people": [{"github", "telegram"}]}`;
   загрузить в `aidteam-team-bot`, временную копию удалить.

Удаление человека — та же последовательность плюс удаление старых версий
файла, где он был; только по слову PD.
Из `telegram.json` человек убирается тем же шагом 5.

## Чего не делать

- Не копировать `people.json` и его фрагменты в репозиторий, issues,
  доски Штабов и память чатов.
- Не открывать бакет на чтение и не выдавать на него ключи без решения PD.

## Имена ресурсов

Всё, что относится к человеку (сервисные аккаунты, ключи), называется по
обязательному полю его карточки — по умолчанию GitHub-логину, не по роли
(решение PD 2026-10-06): роль меняется, человек тот же. `owners.json`
Штаба устроен так же — ключ `github`, ролей нет (формат 2, решение PD «а»).
