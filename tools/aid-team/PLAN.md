# AID Team — план

Живой план базы инженеров и передачи задач между ними. Вопросы, без которых
шаги не двигаются, — в `OPEN-QUESTIONS.md`.

---

## Что решаем

Каждый инженер работает в своём аккаунте Claude, на своей машине.
`SendMessage` между чатами ходит только внутри одной машины
(`docs/hub/ORCHESTRATION.md` §2), память чатов не общая. Поэтому нужны:

1. **База инженеров** — кто есть в команде, за что отвечает, как с ним
   связаться. Личные данные — только в Облаке, каталог `team-data`.
2. **Передача задачи по имени** — «передай Пете задачу X» в чате одного
   инженера превращается в задачу, которую Петя видит в своём аккаунте
   Claude с полным контекстом: что сделано, что осталось, где лежит.
3. **Общий формат** задачи и передачи, одинаковый для людей и чатов.

---

## Принципы

- Личные данные — только в `team-data`. В публичном репозитории — схема,
  формат и протокол, без людей. Человек в файлах репо — роль.
- Контекст задачи (ветки, PR, файлы) по возможности живёт в репозитории
  — он и так публичный; база хранит, **кому** задача и **как** его
  уведомить.
- Человек попадает в базу только с согласия и видит свою карточку.
- Не дублировать: канал задач между людьми — GitHub Issues между Штабами
  (ADR-041, `ORCHESTRATION.md` §9); «роль → GitHub-логин» —
  `docs/hub/owners.json`, правит только PD. База дополняет их
  (имена, контакты, уведомления, назначение по имени), но не заменяет.
- Каждый шаг — с критерием готовности; ничего не строить до ответов на
  вопросы, от которых шаг зависит.

### Варианты хранилища (шаг 4) — для обсуждения

| Вариант | Плюсы | Минусы |
|---|---|---|
| YDB serverless | Настоящая база, запросы, бесплатный уровень, доступ по ролям | Нужна функция-API перед ней |
| Object Storage + JSON-файлы | Проще всего, версии файлов, дёшево | Нет запросов и блокировок при одновременной записи |
| Managed PostgreSQL | Привычный SQL | Платный кластер постоянно, для десятка записей избыточен |

Решение PD 2026-10-06: Object Storage + один JSON — людей четверо.
YDB — когда станет заметно больше.
