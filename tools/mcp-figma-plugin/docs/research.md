# MCP Figma-плагин — исследование

> Статус: Draft · 2026-10-09 · чат «AID · Plugin · MCP» · доска AID-7

Вопрос: можем ли мы сделать свой Figma-плагин, который заменяет
официальный Figma MCP. Агент вызывает его так же, как MCP, а работу в
файле выполняет сам плагин через Plugin API, без кредитов и лимитов Figma.

Короткий ответ: **да, можем, и технически это небольшая работа.** Но
прямо сейчас лимиты нас не держат, и деньги в этой схеме — это не
главное. Главная ценность своего моста — инструменты на языке AID
(токены, компоненты, правила), которых у официального MCP нет. Решение
ниже, в разделе 7.

---

## 1. Эталон

### Что известно

Всё знание — со слов коллег PD (2026-10-01). Других данных нет, и
спрашивать коллег не будем (ответ PD 2026-10-09):

- свой плагин в Figma, который «эмулирует MCP»;
- поднимает свой сервер «а-ля MCP», а в Figma передаёт команды сам,
  через API;
- цель — не тратить кредиты Figma: у официального MCP жёсткие лимиты.

Ни названия, ни кода, ни сценариев эталона у нас нет. Поэтому дальше
эталон описан через открытые проекты того же устройства: по словам
коллег, это та же схема.

### Открытые проекты той же схемы

| Проект | Что это | Лицензия |
|---|---|---|
| [grab/cursor-talk-to-figma-mcp](https://github.com/grab/cursor-talk-to-figma-mcp) | Самый известный: ~7 тыс. звёзд. MCP-сервер + отдельный WebSocket-релей + плагин. ~40 инструментов: чтение документа, выделения, стилей, компонентов; создание фреймов, текста, инстансов; auto layout, заливки, перенос, удаление | MIT |
| [figma-console-mcp (Southleft)](https://docs.figma-console-mcp.southleft.com/architecture) | Плагин «Desktop Bridge» сам ищет MCP-сервер на локальных портах. Умеет CRUD переменных. Есть облачное сопряжение по 6-значному коду | см. репозиторий |
| [Writable Figma MCP Bridge](https://glama.ai/mcp/servers/l0lg4p4s2a) и др. | Один инструмент `run_js`: агент присылает произвольный код, плагин его выполняет с откатом при ошибке | разные |

Большинство мелких проектов — форки первого.

### Как устроено (общая схема)

```
Агент (Claude Code, Cursor)
   │  MCP по stdio
   ▼
Локальный MCP-сервер (Node/Bun)
   │  WebSocket на localhost
   ▼
UI плагина (iframe) — только он имеет сеть
   │  postMessage
   ▼
Код плагина — Plugin API (figma.*) → открытый документ
```

У проектов есть общие черты:

- плагин должен быть **открыт** в нужном файле, иначе команды некуда
  слать;
- сеть есть только у iframe UI, у основного кода плагина её нет. Поэтому
  WebSocket живёт в UI, а команды идут в код через сообщения
  ([документация Figma](https://developers.figma.com/docs/plugins/making-network-requests));
- `ws://localhost:<порт>` объявляется в `networkAccess` манифеста с
  обязательным `reasoning` ([манифест](https://developers.figma.com/docs/plugins/manifest)).

## 2. Можем ли мы

### Лимиты официального Figma MCP — от чего защищает мост

По [гайду Figma](https://github.com/figma/mcp-server-guide/blob/main/README.md)
и [странице лимитов](https://developers.figma.com/docs/figma-mcp-server/rate-limits-access/)
на 2026-10-09 (Figma оставляет за собой право менять цифры):

| Кто | Чтение |
|---|---|
| Enterprise, место Full или Dev | 600 вызовов в день и 20 в минуту |
| Organization / Professional, Full или Dev | 200 в день; 20 / 15 в минуту |
| Любой план, место **View или Collab** | **6 вызовов в месяц** |

- **Запись в холст** (`use_figma` и подобные) сейчас в бете,
  бесплатна и **не входит** в лимиты. Figma заявила, что она станет
  платной, с оплатой за использование. Даты и цены нет.
- Запись доступна только местам Full и Dev на платных планах, и только
  через удалённый сервер.
- Отдельно с марта 2026 действуют кредиты на AI-функции Figma. Цифры у
  сторонних источников расходятся, поэтому здесь они не приводятся. Тратит
  ли кредиты `use_figma`, официально не сказано. Это открытый вопрос
  Р-1.

**Вывод для нас (Enterprise).** Пока 600 чтений в день на человека с
Full или Dev и бесплатная запись покрывают обычную работу: PD
подтвердил, что сейчас в лимиты не упираемся. Мост становится нужен в
трёх случаях:

1. запись в холст станет платной;
2. агент работает в цикле: прочитал → поправил → проверил. Такой цикл
   быстро упирается в 20 вызовов в минуту;
3. MCP нужен людям с местами View или Collab — разработчикам, ревьюерам.
   Для них 6 вызовов в месяц — это ноль.

**Поправка к пункту 3 (2026-10-09).** PD подтвердил: люди с местом View
есть, и MCP им в идеале нужен. Но человек с местом View **не может
запускать плагины**: Figma ограничивает плагины теми, у кого есть право
редактирования. Это ответ поддержки Figma на форуме, в справке это не
описано ([1](https://forum.figma.com/ask-the-community-7/view-seat-users-cannot-access-figma-currentpage-in-plugin-enterprise-organization-47807),
[2](https://forum.figma.com/report-a-problem-6/can-no-longer-access-figma-plugins-47796)).
Значит, мост на плагине людям с View не поможет, как и официальный MCP.
Для них работает другая схема: человек с местом Full или Dev через мост
снимает **слепок** макета (структура, токены, скриншоты) и кладёт его
туда, где агент читает без Figma. Это раздел 5, идея 7.

### Ограничения Plugin API — чего мост не сможет

| Возможность официального MCP | Через Plugin API | Комментарий |
|---|---|---|
| Узлы, свойства, выделение (`get_metadata`) | да | полностью |
| Переменные и стили (`get_variable_defs`) | да | локальные и подключённые из библиотек, без REST и без Enterprise-only эндпоинта |
| Скриншот узла (`get_screenshot`) | да | `exportAsync` → PNG; агенту отдаём файл или base64 |
| Запись: фреймы, инстансы, auto layout, привязка переменных (`use_figma`) | да | это родная задача Plugin API |
| Код по макету: React + Tailwind (`get_design_context`) | **частично** | генерация Figma работает на её стороне и мосту недоступна. Plugin API отдаёт CSS узла (`getCSSAsync`) и привязанные переменные, и из них можно собрать свой код. PD подтвердил, что код по макету через мост нужен: это самая дорогая часть, см. вариант B |
| Code Connect | **нет** | данные хранятся у Figma |
| Поиск по библиотекам команды (`search_design_system`) | частично | Plugin API видит только подключённые к файлу библиотеки, каталога организации у него нет |
| Работа без открытого Figma | **нет** | плагин должен быть запущен в файле |

### Сеть, хранение, авторизация

- **Сервер в облаке не нужен.** Всё живёт на машине пользователя: MCP-сервер
  и WebSocket на `localhost`. Нового деплой-контура, Vercel-проекта или
  Облака нет.
- **Авторизация.** Токен Figma не нужен: плагин работает с правами того,
  кто его открыл. Зато нужна защита самого моста, см. риск Р-3.
- **Хранение.** Только `figma.clientStorage` для настроек (например,
  порт). Данные макета никуда не уходят, кроме агента.
- **Распространение.** На Enterprise плагин публикуется как приватный
  плагин организации, без ревью Figma
  ([справка](https://help.figma.com/hc/en-us/articles/4404228629655)).
  Сервер ставится каждому отдельно: `npx` или npm-пакет плюс строка в
  настройках агента.

**Рекомендация: C сейчас и дешёвая проверка B (раздел 7).** A не беру
как основу. Мост ради моста даёт агенту рисовать в обход токенов, а
ценность для AID — ровно в обратном. Открытый проект годится как
образец устройства и как стенд для проверки.

Совмещать B и C можно: свой мост для операций AID, официальный MCP — для
кода по макету и Code Connect.

**После ответов PD (2026-10-09).** Код по макету через мост нужен, а
пользователи — и инженеры, и дизайнеры. Порядок B меняется. Первая
версия — чтение и контекст в токенах AID. Её же получают люди с View,
через слепок (идея 7). Код по макету идёт второй версией и в токенах AID
(идея 8). Пока его нет, у людей с Full или Dev остаётся
`get_design_context` официального MCP. Это закрывает потребность без
ожидания.

## 4. Связь с AID

- **Стандарты.** Мост может отдавать агенту контекст в терминах
  стандартов: не «цвет #…», а «`bg-accent-main`, semantic, привязан». И
  отказывать в записи литерала цвета там, где по `token-rules.md` это
  `must`. Так стандарты проверяются в момент работы, а не постфактум.
- **Token Comparator.** Самое большое пересечение. Плагин уже
  сканирует макет и сравнивает цвета, типографику и иконки с
  библиотекой. Переменные он читает через REST
  (`api.figma.com/v1/files/:key/variables/local`). Инструмент моста «проверь
  выделение на соответствие токенам» — это то же сравнение. Делать его
  второй раз нельзя. Варианты: общий модуль или мост вызывает логику
  Comparator. По правилам чатов это вопрос PD, а не тихий импорт (Р-5).
- **AID Style Migration.** Задача продукта пока не описана в его
  `CLAUDE.md`. Если это миграция стилей в макетах, массовую замену
  стилей на токены удобно делать агентом через мост. Нужен разговор,
  когда у продукта появится описание.
- **Presentbook.** Прямой связи нет. Позже — страница с установкой
  моста и кнопка скачивания, через чат Presentbook, по правилу стыка
  про GitHub Releases (без метки Latest).
- **AID Bot.** Прямой связи нет. Мост работает только при открытом Figma
  на машине человека, бот на сервере его вызвать не может.
- **Продукты (`driver`, `rider`).** Мост читает реальные файлы UI Kit и
  может помогать сверять их с `tokens/`. Читает, а не правит: канон
  меняется по своим правилам.

## 5. Идеи — что сделать лучше эталона

1. **Инструменты намерений, а не примитивов.** Вместо «`set_fill_color`
   rgb» — «примени токен `bg-accent-main`», «вставь компонент
   `ButtonText` variant=primary», «проверь выделение по правилам AID».
   Агенту нужно меньше вызовов, и он не может обойти токены.
2. **Без отдельного релея.** WebSocket поднимает сам MCP-сервер:
   один процесс, одна команда установки.
3. **Сопряжение по коду.** Плагин показывает одноразовый код, агент его
   передаёт. Без кода команды не принимаются: сайт в браузере не
   подключится к порту (Р-3).
4. **Режим «только чтение» по умолчанию.** Запись включается
   переключателем в плагине на время сессии.
5. **Журнал действий в плагине.** Что агент изменил. Всё, что сделано
   за сессию, откатывается одним шагом Undo в Figma: команды группируются.
6. **`run_js` — только как запасной выход** и только с подтверждением в
   плагине. Произвольный код от агента — то же, что `use_figma`, но
   без подтверждения это дыра.
7. **Слепок для тех, кто без плагинов.** Человек с местом Full или Dev
   одной командой снимает слепок фрейма или страницы: структуру, токены,
   скриншоты. Слепок сохраняется файлом рядом с задачей или в репозитории.
   Агент инженера с местом View читает слепок без Figma, без лимитов и
   без плагина. Это единственный найденный путь для View.
8. **Код по макету в токенах AID.** Генератор Figma выдаёт Tailwind и
   литералы. Наш берёт привязанные переменные и пишет
   `var(--bg-accent-main)`, `DSTokens…`, `DSTheme.tokens…` по
   `platforms.md`, для трёх стеков. Это то, чего официальный MCP не
   умеет в принципе.

## 8. Шаг 1 — ход проверки

Копия `grab/cursor-talk-to-figma-mcp` (коммит `ddd90f3`, 2026-07-26)
лежит в песочнице вне репозитория. В неё ничего из нашего кода не
попадает, в репозиторий из неё тоже.

### Что видно по коду, без запуска

- **Переменных нет совсем.** Ни одного инструмента для чтения или
  привязки переменных. Ответы о заливках и обводках удаляют поле
  `boundVariables`, и агент не узнает, что цвет был токеном. Сценарии
  «прочитать переменные» и «привязать переменную» на аналоге невозможны.
  Это подтверждает минус варианта A: мост общего назначения рисует в
  обход токенов.
- **Порт без защиты.** Релей принимает любое подключение,
  `Access-Control-Allow-Origin: *`, без проверки Origin и без пароля.
  Сопряжение — имя канала из 8 случайных символов (`Math.random`), его
  знает только плагин. Это снижает риск, но не закрывает Р-3.
- **Адрес релея.** В коде строка `hostname: "0.0.0.0"` закомментирована,
  как будто по умолчанию будет localhost. Это не так, см. ниже.
- **Аналитика.** Плагин шлёт в Google Analytics открытия и имена команд
  (без содержимого файла, по их словам). Для песочницы домен убран из
  манифеста, и Figma такие запросы заблокирует.
- **Нужен Bun** для релея. Сам MCP-сервер собран и работает в Node.

### Что проверено запуском (2026-10-09)

Релей запущен в песочнице: Bun 1.4.2, локальная установка.

- **Релей виден в локальной сети.** Bun по умолчанию слушает все
  интерфейсы (`lsof`: `*:3999`), хотя сам сообщает `localhost`. Исходный
  релей аналога доступен любому устройству в той же сети. В песочнице мы
  привязали его к `127.0.0.1`.
- **Р-3 — подключение со страницы.**
  - Со страницы `http://localhost` подключение и вход в канал прошли
    без пароля: релей принимает любого клиента.
  - С внешнего сайта (`https://example.com`) подключение не дошло до
    релея. Его заблокировал браузер (Chromium, защита локальной сети), а
    не мост. В другом браузере или при другой настройке такой защиты
    может не быть.
  - Вывод: защита порта у аналога держится на браузере пользователя.
    Для нашего моста сопряжение по коду и проверка Origin обязательны
    (идея 3).

### Что осталось проверить запуском

Нужны действия PD: установка пакетов в песочнице не прошла из-за сетевых
ограничений сессии, а импорт плагина в Figma делается руками.

- сценарий 2: фрейм и инстанс библиотечного компонента; время и число
