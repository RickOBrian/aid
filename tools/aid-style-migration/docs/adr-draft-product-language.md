# Проект ADR: язык продукта — общая база знаний (2026-09-30)

Статус: **проект** чата AID Style Migration. Принимается в чате стандартов
(владелец `products/` и `docs/standards-alpha/DECISIONS.md`) решением
Principal Designer. Номер ADR присвоит чат стандартов.

Решения Principal Designer в чате AID Style Migration, 2026-09-30: знание о
продукте — общее для команды; правила подтверждают Principal Designer и
главный по AID (сейчас в плагине, потом в Presentbook); база знаний общая
с Token Comparator, код — раздельный; где хранить и как согласовать —
«реши сама».

---

## ADR-0XX · 2026-09-30 · proposed
**Язык продукта — версионируемый артефакт в репозитории, общий для
инструментов.**

**Контекст.** Перевод макетов на продукт ошибался, потому что опирался на
имена токенов и цвета исходника: фиолетовая «ВОЙТИ» ушла в
`Buttons/Accent`, хотя в образцах Driver `Buttons/Accent` на кнопках не
встречается ни разу, главное действие — `Buttons/Positive`, обычные
кнопки — `Buttons/Primary` (разбор — `tools/aid-style-migration/docs/spike-2026-09-29.md`).
Как продукт применяет токены по ролям элементов — знание, которого нет ни
в библиотеке, ни в стандартах. Сейчас оно живёт в `clientStorage` одного
человека: его не видит команда, у него нет истории и ревью.

**Решение.**

1. **Язык продукта** — файл `products/<id>/style-language.json` рядом с
   `product.json`: как продукт оформляет роли элементов (главное действие,
   обычная, второстепенная, разрушительная кнопка, ссылка, таб, поле,
   чип, иконка, карточка, шторка, фон, разделитель, статусы), иерархию
   текста, поверхности, ритм, иконки и тёмную тему — с доказательствами
   из образцов, расхождениями и статусом каждого правила.
2. **Роли — по стандарту**: семейства и уровни из
   `ds-component-architecture-guide` / `naming-conventions`. Отход
   продукта от стандарта — находка, не ошибка (к стандарту стремимся, но
   текущее не ломаем).
3. **Источник правды — репозиторий.** Инструменты читают подтверждённую
   версию из `main` (как Token Comparator читает реестр через
   `raw.githubusercontent.com`, без сервера). Изменения — предложением:
   инструмент готовит файл, коммит — через PR, решение — Principal
   Designer и главный по AID.
4. **Статусы правил:** `proposed` (найдено в образцах) → `confirmed`
   (подтверждено) / `disputed` (роль оформлена по-разному) / `missing`
   (роли нет в образцах — пробел для библиотеки или образцов).
5. **Кто пишет:** AID Style Migration — изучение образцов и предложения;
   позже — пакетное изучение по REST. **Кто читает:** AID Style
   Migration (перевод), Token Comparator (применён ли токен по роли),
   Presentbook (страница ревью языка продукта), аудит библиотеки.
6. **Схема версионируется** (`$schema: aid-style-language/1`); изменение
   формата — согласованно, через чат стандартов.

**Стыки** (строки для корневого `CLAUDE.md`, раздел «Стыки между
продуктами»):

| Стык | Владелец | Правило |
|---|---|---|
| Язык продукта: `products/<id>/style-language.json` | Стандарты — файл и схема; AID Style Migration — предложения содержания | Содержание меняется только PR с решением Principal Designer и главного по AID; инструменты читают версию из `main`; схема меняется согласованно |
| Машинный слой стандартов в AID Style Migration: `skills/_shared/standards/*.json` | Стандарты — содержание; AID Style Migration — чтение | Плагин читает при сборке; изменение формата JSON — через оба чата; в отчётах плагина — версия стандартов |
| Ревью языка продукта в Presentbook | Presentbook — показ; Стандарты — данные | Presentbook читает `style-language.json`, не правит |

**Последствия.**

- Одна правда о том, как продукт применяет токены, — для перевода,
  сравнения и ревью.
- Каждый новый файл образцов и каждое решение при переводе уточняют язык
  продукта через PR, а не теряются в памяти одного человека.
- Решение №11 AID Style Migration («с Token Comparator функционально не
  связаны») уточняется: общая база знаний, код раздельный до общего
  пакета.

**Как применять.** Не подставлять правило из имени токена там, где есть
правило языка продукта. Роль без правила — «нужно решение» и находка,
а не догадка.

## Тексты для других чатов

### Чат «Стандарты ДС»

> Чат AID Style Migration предлагает ADR «Язык продукта» — проект в
> `tools/aid-style-migration/docs/adr-draft-product-language.md` (ветка
> `feat/style-migration-spike`). Просьба: принять ADR под следующим
> номером в `docs/standards-alpha/DECISIONS.md`, добавить три строки
> стыков в корневой `CLAUDE.md`, завести пустой
> `products/driver/style-language.json` со схемой
> `aid-style-language/1`, когда плагин выгрузит первое предложение.
> Роли элементов берутся по `ds-component-architecture-guide` и
> `naming-conventions` — проверьте, что таксономия ролей из проекта с
> ними сходится.

### Чат «Presentbook»

> Не срочно, после принятия ADR «Язык продукта»: появится
> `products/<id>/style-language.json` — как продукт оформляет роли
> элементов, с примерами и статусами правил. Предложение — страница ревью
> языка продукта рядом со страницами токенов: карточка на роль, токены
> Day / Night, примеры, расхождения, статус. Presentbook только читает
> файл.

### Чат «Token Comparator»

> Для сведения: после принятия ADR «Язык продукта» в
> `products/<id>/style-language.json` появится, каким токеном продукт
> оформляет каждую роль элемента. Token Comparator сможет отличать «токен
> существует» от «токен применён не по роли». Код остаётся раздельным.
