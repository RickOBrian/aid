# Журнал решений программы

Новые — сверху. Формат: дата · решение · кто · почему. Решения из
трекера плагина до 2026-09-30 остаются в `audit-2026-09-29.md`.

---

**2026-10-01 · D-13 · Ответы по разбору 03.** Ошибка отправки — отдельное состояние сообщения (`Right`); быстрые ответы — вариант кнопки; у шапки нужен слот действия справа; поле сообщения — вариант поля. Уточнение: «назначение» — роль взаимодействия и смысл, не содержимое (`lessons.md` 2.1а). Кто: Principal Designer.

**2026-10-01 · D-12 · Ответы по разбору 02 и сводный файл уроков.** Пин карты, бейдж маршрута, иконка машины (одна, поворот на макете) — в ДС; линия маршрута — только токен. Кнопка чата кругом — ошибка, счётчик — необязательная часть `fab`. Отвязка — сигнал недостающего варианта (комментарий с продолжением линии маршрута). Комментарий к точке — два стиля одного компонента. Скрывать содержимое перекраской — ошибка дизайнера. Правила копятся в `products/driver/atlas/reviews/lessons.md`. Кто: Principal Designer.

**2026-10-01 · D-11 · Ответы по разбору 01.** Шторка — пропущенный компонент (контейнер со слотами); свёрнутая точка и маршрут, адрес заказа и адрес предложения — разные компоненты (решает назначение, не вид; в библиотеке Order/Offer неверно вариантами одного `address`); разный состав частей при одном назначении — один компонент с опциональными частями; красная мотивация — вопрос автору, пока красный стиль; спрятанная рамка — вопрос автору, отложено. Локальные компоненты находить и решать: в библиотеку или оставить локально, оформив по правилам библиотеки. В ревью два адресата: Principal Designer и автор макета. Кто: Principal Designer.

**2026-09-30 · D-10 · Вопросы Principal Designer — с визуалом: фрагмент экрана с подсветкой места + как в текущей библиотеке (живые инстансы) + варианты ответа.** Кто: Principal Designer («текстом не всегда понятно»).

**2026-09-30 · D-9 · Источник элемента: А — компонент библиотеки (эталон оттуда); Б — компонент создан в файле или другом файле (новый компонент или развитие существующего — решаем отдельно); В — не компонент, но должен быть; Г — компонент, но архитектурно неправильно собран. `bar/button` под шторкой — нормальное перекрытие слоёв, не ошибка.** Кто: Principal Designer.

**2026-09-30 · D-8 · Разборы экранов — на отдельной странице «AID · Разбор экранов» в файле образцов (живой инстанс экрана + маркеры + разбор по уровням); текст-источник — `products/driver/atlas/reviews/`.** Кто: Principal Designer («заведи в том файле отдельный пейдж для аудита»). Это единственная разрешённая запись в файл образцов; остальное — только чтение.

**2026-09-30 · D-7 · Проверяет экзамен сначала Principal Designer.**
Кто: Principal Designer. Почему: сначала отладить знание с одним
проверяющим; дизайнеров продукта подключим позже.

**2026-09-30 · D-6 · Машинный формат атласа согласуем с чатом Presentbook
с самого начала.** Кто: Principal Designer. Почему: у атласа два читателя
(Presentbook и инструменты) — один контракт, без переделок.

**2026-09-30 · D-5 · Плагин переводит «левый» продукт в эталонный
(Driver, Rider…), а не Driver → Rider.** Кто: Principal Designer.
Следствие: учим два умения — читать чужое по стандартам и писать на своём
по атласу; для экзамена нужны образцы «левых» макетов.

**2026-09-30 · D-4 · Атлас строим по уровням: паттерн → выбор компонента →
вариант и состояние → содержимое → оформление.** Кто: предложено мной,
принято Principal Designer («давай попробуем, если что — изменим»).
Почему: дизайнер решает сверху вниз; ошибка верхнего уровня важнее
перекрашенной иконки.

**2026-09-30 · D-3 · Этот чат планирует и учится; правки Presentbook —
отдельный чат.** Кто: Principal Designer. Почему: Presentbook — зона
другого чата. Предпросмотр — только во временной копии вне репозитория.

**2026-09-30 · D-2 · Компоненты остаются в Figma; токены и стили
Presentbook ведёт синхронно с Figma для всех эталонных продуктов.** Кто:
Principal Designer. Почему: вёрстка компонентов в Presentbook рискованна и
не нужна; токены обязаны совпадать. Замер Driver:
`products/driver/atlas/tokens/drift-2026-09-30.md`.

**2026-09-30 · D-1 · Эталон — библиотека и стандарты, а не статистика
макетов; атлас продукта — данные в `products/<id>/atlas/`, показ — в
Presentbook (общий для эталонных продуктов). Плагин заморожен до
экзамена.** Кто: Principal Designer. Почему: статистика принимает
систематическую ошибку за норму; знание должно быть общим для людей и
инструментов.
