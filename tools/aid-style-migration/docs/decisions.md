Кто: Principal Designer. Почему: сначала отладить знание с одним
проверяющим; дизайнеров продукта подключим позже.

**2026-09-30 · D-6 · Машинный формат атласа согласуем с чатом Presentbook
с самого начала.** Кто: Principal Designer. Почему: у атласа два читателя
(Presentbook и инструменты) — один контракт, без переделок.

**2026-09-30 · D-5 · Плагин переводит «левый» продукт в эталонный
(Driver, Rider…), а не Driver → Rider.** Кто: Principal Designer.
Следствие: учим два умения — читать чужое по стандартам и писать на своём
по атласу; для экзамена нужны образцы «левых» макетов.

**2026-09-30 · D-4 · Атлас строим по уровням: паттерн → выбор компонента →

принято Principal Designer («давай попробуем, если что — изменим»).
Почему: дизайнер решает сверху вниз; ошибка верхнего уровня важнее
перекрашенной иконки.

другого чата. Предпросмотр — только во временной копии вне репозитория.

**2026-09-30 · D-1 · Эталон — библиотека и стандарты, а не статистика
