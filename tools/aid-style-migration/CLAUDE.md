# AID Style Migration — чат плагина

Figma-плагин для Presentbook. Отдельный продукт: с Token Comparator общих
кода, сборки и релизов нет. Корневой `CLAUDE.md` действует тоже — особенно
разделы «Три продукта — три чата», «Стыки между продуктами» и
«Git-полномочия».

## Где работаю

- Папка чата — `~/Projects/aid-style-migration` (git worktree). Правлю
  только `tools/aid-style-migration/`. Всё остальное — чужие продукты: см.
  «Стыки» в корневом `CLAUDE.md`.
- Новую ветку — от свежего `origin/main`:
  `git fetch && git switch -c <ветка> origin/main`.
- Код Token Comparator (`tools/figma-token-comparator/`) можно читать как
  образец, но не импортировать из него и не править. Если нужен общий
  модуль — это вопрос к Principal Designer, а не тихая зависимость.

## Задача

Есть файл макетов с плохой системой стилей и компонентов: он не тянет ни
одну из наших библиотек. Плагин переводит такие макеты на токены и
компоненты выбранного продукта (Driver, Rider или будущего) так, чтобы
**структура макетов не менялась**, а визуально они стали макетами этого
продукта. Чего в библиотеке продукта не хватает — плагин предлагает
добавить или изменить.

Для кого — дизайнеры команды, как у Token Comparator.

Как работает, по шагам:

1. **Область** — выделение, страница или набор страниц (выпадающий список с
   чекбоксами).
2. **Сборка** — макеты разбросаны по страницам и канвасам; плагин собирает
   их, дублирует на отдельную страницу и аккуратно расставляет парами
   «было → стало». Исходные макеты не трогаются.
3. **Образцы** — пользователь выбирает целевые библиотеки и, отдельно,
   файлы образцовых макетов: как в них выглядят и какие токены и компоненты
   используют для каких ролей. Выбор — через плагин, по образцу выбора
   библиотек в Token Comparator; доступ — и через PAT + REST API, и через
   индексацию открытого файла.
4. **Перевод** — сырые значения и чужие стили/переменные → токены продукта;
   чужие инстансы, локальные компоненты и ручные фреймы → компоненты
   продукта.
5. **Ревью** — «было → стало» рядом, визуально и текстом: что переехало
   хорошо, что спорно, что нужно добавить или изменить в библиотеке.

Плагин не привязан к продукту: библиотеки и образцы выбирает пользователь.
Решения и план — `docs/audit-2026-09-29.md`.

### Готово, когда

На реальном файле экран переведён: старых стилей, переменных и компонентов
не осталось, вёрстка не поехала, есть ревью «было → стало» со статусами и
список предложений в библиотеку.

## Решения, которые действуют всегда

- **Без сервера** — всё локально, как у Token Comparator до бэкенда.
  Появится сервер — это новый контур, см. «Когда появится код».
- **Профиль маппинга** хранится в плагине (`clientStorage`) с экспортом и
  импортом JSON. Общий реестр профилей — позже.
- **Код Token Comparator не импортируется** — нужное копируется сюда и
  развивается независимо. Общий пакет — после готовности обоих плагинов,
  решение Principal Designer.
- **Визуальный стиль интерфейса — общий с Token Comparator**, интерфейс
  компактный. Плагины одной компании, но функционально не связаны.
- **Продукт — это данные, а не код.** Один запуск — один целевой продукт.
  Всё продуктовое (библиотеки, образцы, коллекция темы и её режимы) — в
  профиле продукта; имён продуктов и режимов (`Day`, `Night`, `Light`…) в
  `src/` нет. Новый продукт подключается профилем, без правки кода.
- **Тёмная тема обязательна**, даже если в исходнике её нет: «Стало»
  показывается во всех режимах темы продукта. Колонка тёмного режима —
  производная от светлой, руками не правится.
- **Предложения в библиотеку** — отдельная страница в том же файле;
  оформление — токенами целевого продукта, без захардкоженных цветов.
- **AI в плагине нет.** Ядро детерминированное; подсказки от модели —
  возможность на будущее.
- **Наработки Figma Agent** (скилл wb-aid-core/rules/steps) — референс и
  идеи, не источник правды. Разбор — в `docs/audit-2026-09-29.md`.

## Когда появится код

- Проверки перед тем, как считать работу готовой, — записать сюда
  командами, как у Token Comparator (`typecheck`, `test`, `build`).
- С первым кодом — добавить задачу в `.github/workflows/checks.yml`. Это
  общий файл: правка через Principal Designer.
- Если понадобится сервер — это новый деплой-контур и новый Vercel-проект.
  Сначала описать его в корневом `CLAUDE.md` («Два контура репозитория»),
  потом заводить.

## Релизы

- Тег — со своим префиксом, чтобы не пересекаться с Token Comparator:
  `style-migration-vX.Y.Z`.
- Релиз публикуется **без** метки Latest: она держит кнопку скачивания
  Token Comparator в Presentbook (стык в корневом `CLAUDE.md`).
- Кнопка скачивания этого плагина в Presentbook — задача чата Presentbook.
- Выпуск — только по явной команде Principal Designer.

## Секреты

`.env`, `.env.local` и значения ключей не читать, не печатать, не
коммитить; в сборку и архив релиза они попадать не должны.
