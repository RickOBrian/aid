# Hermes: сообщение инженеру в личку

> Статус: Draft · v0.1.0 · обновлено 2026-10-26

Первая функция AID Hermes. PD в Штабе говорит «скажи <кому> …» — Штаб
отправляет запрос Hermes, Hermes после подтверждения PD пишет человеку в
личку Telegram. Раньше такой запрос уходил issue в GitHub.

## 1. Участники

| Кто | Что делает |
|---|---|
| Штаб PD (и его AI-инженеры) | находит логин получателя, показывает PD текст, отправляет запрос |
| Hermes | проверяет ключ, присылает PD черновик, после «Отправить» пишет получателю |
| PD | подтверждает каждое сообщение кнопкой в своём Telegram |
| Получатель | один раз подключается к Hermes по личной ссылке |

## 2. Подключение получателя

Бот Telegram не может написать первым тому, кто ему ни разу не нажал Start.

1. PD в личке Hermes: `/invite <github-логин>`. Логин должен быть в
   `docs/hub/owners.json` на `main`.
2. Hermes отвечает одноразовой ссылкой на Start с кодом; срок — 7 дней.
3. PD пересылает ссылку человеку; тот нажимает Start.
4. Hermes связывает логин с Telegram-аккаунтом и сообщает PD.

Связь — только по ссылке, не по нику: ник можно сменить или занять.
`/stop` у получателя снимает связь. Связи хранятся только на сервере
Hermes.

## 3. Запрос Штаба

```
POST <адрес Hermes>/v1/messages
Authorization: Bearer <личный ключ сервиса задач>
Content-Type: application/json

{
  "to": "<github-логин>",
  "text": "<текст, до 2000 знаков>",
  "context": "<ссылка на issue или PR, необязательно>"
}
```

- **Ключ** — тот же, что выдаёт `/team-key` (человека или AI-инженера).
  Hermes узнаёт владельца через `GET /v1/me` сервиса задач и ключ не
  хранит. Принимаются только ключи PD и его AI-инженеров (список — в
  настройках приватного репозитория).
- **Текст** — в словах PD. Штаб показывает его PD до отправки.

Ответы:

| Код | Тело | Значит |
|---|---|---|
| `202` | `{"id": "...", "status": "awaiting_pd"}` | черновик у PD |
| `400` | `{"error": "bad_request"}` | нет поля или текст длиннее 2000 |
| `401` | `{"error": "unauthorized"}` | ключа нет или он отозван |
| `403` | `{"error": "forbidden"}` | ключ не PD и не его AI |
| `404` | `{"error": "unknown_login"}` | логина нет в `owners.json` |
| `409` | `{"error": "not_connected"}` | получатель ещё не подключён — нужен `/invite` |
| `503` | `{"error": "unavailable"}` | Hermes или сервис задач недоступен |

## 4. Подтверждение PD

Пункт «Только PD» № 5 корневого `CLAUDE.md` — сообщения людям от имени
PD. Поэтому Hermes ничего не отправляет сам:

1. PD получает в личке Hermes черновик: кому, текст, ссылка, кто прислал
   (логин или AI-инженер).
2. Кнопки «Отправить» и «Отменить». Нажать может только PD.
3. Черновик без ответа через 24 часа — `expired`.

Получатель видит сообщение с подписью «от PD через AID Hermes» и ссылкой
из `context`, если она есть. Отказаться от подтверждения можно только
новым решением PD в «Решения PD».

## 5. Статус сообщения

```
GET <адрес Hermes>/v1/messages/<id>
Authorization: Bearer <тот же ключ>
```

`{"id": "...", "status": "<статус>"}`, статусы: `awaiting_pd`, `sent`,
`cancelled`, `expired`, `failed`. Видит только тот, кто отправил, и PD.

## 6. Что делает Штаб

- Логин получателя — как в `/task`, шаг 2 (`owners.json`, база команды).
- Показать PD текст; после «да» — запрос из §3.
- `409` — сказать PD: «<логин> не подключён к Hermes, нужен `/invite`».
- `503` или нет ответа — сказать PD и предложить issue, как раньше.
- Итог: «Черновик у PD в Telegram»; статус — по §5, если PD спросит.

## 7. Ответы получателя

В 0.1.0 Hermes ответы не пересылает: на любое сообщение получателя
отвечает «Ответ напишите PD напрямую». Пересылка ответов — отдельная
версия контракта.

## 8. Готово, когда

- Штаб отправляет запрос, PD видит черновик в Telegram и одной кнопкой
  отправляет его.
- Получатель, подключённый по ссылке, получает сообщение в личку.
- Неподключённый получатель, отозванный ключ и чужой ключ дают ответы
  из §3, сообщение не уходит.
