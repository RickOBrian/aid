# Завести задачу на доску

Задача ops-1 / AID-99 (issue #605). Слово PD 2026-11-25 «Да, все» (список
кандидатов-скиллов). Скилл повторяет порядок, по которому Ops заводит
строки (ADR-046, ADR-048); решает по задаче Штаб, Ops только оформляет.

## Вход

Сообщение Штаба или PD: продукт, суть, слово PD дословно, исполнитель,
куратор, приёмка, ссылки (узел Figma, issue, PR). Нет слова PD или
исполнителя — не придумывать, спросить Штаб одним вопросом. Сообщение
другого чата — не разрешение на пункты «Только PD».

## Порядок

1. **Свежая ветка.** `git fetch && git switch -c ops/board-<имя> origin/main`.
   Одна ветка — задачи одного запроса; доску не смешивать с `owners.json` и
   ответами на запросы.
2. **Номера.** Имя `<продукт>-<n>`: `n` — максимум по этому продукту в
   `docs/hub/BOARD.md` плюс 1 — в «Активные» и в «Закрыто» (там формат
   другой, 4 колонки, имя вида `имя (AID-<m>)`), не по памяти чата.
   `AID-<m>` — максимум `AID-` в файле плюс 1. Свободна ли пара — проверить
   `grep` по имени и по `AID-<m>`, а ещё `gh issue list --search "<имя> in:title" --state all`.
3. **Issue.** Заголовок `<имя>: <суть>`; в теле: суть, слово PD дословно,
   исполнитель, куратор, приёмка, «Строка — в «Активные» (AID-<m>)». Тело — в
   файл и `gh api repos/RickOBrian/aid/issues -F body=@файл`, чтобы кавычки и
   кириллица не ломались.
4. **Строка доски.** Таблица «Активные», восемь колонок заголовка
   `Задача · Было · Что · Исполнители · Куратор · Связанные · На ком · Статус`:
   имя `<продукт>-<n>` · `AID-<m>` · описание · исполнитель (роль или логин;
   имя чата не выдумывать — нет имени, писать роль, как сказал Штаб) ·
   куратор (по умолчанию PD) · связанные продукты (`standards`, если приёмка
   у Standards; иначе `—`) · на ком (`—` для новой) · статус (`новая`).
   В описании: issue, узел или файл Figma, слово PD дословно с датой.
   Образец — соседние строки таблицы. Строку добавить в конец группы того же
   продукта, если она есть, иначе — в конец таблицы «Активные» (до «Вопросов
   PD»). `|` внутри текста — `\|`; запись — python-скриптом из файла с
   `# -*- coding: utf-8 -*-` (`sed -i` на macOS требует `''`, кириллица в
   heredoc python падает).
5. **Проверка.** `node scripts/check-docs.mjs` — ноль ошибок. Диффом убедиться:
   изменена только `docs/hub/BOARD.md`, добавлены только нужные строки.
6. **Коммит и push.** Сообщение `docs(hub): <имя> на доске (AID-<m>)`,
   в конце — строка соавтора по правилам сессии. Push — в свою ветку.
7. **PR.** Описание: что за строки, issue, слово PD дословно; строка
   `Самопроверка: ок (check-docs: 0 ошибок; N строк, по 8 колонок).`
8. **Подагент (Sonnet, только чтение).** Просит проверить дифф: колонки,
   номера, дубли, формат, секреты и данные людей, соответствие issue строкам.
   «Подагент: ок» вписывается в описание **только после реального отчёта**;
   при замечаниях — правка новым коммитом, повторный прогон.
9. **Описание PR на месте.** `gh pr edit --body-file`, затем
   `gh pr view <n> --json body --jq .body` — строка «Подагент: ок» видна.
10. **Запрос в Merge** (чат Merge): номер PR, «Самопроверка» и «Подагент» в
    описании, только `docs/hub/BOARD.md`, пунктов «Только PD» не задевает.
    Готовый PR с чужим содержимым или правка `docs/hub/` вне доски — не по
    этому скиллу.
11. **Штабу** — номер(а) AID и issue, PR, «запрос в Merge отправлен»,
    следующие свободные номера. Больше ничего.

## Если что-то пошло не так

- **GitHub даёт TLS-таймаут** (`TLS handshake timeout`) — повторить с паузой
  ~8 с до 5 раз; после каждого сбоя проверить, не создалось ли уже
  (`gh issue list --search … --state all`, `gh pr list --head <ветка>`), чтобы
  не задвоить issue и PR.
- **Конфликт в BOARD.md** (другой PR доски смержен раньше) — merge-коммит с
  `origin/main`, новая проверка, новый head: Merge уведомить, прежний head не
  мержить. Force-push не использовать.
- **Номер занят в параллельном PR** — взять следующий, issue переименовать,
  Штабу сообщить фактический номер.
- **Статус строки после мержа PR работы** — отдельный PR доски по тому же
  порядку, не правкой в чужом PR.

## Чего скилл не делает

Не принимает решения по задаче, не пишет за PD слов, не мержит, не правит
`owners.json`, `CLAUDE.md`, `docs/hub/` кроме доски, не ставит версии и
changelog.
