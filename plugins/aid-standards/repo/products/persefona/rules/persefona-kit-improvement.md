# Улучшение визуального языка Persefona

> Статус: Alpha · v1.0.0 · обновлено 2026-10-26

---

## 1. Назначение

Persefona — UI Kit самого AID (`products/persefona/product.json`). Kit
не только оборачивает существующие стили Presentbook, но и улучшает UI
и визуальный язык, как это сделал бы арт-директор (решение PD
2026-10-23, `docs/hub/BOARD.md` «Решения PD», строка «Persefona — Kit
улучшает визуальный язык»).

Этот документ задаёт порядок такого улучшения: кто предлагает, в какой
форме, кто принимает и что подтверждают PD или arturuxui. Сами значения токенов и вид
компонентов здесь не описываются — они живут в библиотеке Figma
Persefona и в правилах вида в этой папке.

Действует для всех чатов, которые меняют Kit: Designer · Persefona
(пишет в библиотеку), Designer · Persefona · <задача> (только заявкой
Designer · Persefona), Developer · Persefona (код портала), — и для
Claude Code arturuxui, который получает эти правила плагином
`aid-standards`.

## 3. Форма предложения

Улучшение приходит **пачкой по одной теме** (цвет, типографика, отступы
и радиусы, тени, конкретный блок), а не правками вразнобой. Пачка — PR
Designer · Persefona или раздел в его открытом PR по Kit.

Каждый пункт пачки — строка таблицы:

| Поле     | Что пишется                                                                 |
|----------|------------------------------------------------------------------------------|
| Было     | Текущее значение или вид: токен, HEX, размер, скриншот/узел Figma            |
| Стало    | Предлагаемое значение или вид, имя токена по `naming-conventions`             |
| Почему   | Что улучшается для читателя страницы: иерархия, читаемость, ритм, единство   |
| Контраст | Для цвета текста и иконок — отношение к фону и уровень (AA минимум)          |
| Затронет | Какие токены, стили, блоки и поверхности (Figma, портал, гайды, плагины)     |

Пункт без «почему» не рассматривается: вкус без аргумента — не довод.
Пункт, который меняет токен или стиль, сопровождается ответами анкеты
`token-change-gate` (артефакт, тип изменения) — одной анкетой на пачку.

---

## 4. Приёмка

Пачку принимает Standards · Persefona. Решение — комментарием в PR, по
каждому пункту одно из трёх:

1. **Принято** — Designer собирает в библиотеке Figma.
2. **Принято с правкой** — правка названа в комментарии, после неё
   пункт проверяется ещё раз.
3. **Подтверждение стороны** — пункт задевает §5; Standards · Persefona
   формулирует вопрос с вариантами и своей рекомендацией и передаёт
   тому, с чьей стороны правка (§5): PD — через Штаб, arturuxui — в его
   канале. До ответа пункт не собирается.

Отклонённый пункт закрывается с причиной; повторно — только с новым
аргументом.

После сборки Standards · Persefona сверяет библиотеку с принятым
(значения, привязки переменных, отсутствие литералов) — без этой
сверки пачка не считается закрытой.

---

## 5. Что подтверждают PD или arturuxui

Права на стандарты Persefona у PD и arturuxui равные (решение PD
2026-10-26, `docs/hub/BOARD.md` «Решения PD», строка «Стандарты
Persefona — общие для PD и arturuxui»). Правку подтверждает тот, с
чьей стороны она пришла:

- правка со стороны PD (Designer · Persefona и чаты PD) — «да» PD;
- правка со стороны arturuxui (его Claude Code) — «да» arturuxui;
  PD её не согласует.

Подтверждение нужно, даже если улучшение очевидно, для пунктов, которые
меняют прежние решения по Persefona:

- акцент — графит; цветной акцент для бейджей — `#6A1FD0` и производные
  (палитра iolite), хром портала при этом не меняется;
- шрифт;
- светлая тема;
- хром портала — менять его может только задача Developer · Persefona,
  поставленная через Ops.

Подтверждение одной стороны — не согласование с другой. Приёмка
Standards · Persefona (§4, соответствие общим стандартам AID) — для
правок обеих сторон одинаково и подтверждением не заменяется.

Отход от общих стандартов AID (именование, уровни токенов, доступность)
— не вопрос вкуса и не решается ни приёмкой Persefona, ни
подтверждением стороны: записью исключения через Standards
(`conformance-levels`).

## 6. До и после первой публикации

По `semver-guide` первая версия любого артефакта — `1.0.0`. До первой
публикации библиотеки Persefona (`release-gate`) токены, стили и блоки —
черновик: значения и имена меняются свободно, версия не ставится,
changelog не ведётся. Тип изменения в анкете указывается всё равно —
из него собирается первая запись changelog.

После публикации действует общий порядок: переименование и удаление —
MAJOR, его публикуют только люди; minor и patch AI-инженер публикует
через `release-gate` по задаче с разрешением PD или куратора-человека
(решение PD 2026-10-22, корневой `CLAUDE.md` «Только PD», п. 4).

---

## 7. Код портала

Улучшение, принятое в Kit, не переносится в `pages/aid-portal/` чатом
дизайнера. Перенос — задача Developer · Persefona через Ops, с
переменными `--pf-…`. До перевода портала на переменные расхождение
Figma и портала — ожидаемое состояние, а не ошибка.

---

## 8. Проверка

Перед приёмкой пачки:

- [ ] пачка по одной теме, у каждого пункта есть «было / стало / почему»;
- [ ] анкета `token-change-gate` заполнена, тип изменения назван;
- [ ] имена — по `naming-conventions`, новых уровней токенов нет;
- [ ] контраст каждой пары «текст / фон» — AA или выше;
- [ ] ни один пункт не меняет решения из §5 без «да» своей стороны
      (PD или arturuxui);
- [ ] новый компонент прошёл `component-gate`;
- [ ] изменения кода портала вынесены в задачу Developer · Persefona.
