# open-chat — чат Designer или Developer под задачу

Работает в чате «AID · Hub · Штаб». Протокол — `docs/hub/ORCHESTRATION.md`
§1a «Имена и типы» и §6 «Новый чат»; карточки ролей —
`docs/hub/agents/designer.md`, `docs/hub/agents/developer.md`. Отвечать
по-русски.

## 1. Проверить, что чат можно открыть

- Задача есть на доске (`git show origin/main:docs/hub/BOARD.md`,
  «Активные») с номером `AID-<n>` и подтверждена PD или Штабом
  (§4 «Что считается разрешением»). Номера нет — сначала Ops, чат не
  открывать.
- Есть issue задачи (`gh issue view <n> --repo RickOBrian/aid`). Нет —
  завести или попросить Ops; ссылка на issue — обязательная строка брифа.
- Такого чата ещё нет: `list_sessions` → нет сессии с тем же `AID-<n>`.
  Есть — писать ей, второй не открывать.

## 2. Имя и папка

| Что за задача | Имя чата | Папка (`~/Projects/…`) |
|---|---|---|
| Сборка или аудит одного компонента AID | `Designer · 💠 <Компонент> · AID-<n>` | `aid-designer`, свой worktree |
| Иконки, иллюстрации | `Designer · 🖼 <Объект> · AID-<n>` | `aid-designer`, свой worktree |
| Токены, стили | `Designer · 🎨 <Объект> · AID-<n>` | `aid-designer`, свой worktree |
| Дизайн-задача продукта | `Designer · <Продукт> · AID-<n>` | папка продукта — таблица `developer.md` |
| Применение Kit Persefona в продукте | `Designer · Persefona · AID-<n>` | папка продукта — таблица `developer.md` |
| Код продукта | `Developer · <Продукт> · AID-<n>` | папка продукта — таблица `developer.md` |

- Имя компонента — как в Figma и на доске. Пока имени нет — узел Figma
  (`Designer · 💠 349:4025 · AID-75`), после определения имени —
  `set_session_title`.
- Папку брать из таблицы карточки на `origin/main`, не по памяти: продукт
  не в таблице — вопрос Штабу (себе) и строка на доске, чат не открывать.

## 3. Открыть

`start_session`:

- `cwd` — папка из п.2; **свой worktree** (`use_worktree: true`), ветка от
  свежего `origin/main`. Ручной `git worktree add` не нужен.
- `context: "fresh"` — бриф ниже самодостаточен.
- Модель — Opus (§12 «Модели по чатам»); усилие — `set_session_effort`
  после открытия.
- Группа сайдбара — «AID».
- Чат `Designer · 💠 / 🖼 / 🎨` сразу отвязать (`detach_session`, §6
  «Отвязка»); Developer и прочие под задачу — остаются привязанными.

## 4. Бриф — первое сообщение

Заполнить все строки; строка, которой нет, — «нет» с причиной, не
пропускать.

```
Задача AID-<n>: <что сделать, 1–2 строки своими словами>
Issue: https://github.com/RickOBrian/aid/issues/<n>
Карточка роли: docs/hub/agents/<designer|developer>.md — прочитать первой.
Вход в контекст продукта: <файл из таблицы developer.md | products/<id>/product.json>
Ветка: своя, от свежего origin/main (worktree уже создан). Rebase не использовать — только merge.
Вход PD / материалы: <ссылка Figma с узлом | цитата PD дословно с датой | «нет»>
Решения PD по задаче: docs/hub/BOARD.md «Решения PD» — строки от <дата>.
<только для Designer компонентов:>
Страницы аудита и сборки: products/persefona/rules/persefona-figma-pages.md
  (👀 <Компонент> · audit → 🚧 <Компонент> · construction, аудит переезжает секцией).
Протокол: skills/_shared/protocols/figma-library-workflow.md (§3.1 аудит, §3.8 сборка);
  перед приёмкой — скилл ds-component-check подагентом.
Приёмка аудита и сборки: Standards — запрос напрямую.
Логика сценария: Product Logic — был ли похожий.
<конец блока Designer>
Готово = <PR смержен | аудит/сборка приняты Standards | файл Figma по задаче>.
Мерж: свой PR в своей зоне — сам по «Git-полномочиям»; общее и заблокированное — чат Merge, запрос напрямую.
Вопросы PD — в этом чате напрямую; Штабу — только блокер одной строкой.
Состояние между заходами — CLAUDE.local.md папки (скилл /save-state), контекст > 150 тыс. — перезапуск.
После мержа или приёмки: итог — в PR / на доске, затем archive_session("self").
```

- Для Standards, Product Logic и Merge вписать их id `local_…` из
  `list_sessions` в момент открытия: в скилле id нет, чаты меняются.
- В бриф — только факты задачи и ссылки; правила не пересказывать, они в
  карточке и гайдах.
- Цитата PD — дословно, с датой и местом, где дана.

## 5. После открытия

- Строка на доске в «Активные» (исполнитель — имя чата) — через Ops или
  своим PR доски (мержит Merge).
- Чату Штаб больше не пишет, пока тот не пришлёт блокер или итог.

## Запреты

- Не открывать чат без номера задачи и без issue.
- Не открывать в общей папке постоянного чата (`aid-designer`,
  `aid-persefona`) без своего worktree.
- Публичный репозиторий: в брифе, который попадёт в PR или issue, — роли,
  не имена людей; секретов и ключей не писать.
