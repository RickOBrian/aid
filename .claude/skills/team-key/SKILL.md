# team-key — личный ключ сервиса задач

Решение — ADR-046, `docs/hub/ORCHESTRATION.md` §10 «Ключи»; устройство —
`tools/aid-team/SERVICE.md`. Отвечать по-русски.

Ключ нужен, чтобы писать в сервис задач: ставить и менять задачи. Читать
задачи можно без ключа. Каждый получает ключ сам — без PD и без
передачи файлов.

## Получить

1. Обновить рабочую копию: `git pull` (или `git fetch` и сверка с
   `origin/main`) — скрипт лежит в репозитории.
2. Запустить в терминале:
   ```bash
   python3 tools/aid-team/bin/team-key
   ```
3. Скрипт выведет ссылку `https://github.com/login/device` и код из 8
   символов. Передать их человеку дословно: открыть ссылку, ввести код,
   подтвердить приложение «AID Team». Приложение не получает доступа к
   репозиториям — только узнаёт GitHub-логин.
4. Дождаться строки «Готово: ключ для @<логин> сохранён». Ключ лежит в
   связке ключей macOS (на Linux — `~/.config/aidteam/team-key`, 0600).

Сервис отказывает, если логина нет в `docs/hub/owners.json`: ключ выдаётся
только людям команды. Тогда — сказать человеку, что его должен добавить
PD.

## Проверить

```bash
python3 tools/aid-team/bin/team-key --check
```

## Отозвать

Ключ утёк, машина больше не используется, человек уходит:

```bash
python3 tools/aid-team/bin/team-key --revoke
```

Ключ другой машины отзывается с той машины. Если доступа к ней нет —
сказать PD: Team отзовёт ключ по логину.

## Запросы с ключом

Скиллы `/task`, `/delegate`, `/team` и любые запросы к сервису —
через `python3 tools/aid-team/bin/team-api <METHOD> <путь> ['<json>']`:
ключ подставляется сам и не попадает в аргументы и вывод.

## Не делать

- Не выводить ключ и не читать его из связки ключей в чат:
  `security find-generic-password … -w` — только внутри скриптов.
- Не передавать ключ другому человеку и не копировать между машинами —
  на каждой машине свой `/team-key`.
- Не запускать `curl` с ключом в аргументах — только `team-api`.
