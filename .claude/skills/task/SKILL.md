# task — задача от менеджера на PD

Работает в Штабе менеджера. Протокол — `docs/hub/ORCHESTRATION.md` §9,
роль — `tools/aid-team/MANAGER.md`. Отвечать по-русски.

Менеджер ставит задачи **только на PD**. PD решает: делает сам или
передаёт инженеру (`/delegate`). Задачу напрямую инженеру не ставить —
даже если менеджер назвал исполнителя: записать его как пожелание.

## 1. Собрать задачу

Из слов менеджера заполнить поля. Чего не хватает — один вопрос со всеми
пробелами сразу, не по одному.

| Поле | Обязательно | Пример |
|---|---|---|
| Что нужно | да | «Кнопка скачивания плагина показывает версию» |
| Зачем | да | «Дизайнеры не понимают, обновились ли» |
| Готово, когда | да | «На aidteam.pro видна версия последнего релиза» |
| Срок | нет | дата или «не горит» |
| Приоритет | да | `высокий` · `обычный` · `низкий` |
| Продукт | нет | метка `to:<продукт>` из `docs/hub/owners.json` |
| Пожелание по исполнителю | нет | GitHub-логин, если менеджер назвал человека |
| Контекст | нет | ссылки на PR, issues, файлы |

Человека менеджер может назвать по имени — найти логин по базе
(`tools/aid-team/READER.md`): скачать `people.json` во временный файл,
найти по имени, фамилии, Telegram или логину, удалить файл. Несколько
совпадений — спросить. В issue писать **только логин**, не имя.

## 2. Проверить перед созданием

- Репозиторий публичный: в тексте нет имён, Telegram, e-mail, секретов,
  внутренних данных продуктов. Есть — убрать и сказать менеджеру.
- Нет ли уже такой открытой задачи:
  `gh issue list --repo RickOBrian/aid --state open --search "[TASK] in:title <ключевые слова>"`.
  Нашлась — показать и спросить: дополнить её или создать новую.

## 3. Показать и создать

Показать менеджеру готовый текст. После «да»:

```bash
gh issue create --repo RickOBrian/aid \
  --title "[TASK] <что нужно, коротко>" \
  --body-file <временный файл>
```

Меток и исполнителя не ставить: в репозитории их может ставить только
collaborator, а менеджер им не является — `gh` откажет. Задачу находит
`/plan` PD по заголовку `[TASK]` и автору из `owners.json` и сам ставит
метки `hub`, `to:hub`, `task` при приёме.

Тело:

```
**От:** Штаб менеджера
**Приоритет:** <высокий | обычный | низкий>
**Срок:** <дата | не горит>

**Что нужно:** …
**Зачем:** …
**Готово, когда:** …

**Продукт:** <to:… | не указан>
**Пожелание по исполнителю:** <@логин | нет>
**Контекст:** …

<!-- PD: сделать самому или /delegate. Решение — комментарием дословно. -->
```

Удалить временный файл после создания.

## 4. Итог менеджеру

Ссылка на issue и одна строка: «Ушло PD, увидит в /plan; статус — в
/team». Ничего больше не обещать: решение за PD.

## Не делать

- Не ставить метку `for:<логин>` — это делегирование, только PD.
- Не ставить `decision:pd` — системный уровень решает PD сам.
- Не писать в issue имена и контакты из базы.
