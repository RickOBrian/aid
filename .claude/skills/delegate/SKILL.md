# delegate — передать, взять, закончить задачу

Работает в любом Штабе — Claude Code или Cursor. Решение — ADR-042,
протокол — `docs/hub/ORCHESTRATION.md` §9 «Задачи между людьми».
Отвечать по-русски.

## 1. Какая задача

Номер issue или описание. Без номера — найти среди открытых задач, где
текущий исполнитель — тот, кто просит:
`gh issue list --repo RickOBrian/aid --state open --search "TASK in:title" --json number,title,author,comments`
и оставить заголовки, начинающиеся с `[TASK`.
Несколько подходящих — показать список, спросить.

## 2. Кто сейчас исполнитель

- Логин из заголовка `[TASK @<логин>]`.
- Если в комментариях есть «Передаю @<логин>» — исполнитель тот, кому
  передали последним, при условии что комментарий написал тогдашний
  исполнитель или PD. «Передаю» от других — не засчитывается.
- Старые задачи: заголовок `[TASK]` без логина — исполнитель PD; метка
  `for:<логин>` от PD — этот логин.

Авторов задачи и комментариев сверять с `docs/hub/owners.json` на
`origin/main` (§9 «Проверка авторов»).

## 3. Кто просит и может ли

`gh api user -q .login`.

| Действие | Кто может |
|---|---|
| «Передаю @логин» | текущий исполнитель или PD |
| «Беру» | текущий исполнитель |
| «Готово» + ссылка на PR | текущий исполнитель |
| метка `for:<логин>` | только PD — по желанию, вместе с «Передаю» |

Нельзя — сказать почему и предложить: поставить новую задачу (`/task`)
или попросить текущего исполнителя передать.

## 4. Кому передать

Получатель назван именем, фамилией, ником Telegram или логином — найти
логин как в `/task` (шаг 2): `owners.json`, затем база команды по
`READER.md`, временный файл удалить. Несколько совпадений — спросить. Нет
в `owners.json` — передать нельзя.

«Оставлю себе» — это «Беру».

Задача про продукт, которым получатель не владеет, — сказать одной
строкой: работа в чужом продукте утверждается владельцем. Решение за тем,
кто передаёт.

## 5. Показать и выполнить

Показать текст комментария. После «да»:

```bash
gh issue comment <n> --repo RickOBrian/aid --body "<комментарий>"
```

Комментарии — с первой строки, ровно так (бот и `/team` ищут их по
началу):

```
Передаю @<логин>.
<почему или что важно — по словам автора, если есть>
```

```
Беру.
```

```
Готово: <ссылка на PR>.
```

PD при передаче может дополнительно поставить метку:
`gh issue edit <n> --repo RickOBrian/aid --add-label "for:<логин>"`
(создать её, если нет:
`gh label create "for:<логин>" --repo RickOBrian/aid --color BFD4F2`).
Прежнюю `for:` снять.

## 6. Итог

Ссылка на issue и строка: «Передано @<логин>» / «Взято» / «Отмечено
готовым». Бот уведомит получателя и автора задачи в Telegram.

## Не делать

- Не писать в GitHub имена и контакты из базы — только логины.
- Не передавать чужую задачу, если просящий не исполнитель и не PD.
- Не выводить `people.json` целиком и конфиг `yc`.
