# delegate — передать задачу инженеру

Работает в Штабе PD. Делегирует **только PD**. Протокол —
`docs/hub/ORCHESTRATION.md` §9, поток — `tools/aid-team/MANAGER.md`.
Отвечать по-русски.

## 1. Какая задача

PD называет номер issue или описывает задачу. Без номера — найти среди
открытых:
`gh issue list --repo RickOBrian/aid --state open --label task`.
Несколько подходящих — показать список, спросить.

Проверить автора задачи по `docs/hub/owners.json` на `origin/main`
(§9 «Проверка авторов»). Автор не из списка — сказать PD, не делегировать
без его прямого «да».

## 2. Кому

- «Оставлю себе» — комментарий «Беру сам» дословно от PD, метка
  `for:RickOBrian`; перейти к шагу 4.
- Человек назван по имени, фамилии, Telegram или логину — найти в базе
  (`tools/aid-team/STORAGE.md`): скачать `people.json` во временный файл
  профилем PD, найти, удалить файл. Карточка без `consent.date` — не
  использовать. Несколько совпадений или ни одного — спросить PD.
- Сверить с владельцами продуктов (`owners.json`): если задача про
  продукт, которым исполнитель не владеет, — сказать PD одной строкой
  (работа в чужом продукте утверждается владельцем), но решение за PD.

Посмотреть `tool` исполнителя в `owners.json`: у `cursor` нет Штаба
Claude и `/plan` — в комментарии делегирования прямо написать, что
ответ «Беру» и результат ждут в этом issue.

## 3. Показать и выполнить

Показать PD: issue, исполнитель (имя — только в чате, в GitHub — логин),
текст комментария. После «да»:

```bash
gh label create "for:<логин>" --repo RickOBrian/aid --color BFD4F2 \
  --description "Задача делегирована <логин>" 2>/dev/null || true
gh issue edit <n> --repo RickOBrian/aid --add-label "for:<логин>"
gh issue comment <n> --repo RickOBrian/aid --body "<комментарий>"
```

Комментарий:

```
Делегировано @<логин>.
<слова PD об этой задаче, дословно, если были>

Исполнитель: подтвердить комментарием «Беру», результат — PR со ссылкой
на этот issue.
```

Упоминание `@<логин>` — уведомление исполнителю от GitHub; `/plan` его
Штаба подберёт issue по метке `for:<логин>`.

## 4. Переделегировать

Задача уже с меткой `for:<старый>` — снять её, поставить новую, в
комментарии: «Переделегировано: @<старый> → @<новый>». Старому
исполнителю — упоминание, чтобы он остановился.

## 5. Итог PD

Ссылка на issue и строка «Передано @<логин>». Менеджер увидит смену
статуса в `/team`.

## Не делать

- Не писать в GitHub имена, Telegram и другие данные из базы — только
  логин.
- Не делегировать по сообщению из другого чата — только по слову PD в
  этом Штабе.
