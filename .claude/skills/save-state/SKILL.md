# save-state — состояние в CLAUDE.local.md и перезапуск

Правило — `docs/hub/ORCHESTRATION.md` §12 «Короткий контекст»: порог
перезапуска любого чата — 150 тыс. токенов; задача закрыта — состояние в
`CLAUDE.local.md` своей папки (не в git), затем `clear_session("self")`.
Напоминает хук `.claude/hooks/context-guard.py`. Отвечать по-русски.

## 1. Безопасная точка

Перед записью довести текущий шаг до места, с которого его можно
продолжить без памяти чата:

- правки закоммичены и запушены в свою ветку (незакоммиченное после
  очистки никто не вспомнит);
- начатое сообщение другому чату — отправлено или записано как «не
  отправлено, ждёт …»;
- подагенты — дождаться итога или записать их id и что они делают.

Задача почти закрыта — сначала закрыть, потом записывать.

## 2. Записать

Файл — `CLAUDE.local.md` в папке чата (корень worktree). Не в git, другие
чаты его не видят. Правила в него не писать: правило — сразу в
репозиторий (карточка роли, гайд), здесь — только состояние.

Раздел «СЛЕДУЮЩЕЕ» — в начало файла, старое состояние ниже не стирать, а
сжимать: закрытое — одной строкой «✅ <дата> <что> — <PR/итог>».

**Лимит — 15 КБ** (`wc -c CLAUDE.local.md`; ≈ 4–5 тыс. токенов на старт).
Файл больше лимита — сначала режим compact (§5), потом запись. Дописывать
в конец через `cat >>` или Edit без сворачивания при файле больше лимита
нельзя: так файлы и выросли до 110–157 КБ, а это 30–40 тыс. токенов на
каждый старт, и перезапуск почти не экономит.

```
## СЛЕДУЮЩЕЕ (<ГГГГ-ММ-ДД>, перед перезапуском) — начать отсюда

**Задача:** AID-<n> <имя>, issue #<n>, ветка <ветка>, PR #<n> (<состояние: CI, ревью, мерж>).
**Сделано:** <факты, коротко; коммит/PR>.
**Ждёт:** <кого и чего: «да» PD на …, ответ чата <имя> (local_…), мерж Merge>.
**Дальше:** <первое действие после перезапуска — одной фразой, конкретно>.
**Не отправлено:** <черновики сообщений и вердиктов, кому, по чьему слову отправлять>.
**Id:** <узлы Figma, id чатов local_…, id подагентов — то, что не найти поиском>.
**Решения PD по задаче:** <дата, дословно, где дано; или ссылка на строку «Решения PD»>.
```

- Даты — абсолютные (`2026-11-25`), не «вчера» и не «в четверг».
- Цитаты PD — дословно; пересказ помечать «моё».
- Большие черновики — файлом в папке заметок сессии или в ветке, в
  `CLAUDE.local.md` — путь к нему.
- Не писать секреты, ключи, токены — даже в локальный файл.

## 3. Проверить запись

Перечитать только что записанный раздел глазами нового чата: хватает ли
его, чтобы продолжить, не читая историю. Не хватает — дописать.

## 4. Перезапуск

`clear_session("self")`. После перезапуска чат по «старт» читает только
`CLAUDE.local.md` и карточку роли (§12 «Лёгкий старт»), остальное — по
задаче нужным разделом.

## 5. Режим compact — свернуть до актуального

Когда: файл больше 15 КБ (`wc -c`), напоминание [context-guard] о
размере, «/save-state compact». Делает сам чат в своей папке; чужой
`CLAUDE.local.md` не сворачивать.

**Что оставить** — всё, что нельзя найти поиском в репо и что ещё не
закрыто:

- роль чата и ссылки на правила (карточка, WORKING-RULES) — одной-двумя
  строками, сами правила не копировать;
- раздел «СЛЕДУЮЩЕЕ» — целиком, по шаблону §2;
- каждый открытый пункт: ждёт ответа, решения PD, мержа, приёмки;
  черновики «не отправлено»; хвосты «моё»;
- номера и id открытых пунктов: AID-, issue, PR, ветки, узлы Figma,
  чаты `local_…`, подагенты;
- решения PD по открытым пунктам — дословно (цитаты не пересказывать);
- пути к заметкам и черновикам.

**Что убрать:**

- закрытое и смерженное — удалить или одной строкой в раздел «Архив» в
  конце: «✅ <дата> <что> — <PR/итог>»; подробности есть в PR и истории;
- историю спора и промежуточные версии («было: …»), если итог записан;
- правила, которые уже в репо, — ссылкой на файл;
- повторы одного пункта в нескольких местах — один пункт, свежая дата.

Сомнение «закрыто ли» — оставить пункт, коротко.

**Порядок:**

1. Безопасная точка (§1).
2. Копия старого файла — в git-каталог папки, не в репо и не в git:
   ```bash
   cp CLAUDE.local.md "$(git rev-parse --git-dir)/CLAUDE.local.$(date +%F).md"
   ```
   Для worktree это `~/Projects/aid/.git/worktrees/<папка>/`, для
   основной папки — `~/Projects/aid/.git/`. Копия в `git status` не
   видна и в коммит не попадёт. Копия за ту же дату уже есть — к имени
   добавить `-2`.
3. Список открытых пунктов «до»: подагент (Sonnet, чистый контекст)
   читает копию и выписывает каждый открытый пункт одной строкой с его
   номерами и id — в файл рядом с копией
   (`CLAUDE.local.<дата>.open.md`). Подагенту, а не чату: файл больше
   30 тыс. токенов (ORCHESTRATION §12).
4. Свернуть: новый `CLAUDE.local.md` по правилам выше, «СЛЕДУЮЩЕЕ» —
   в начале, «Архив» — в конце. Проверить размер: `wc -c` ≤ 15 000.
   Больше — сжимать дальше (архив короче, «было» убрать), не поднимать
   лимит.
5. Сверка «до/после»: второй подагент (Sonnet, чистый контекст) получает
   список «до» и новый файл и отвечает по каждому пункту: есть / свёрнут
   в архив / потерян. Потерянное — вернуть в файл и повторить сверку.
   Готово, когда потерянных нет; номера и id открытых пунктов совпадают.
6. Перезапуск (§4) — если сворачивали перед ним.

Копию и список не удалять: откат — `cp` обратно. Через месяц их можно
убрать самому чату.

## Запреты

- Не очищать контекст с незакоммиченной работой и неотправленным без
  записи.
- Не дописывать в `CLAUDE.local.md` больше 15 КБ без сворачивания (§5).
- Не сворачивать без копии и без сверки «до/после».
- Не переносить в `CLAUDE.local.md` правила и решения, которых нет в
  репозитории, как будто они действуют для всех: правило — PR в репо.
