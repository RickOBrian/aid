# Знание о продукте Driver

Что знает о продукте наша команда (и плагин AID Style Migration): как
устроены токены и компоненты, по какой логике строится каждый элемент и
как узнать ошибку дизайнера. Эталон — **библиотека** (компоненты и
токены) и **стандарты ДС**; макеты сравниваются с эталоном, а не друг с
другом.

Решение Principal Designer (2026-09-30): источник истины продукта —
Presentbook; знание о продукте — его содержание. Раскладка:

| Где | Что |
|---|---|
| `products/driver/knowledge/` (здесь) | данные знания о продукте в репозитории: выгрузки из Figma, анатомия компонентов, логика построения, находки. Версионируются в Git |
| `pages/aid-portal` (Presentbook) | показ знания о продукте людям. Подключение — отдельным шагом вместе с миграцией токенов в Presentbook |
| `tools/aid-style-migration` | плагин читает знание о продукте как материал продукта; скрипты выгрузки — `scripts/knowledge/`, аудит — `scripts/audit/` |

Для другого продукта — тот же набор в `products/<id>/knowledge/`.

## Состав

- `sources.json` — файлы Figma, откуда выгружено.
- `tokens/color-sem.tsv` — все 131 цветовых токена: имя | day | night | области применения | описание.
- `components/*.anatomy.txt` — эталон компонентов: каждая часть и её токен по вариантам.
- `logic.md` — логика построения, выведенная из эталона, сверка со стандартом, находки для библиотеки.

## Как обновить

1. Токены: `use_figma` в файле токенов — переменные коллекции `color-sem` (см. историю в `logic.md`).
2. Компоненты: `tools/aid-style-migration/scripts/knowledge/anatomy.js`, заменить `__PAGE__` на id страницы библиотеки.
3. Только чтение; в файлы Figma ничего не пишем.

Статус: v0 (2026-09-30) — токены, анатомия 12 из 14 страниц (без карт: Pins, Layers), логика построения. Дальше — макеты против эталона.
