# Аудит rider-1 — как прогнать экран

Формат утвердил PD 2026-10-18 на пробе «Navigation · Taxi». Страница аудита в
копии `bL4jeQWMvn3GKVNRPnmJMj`: «🔍 Аудит · Navigation» (`5011:3071`), секция пробы `5014:7732`.

Исходные экраны не трогаем — работаем с клонами на странице аудита.

На каждый экран (ряд в секции):

1. Три клона экрана: «было», «стало», «стало · натянутость».
2. На «стало» — замены по `swap-map.json` и токены Rider на слоях вне
   инстансов (точное совпадение — молча, неточное — находка «пара значений»).
3. Снимки «было» и «стало» (`get_screenshot`, `contentsOnly`), затем
   `python3 tools/diff.py before.png after.png 24 4 3` → рамки. Запускать с
   user site-packages (PIL) из папки tools, а не из папки снимков.
4. Рамки сдвигов (красные, с номерами) — отдельный слой поверх «стало».
5. Подсветка на третьем клоне: красное — чужой компонент, чужой токен или
   значение без токена; серое — Map, скриншоты-подложки (F). Map Pin — не F.
6. Находки — карточки справа и запись в `../navigation.json`.

Порог 24 из 255: T=8 ловит сглаживание, T=48 теряет мелкие кнопки. Тени и
цвета, отличающиеся меньше порога, ловит сверка значения с токеном.

Ограничения `use_figma`: ответ ≤ 20 КБ, один файл за вызов, одна смена
страницы за вызов.
