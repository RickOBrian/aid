# Аудит rider-1 — как прогнать экран

Формат утвердил PD 2026-10-18 на пробе «Navigation · Taxi». Страница аудита в
копии `bL4jeQWMvn3GKVNRPnmJMj`: «🔍 Аудит · Navigation» (`5011:3071`), секция пробы `5014:7732`.

Исходные экраны не трогаем — работаем с клонами на странице аудита.

На каждый экран (ряд в секции):

1. Три клона экрана: «было», «стало», «стало · натянутость».
2. На «стало» — замены по `swap-map.json` и токены Rider на слоях вне
   инстансов (точное совпадение — молча, неточное — находка «пара значений»).
3. Снимки «было» и «стало» (`get_screenshot`, `contentsOnly`), затем
   `python3 tools/diff.py before.png after.png 24 4 3` → рамки. Запускать с
   user site-packages (PIL) из папки tools, а не из папки снимков.
4. Рамки сдвигов (красные, с номерами) — отдельный слой поверх «стало».
5. Подсветка на третьем клоне: красное — чужой компонент, чужой токен или
   значение без токена; серое — Map, скриншоты-подложки (F). Map Pin — не F.
6. Находки — карточки справа и запись в `../navigation.json`.

Порог 24 из 255: T=8 ловит сглаживание, T=48 теряет мелкие кнопки. Тени и
цвета, отличающиеся меньше порога, ловит сверка значения с токеном.

Ограничения `use_figma`: ответ ≤ 20 КБ, один файл за вызов, одна смена
страницы за вызов.

## Чекпоинты

Аудит идёт шагами: шаг (сейчас — секция страницы) → чекпоинт → решения →
следующий шаг. Порядок согласован с PD 2026-10-18.

- **Чекпоинт** — список открытых пунктов шага: находки, пропущенные замены,
  вопросы анкеты. Разбираем с PD в чате, дальше не идём, пока он не закрыт.
- **Ссылки в разборе** — на слои Figma с человеческой подписью: что за слой,
  ряд, экран («Whitener — ряд 1 «492», «стало»»), номер узла — только в адресе
  (`skills/_shared/protocols/guide-template.md`, «Разметка»).
- **Решение по пункту:** принять → в список применяемых; отклонение → как в
  исходнике, запись в `products/rider/deviations.json`; доработать Rider →
  задача Designer, пункт ждёт; вне рамок (F).
- **Где решение:** статус и формулировка PD — в `../navigation.json`, карточка
  на странице помечается решённой. Решение, которое пригодится в похожих
  случаях, — коротко в `skills/_shared/notes/audit-precedents.md`.
- **Неполный чекпоинт** (найден пробел в проверке) — недостающее добавляется
  пунктами в тот же чекпоинт, не в следующий шаг.
- **Аудит закрыт**, когда нет пунктов `open`: каждое изменение либо не меняет
  вид (точный токен, принятый сдвиг ниже порога), либо меняет его с согласия PD.

Статус изменения на странице: видно (рамка, порог 24) · ниже порога (пара
значений) · скрыто (под слоем или за кадром — серая пунктирная рамка) · не
применено (нет пары — красное на третьем клоне, пункт анкеты).
