# Semantic Color Tokens — Архитектурный гайд

> Этот гайд описывает архитектуру системы цветовых токенов: как они называются,
> структурируются и применяются на всех платформах. Он не описывает процессы
> и роли — это тема отдельного governance-гайда.
>
> Core Color Tokens описаны в отдельном гайде «Core Color Tokens — Архитектурный гайд».

---

## 1. Что такое Semantic Color Tokens

Семантические токены цвета используются в макетах с учётом контекста применения.
Мы применяем их для компонентов и блоков, чтобы задать нужный цвет и при
необходимости показать состояния элемента.

### Как формируется

Все семантические токены ссылаются на **Core Color Tokens** — базовые палитры цветов.
Если изменить HEX в Core Color Tokens, алиасы семантических токенов обновятся автоматически.

```
Core Color Token:
  jasper-65 = #2C64E3

Semantic Token:
  bg/accent/main → jasper-65 → #2C64E3
```

Цепочка всегда двухуровневая: **Core → Semantic**.
Semantic не обращается к Core напрямую через HEX — только через алиас.

На уровне Core палитры имеют нейтральные имена (камни, города и т.п.) и не знают
о ролях (`brand`, `status`, `product`). Роль задаётся только на семантическом уровне.

### Единый файл токенов для всех платформ

Все токены хранятся в одном Figma-файле для всех платформ сразу.
На этапе экспорта каждая платформа получает только релевантные токены —
через фильтрацию по морфемам (см. раздел «Морфемы»).
Синтаксис токенов адаптируется под платформу через Style Dictionary или
аналогичный инструмент.

Это намеренное решение: единый источник правды исключает рассинхрон между
платформами и упрощает обновления.

## 2. Структура папок

Все токены хранятся в папках по логике применения.

```
bg/
├── base/
│   ├── main
│   ├── main-secondary
│   ├── brand-fade
│   ├── card/
│   │   ├── main
│   │   └── main-secondary
│   ├── overlay/
│   │   ├── main
│   │   └── inverse
│   └── modal/
│       ├── main
│       └── main-secondary
├── accent/
│   ├── main
│   ├── main-secondary
│   ├── fade
│   ├── ghost
│   ├── states/
│   │   └── main-disable
│   └── product/
│       ├── marketplace/
│       │   ├── main
│       │   └── main-secondary
│       ├── status/
│       │   └── attention/
│       │       ├── main
│       │       └── main-secondary
│       └── additional/
│           └── [color-name]/
│               ├── main
│               └── main-secondary
└── component/
    ├── form
    ├── control
    ├── floating
    └── states/
        └── form-focused

text/       # аналогичная структура
icon/       # аналогичная структура
line/       # аналогичная структура
```

`ghost`-оттенки в semantic-слое ссылаются на прозрачные ступени палитр Core
из подпапок `alpha` (см. Core-гайд).

## 3. Структура имени токена

Название токена отражает весь путь от категории до морфемы:

```
[категория] - [тип] - [раздел] - [цвет] - [оттенок] - [иерархия] - [морфема]
```

Пример:
```
bg - accent - product - marketplace - main - secondary - static
```

Не все сегменты обязательны — используются только те, что нужны для однозначной
идентификации.

**Сегмент `[цвет]` в semantic-слое не обязан совпадать с именем палитры Core.**
На уровне Semantic используются смысловые имена (`brand`, `status`, названия
продуктов), даже если под ними лежат нейтральные палитры Core (`jasper`, `citrine`).

---

## 4. Категории

Первый сегмент имени токена. Определяет базовое место элемента в интерфейсе.

| Категория | Применение |
|-----------|-----------|
| `bg` | Фоны экранов и блоков, на которых располагаются другие элементы |
| `text` | Цвета текста |
| `icon` | Цвета иконок |
| `line` | Цвета обводок и линий |

**Правило:** любой цвет элемента интерфейса всегда относится к одной из этих
четырёх категорий.

---

## 5. Типы

Второй сегмент. Делит категорию на три части:

| Тип | Описание |
|-----|----------|
| `base` | Базовые поверхности. Не имеют состояний (hovered, pressed и т.п.) — состояния есть у компонентов, которые располагаются поверх них |
| `accent` | Акцентные цвета. Могут иметь состояния |
| `component` | Уникальные точечные цвета для отдельных компонентов (см. раздел «Компонентные токены») |

---

## 6. Разделы

Третий сегмент. Используется для группировки токенов внутри типа.

### Разделы в `base`

| Раздел | Описание |
|--------|----------|
| `card` | Базовые цвета карточек и островков |
| `overlay` | Затемнения и осветления фона |
| `modal` | Диалоговые окна и шторки |

### Разделы в `accent`

| Раздел | Описание |
|--------|----------|
| `product` | Брендовые цвета конкретных продуктов и разделов приложения (например, `marketplace`, `loyalty`, `premium`) |
| `additional` | Дополнительные цвета для инфографики: статистики, легенд карт, графиков, цветовых ассоциаций |
| `status` | Статусные цвета (`attention`, `success`, `warning`, `error`) |

**Разница между `product` и `additional`:**
- `product` — брендовые цвета зон/сервисов. Пример: раздел «Маркетплейс» имеет
  свой акцент, раздел «Программа лояльности» — свой.
- `additional` — цвета инфографики и визуализации данных. Не привязаны к
  конкретному продукту.

---

## 7. Оттенки

Четвёртый сегмент. Основное название токена внутри раздела.

| Оттенок | Описание |
|---------|----------|
| `main` | Основной насыщенный оттенок |
| `fade` | Пастельный оттенок |
| `ghost` | Цвет с прозрачностью, ссылается на `-aXX` ступени Core-палитр |
| `inverse` | Инверсивный цвет (для акцентных элементов превращает main в белый) |
| `transparent` | Полностью прозрачный |

### Иерархия оттенков

Порядок в иерархии строится по физическому оттенку:

- `main` — от тёмного к светлому
- `fade` — от светлого к тёмному
- `ghost` — от тёмного к светлому (как main), но через альфа-ступени Core
- `inverse` — иерархии нет

### Inverse: зачем не использовать один общий белый

Если использовать один общий белый токен для текста на акцентных фонах,
при смене брендового цвета он не обновится автоматически. `inverse` — это
алиас на белый через цепочку конкретного цвета.

Пример:

```
Core:
  jasper-0   = #FFFFFF
  jasper-60  = #7B2BE0

Semantic:
  brand-main    → jasper-60
  brand-inverse → jasper-0
```

Отдельных Core-токенов `white` и `black` нет — белый и чёрный живут как
крайние ступени палитр Core (0 и 100).

---

## 8. Иерархия (`-primary`, `-secondary`, `-tertiary`)

Пятый сегмент. Используется когда одного токена недостаточно и нужно несколько
уровней одного цвета.

```
bg-base-main             ← основной (primary не пишем — экономим место)
bg-base-main-secondary   ← вторичный
bg-base-main-tertiary    ← третичный
```

`-primary` явно не указывается: если нет суффикса иерархии — это и есть primary.

## 9. Морфемы

Морфема — это суффикс, который добавляет к токену дополнительное правило поведения.

### `-static` — статичные цвета

**Аксиома системы:** каждый семантический токен по умолчанию адаптируется к теме.
Он имеет одно значение в light mode и другое в dark mode.

Морфема `-static` применяется только тогда, когда токен не должен менять
значение между light и dark.

```
bg-accent-product-marketplace-main         → light: jasper-55 / dark: jasper-75
bg-accent-product-marketplace-main-static  → light: jasper-55 / dark: jasper-55
```

**Правило:** если токен только один (нет адаптивной версии), `-static` не пишется —
это лишняя морфема без смысла.

#### `-staticwm` — статичные цвета в White Label / Wealth Management режиме

Для продуктов с темизацией под партнёра или WM-режимом существует третий уровень:
помимо light/dark есть ещё партнёрские темы и WM-режим.

`-staticwm` фиксирует цвет во всех режимах, включая WM.

### `-states` — состояния

Морфемы для интерактивных состояний. Применяются в разделах `accent` и `component`.

```
bg-accent-states-...
bg-component-states-...
```

#### Шпаргалка по названиям состояний

| Состояние | Web | iOS | Android |
|-----------|-----|-----|---------|
| При наведении | `hover` | — | — |
| При нажатии | `pressed` | `pressed` | `pressed` |
| Активный | `active` | `active` | `active` |
| Недоступный | `disable` | `disable` | `disable` |
| В фокусе | `focused` | `focused-ios` | — |
| Ripple-эффект | — | — | `ripple-android` |

### `-ios`, `-android` — платформенные морфемы

Морфема платформы добавляется в двух случаях:

1. Токен используется **только на одной платформе** (на других отсутствует)
2. Токен присутствует на всех платформах, но его **значение различается** для
   конкретной ОС

```
bg-accent-states-focused-ios      ← фокусное состояние только на iOS
bg-accent-states-ripple-android   ← эффект тапа только на Android
```

**Механика экспорта:** токены с морфемой `-ios` подгружаются только в iOS-артефакт,
с `-android` — только в Android. Другие платформы их не получают.
Это обеспечивается на этапе экспорта из Figma через фильтрацию по морфеме.

## 10. Компонентные токены

Тип `component` в структуре папок предназначен для **точечных исключений** — токенов,
которые нужны конкретному компоненту и не имеют смысла на семантическом уровне.

**Компонентный уровень не является обязательным третьим слоем системы.**
Для большинства компонентов достаточно семантических токенов — дополнительный
алиас (component → semantic → core) создаёт избыточную индирекцию без реальной пользы.

Компонентный токен создаётся только когда:
- Два компонента используют один семантический токен, но должны разъехаться независимо
- Токен специфичен для группы компонентов и не имеет аналога в semantic-слое

### Нейминг компонентных токенов

Перед названием цвета и оттенка указывается группа компонентов:

```
bg-component-states-[группа]-[цвет]-[состояние]
```

Примеры групп:
- `control` — кнопки, чекбоксы, переключатели
- `form` — текстовые поля, поля ввода кода, суммы

Пример полного имени:

```
bg-component-states-control-accent-active
```

Для компонентных токенов допускается сокращение пути:
вместо `...-accent-additional-chart-fade` достаточно `...-chart-fade`,
если имя однозначно идентифицирует токен в контексте компонента.

## 11. Additional — цвета инфографики

`additional` — это дополнительные акцентные цвета для общей и продуктовой инфографики.

### Общая инфографика

Используется для дополнительных акцентов и визуального разнообразия:
статистика, легенды на интерактивных картах, графики, цветовые схемы залов.

```
bg-accent-additional-chart-a-main
bg-accent-additional-chart-b-main
bg-accent-additional-chart-c-fade
```

### Продуктовая инфографика

Дополнительные цвета, закреплённые за конкретными продуктами или сервисами.
Используются для цветовой ассоциации: Программа лояльности, Страхование, Маркетплейс.

```
bg-accent-product-loyalty-main
bg-accent-product-insurance-fade
bg-accent-product-marketplace-main
```

Цвета формируются из Core Color Tokens.

## 12. Коллекции static-lm / static-dm

Для White Label и WM-сценариев существуют специальные коллекции:

- `static-lm` — повторяет стандартную семантическую коллекцию, но только с
  одним режимом: light
- `static-dm` — только dark

```
Стандартная коллекция:
  bg-base-main → light: jasper-5 / dark: jasper-90

Коллекция static-lm:
  bg-base-main → jasper-5   (только light)

Коллекция static-dm:
  bg-base-main → jasper-90  (только dark)
```

### Переключение коллекций в Figma

Для смены коллекции в секциях и фреймах используется плагин
**Variable Collection Switcher**.

**Порядок работы:**
1. Отрисуйте флоу на основе одной коллекции
2. Скопируйте флоу
3. Выделите все копии и запустите плагин
4. Нажмите «Switch»

**Важно:**
- Выделенные экраны должны использовать дефолтный Appearance
- Переключайте light/dark mode для нужных экранов уже после применения плагина
- Не задавайте Appearance на выделенных фреймах до переключения коллекции
