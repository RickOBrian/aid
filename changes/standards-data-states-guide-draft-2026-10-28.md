# Состояния данных

> Статус: Draft · v0.1.0 · обновлено 2026-10-28

## 1. Назначение

Экран или блок, который показывает загружаемые данные, бывает не только в
«идеальном» виде. Данных может ещё не быть, может не оказаться совсем,
загрузка может не удаться. Этот гайд описывает, что человек видит в
каждом таком случае и как это называется.

Границы:

- **не** про состояния компонента (`pressed`, `disabled`, `loading` и
  другие) — это `component-states-guide`;
- **не** про ошибку поля формы — это состояние компонента `error`;
- про данные области экрана: список, лента, карточка с данными, экран
  целиком.

## 3. Четыре состояния данных

| Состояние | Когда | Что видит человек |
|---|---|---|
| `pending` | Данных ещё нет, идёт первая загрузка | Скелетон области или индикатор загрузки |
| `content` | Данные есть — сколько угодно, хоть одна запись | Данные |
| `empty` | Загрузка удалась, данных нет | `EmptyState`: почему пусто и что сделать |
| `failed` | Загрузка не удалась, показать нечего | `EmptyState`: что случилось и кнопка «Повторить» |

К `content` добавляются два признака — они не отменяют данные на экране:

| Признак | Когда | Что видит человек |
|---|---|---|
| `isRefreshing` | Данные есть, идёт обновление | Прежние данные + индикатор обновления платформы |
| `isStale` | Данные есть, но обновить не удалось (нет сети, сбой) | Прежние данные + `Banner`: данные могут быть устаревшими, кнопка «Повторить» |

### 3.1. Почему не `loading` и не `error`

Эти слова уже заняты состояниями компонента: `loading` — спиннер внутри
кнопки, `error` — ошибка поля формы. На экране обе оси встречаются
одновременно, поэтому имена не должны совпадать.

| Обычное слово | Состояние компонента | Состояние данных |
|---|---|---|
| Загрузка | `loading`, `skeleton` | `pending`, `isRefreshing` |
| Ошибка | `error` (только формы) | `failed`, `isStale` |

### 3.2. «Частичное» — значение, а не состояние

Одна запись в списке, незаполненный профиль, три карточки вместо десяти —
это `content` с малым количеством данных. По правилу «состояние против
значения» (`component-states-guide` §4) это не отдельное состояние:
оно не возникает от взаимодействия и не меняет, что рисовать.

Норма для малого количества данных: область с одной записью
выглядит задуманной — без пустых рамок под отсутствующие карточки и без
растянутого на весь экран единственного элемента. Компонентная часть —
`component-standards` §10.

## 4. Кто решает

Так же, как в `ds-component-architecture-guide` §7–8 (кроме статуса
`CollectionView` — см. ниже):

- **экран** знает состояние данных и решает, что рисовать;
- **компонент** рисует то, что ему передали пропом (`isSkeleton`,
  `isLoading`), и не знает об источнике данных;
- **Layout** только расставляет — логики выбора в нём нет.

| Состояние данных | Что рисует экран |
|---|---|
| `pending`, структура известна | Те же компоненты с `isSkeleton` |
| `pending`, структура неизвестна | Индикатор загрузки на область (компонент `Spinner` — после его внесения в гайд архитектуры 1.7.0) |
| `content` | Компоненты с данными |
| `content` + `isRefreshing` | Компоненты с данными + индикатор обновления платформы |
| `content` + `isStale` | Компоненты с данными + `Banner` над областью |
| `empty` | `EmptyState` с причиной (§5) |
| `failed` | `EmptyState` с причиной (§5) |

`CollectionView` в глоссарии архитектуры (§11) назван оркестратором, но
уровня у него нет. Предложение ★: это не компонент ДС, а паттерн экрана —
контракт выше, реализация в продукте; глоссарий поправить вслед
(вопрос 4 разбора).

## 5. Причины: `reason`

Пусто и сбой выглядят одинаково — иллюстрация, заголовок, текст,
действие. Отличаются текст и кнопка. Поэтому причина — значение `reason`
у `EmptyState` ★, а не вариант: вариант меняет оформление
(`component-standards` §8.1), а оформление здесь одно.

Почему это не новый компонент по `component-standards` §8.2 («меняется
смысл действия»): смысл самого `EmptyState` один — «показать нечего,
вот почему и что делать». Кнопка приходит слотом от экрана, компонент её
смысл не задаёт. Если PD увидит здесь разные компоненты — вопрос 3
разбора, вариант «б».

| Состояние | `reason` | Когда | Действие |
|---|---|---|---|
| `empty` | `first-use` | Человек ещё ничего не создал | Создать первое («Добавить адрес») |
| `empty` | `no-results` | Поиск или фильтр ничего не нашёл | Сбросить фильтр или изменить запрос |
| `empty` | `cleared` | Всё удалено или прочитано | Обычно без действия |
| `failed` | `offline` | Нет сети | «Повторить»; повторить сам при появлении сети |
| `failed` | `server` | Сбой на нашей стороне | «Повторить» |
| `failed` | `forbidden` | Нет прав на данные | Куда обратиться или вернуться назад |

Новая причина добавляется в эту таблицу, а не придумывается в продукте.

## 6. Переходы

### 6.1. Допустимые и недопустимые

| ✅ Допустимо | ❌ Недопустимо | Почему |
|---|---|---|
| `pending` → `content` / `empty` / `failed` | `content` → `pending` при обновлении | Данные пропадают и мигают заглушками; нужен `isRefreshing` |
| `content` → `content` + `isRefreshing` | `content` → `failed` при неудачном обновлении | Человек теряет то, что уже видел; нужен `isStale` |
| `failed` → `pending` по «Повторить» | Скелетон и `Spinner` в одной области сразу | Продолжение запрета `skeleton + loading` |
| `empty` → `content` | `empty` до окончания загрузки | «Ничего нет» показали, а данные пришли |

### 6.2. Зоны

У составного экрана у каждой зоны своё состояние данных. Одна зона может
быть в `failed`, остальные — в `content`. Это продолжение правила о
составном `loading` у Structural View (`ds-component-architecture-guide`
§8). Упавшая зона показывает `EmptyState` меньшего размера (проп `size`,
`naming-conventions` §4), а не ломает экран целиком. Набор размеров —
при описании `EmptyState`.

### 6.3. Время

Правила:

- индикатор не показывается, если данные пришли быстрее порога появления;
- показанный индикатор держится не меньше минимального времени — иначе
  мигает.

Значений в гайде нет: пороги — токены времени (пробел, вопрос 5 разбора).
Коллекции `motion` в стандартах пока нет: она заведена в Figma Rider под
Spinner, норма категории ещё не написана. Кандидаты имён —
`duration-delay-indicator` и `duration-min-indicator` (в Figma —
`Duration/Delay Indicator`, `Duration/Min Indicator`, по образцу
`Duration/Loop` → `duration-loop`), в одной анкете с нормой motion.

---

## 7. Текст сообщений

Минимум до стандарта текстов интерфейса (вопрос 6 разбора):

- заголовок говорит, что случилось, языком человека: «Нет интернета», а не
  «Ошибка сети»;
- текст говорит, что делать;
- у `failed` всегда есть действие;
- без кодов ошибок и без вины человека.

## 8. Доступность

Опирается на `accessibility` §6–7.

| Состояние | Web | iOS | Android |
|---|---|---|---|
| `pending` | `aria-busy="true"` на области; скелетон `aria-hidden="true"` | Скелетон скрыт (`accessibilityHidden(true)`); у области `accessibilityLabel` «Загрузка» | Скелетон скрыт (`clearAndSetSemantics {}`); у индикатора `ProgressBarRangeInfo.Indeterminate` |
| `empty`, `failed` | Текст в контейнере `role="status"`, который есть в DOM до смены состояния | `AccessibilityNotification.Announcement("…").post()` (iOS 17+) или `UIAccessibility.post(notification: .announcement, argument: "…")` | `Modifier.semantics { liveRegion = LiveRegionMode.Polite }` |
| `isStale` | `Banner` в том же контейнере `role="status"` | Объявление, как выше | `liveRegion = LiveRegionMode.Polite` |

Фокус: если смену состояния вызвал не человек (данные пришли сами) —
объявление, фокус не двигается. Если человек нажал «Повторить» и кнопка
исчезла — фокус переходит на заголовок области, чтобы не потеряться
(`accessibility` §6: «move focus or announce»). Кнопка «Повторить»
доступна с клавиатуры и скринридера.

## 9. Имена

### 9.1. Figma

- У `EmptyState` — свойство `Reason`, значения как в §5 с заглавной:
  `First Use`, `No Results`, `Cleared`, `Offline`, `Server`, `Forbidden`.
- Кадры состояний экрана в макете подписываются состоянием данных
  латиницей, как в коде: `Orders · pending`, `Orders · empty`.

### 9.2. Код

| | Web | iOS | Android |
|---|---|---|---|
| Состояние | `type DataState = 'pending' \| 'content' \| 'empty' \| 'failed'` | `enum DataState { case pending, content, empty, failed }` | `enum class DataState { Pending, Content, Empty, Failed }` |
| Причина | `type DataStateReason = 'first-use' \| 'no-results' \| …` | `enum DataStateReason { case firstUse, noResults, … }` | `enum class DataStateReason { FirstUse, NoResults, … }` |
| Признаки | `isRefreshing`, `isStale` | `isRefreshing`, `isStale` | `isRefreshing`, `isStale` |

Общие для платформ: значения `DataState` и `reason` в документации, как в
§3 и §5. Тип общий для всех экранов, поэтому без имени компонента в
префиксе — в отличие от `[Component]Variant`.

## 10. Правила и уровни

Уровни хранятся в машинном слое (`conformance-levels` §5); здесь — правила
и почему среди них нет `must`. Экран без нарисованного `failed` можно
опознать и перенести между продуктами: это дистанция от эталона, а не
поломка (`conformance-levels` §2).

Правила гайда:

- для области с загружаемыми данными нарисованы `pending`, `empty`,
  `failed`;
- имена состояний — из §3, не `loading` / `error`;
- обновление не возвращает область в `pending` (§6.1);
- у `failed` есть действие;
- при неудачном обновлении — `isStale` с `Banner`;
- упавшая зона составного экрана — `EmptyState` меньшего размера (§6.2).

## 11. Проверка

- Для каждой области с загружаемыми данными есть кадры `pending`,
  `content`, `empty`, `failed`?
- `empty` — с причиной из §5 и действием, где оно нужно?
- `failed` — с кнопкой «Повторить» или другим действием?
- Одна запись выглядит задуманно (§3.2)?
- Обновление не стирает данные (§6.1)?
- Имена `loading` и `error` не используются для экрана?
- Время индикатора — через токены, без чисел в макете и коде?
