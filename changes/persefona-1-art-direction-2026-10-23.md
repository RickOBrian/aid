## Что не так сейчас — коротко

Kit честно повторяет портал, а портал собирался из разных источников. Поэтому:

1. серые трёх температур в одной палитре;
2. статусы разной светлоты и насыщенности — читаются как цвета из разных наборов;
3. обложка и раздел с заголовком одного размера — у страницы нет главного;
4. мягкие бейджи держат три слоя (фон, рамка, текст) — шумно в ряду;
5. тени одним размытым слоем — элемент «плавает», а не лежит;
6. нет фокуса — клавиатурой интерфейс не читается.

## Пачка А. Цвет: одна температура нейтральных

**Было.** `graphite` собран из трёх источников (OKLCH):

| Ступень | Значение | Тон |
|---|---|---|
| 2, 3, 20, 30, 45, 50 | `#FAFAFA` … `#616161` | чистый серый, C = 0 |
| 5, 15 | `#EBEDF0`, `#D0D4DC` | холодный сине-серый, H ≈ 260 |
| 70 | `#2D2C2E` | фиолетовый, H ≈ 308 |

Рамка холоднее текста, текст теплее рамки — рядом это даёт «грязь», которую видно на
белых карточках. Вторичный текст на приглушённом фоне не проходит AA (4.23), отсюда
обход 7а.

**Стало.** Одна шкала: тон H = 290 (между `graphite-70` и `iolite`), насыщенность
0.002–0.008 — серый остаётся серым, но одного семейства с цветным акцентом.
Светлота ступеней та же, кроме `graphite-45`: темнее на 0.027 L, ступень не меняется.

| Токен | Было | Стало | Контраст |
|---|---|---|---|
| `graphite-2` | `#FAFAFA` | `#FAFAFB` | |
| `graphite-3` | `#F5F5F5` | `#F5F5F7` | |
| `graphite-5` | `#EBEDF0` | `#EDECF0` | |
| `graphite-15` | `#D0D4DC` | `#D4D3D9` | |
| `graphite-20` | `#BDBDBD` | `#BDBCC2` | |
| `graphite-30` | `#9E9E9E` | `#9E9DA3` | на белом 2.69 (как было, п. 6а) |
| `graphite-45` | `#757575` | `#6D6C72` | на белом 5.20 (было 4.61), на `graphite-3` 4.78 (было 4.23 ✗), на `graphite-2` 4.99 |
| `graphite-50` | `#616161` | `#616166` | на `graphite-3` 5.66 |
| `graphite-70` | `#2D2C2E` | `#2C2C2F` | на белом 13.9 |

**Почему.** Арт-дирекция начинается с нейтралей: это 90 % пикселей Kit. Одна
температура делает страницу «собранной»; лёгкий сдвиг к тону акцента связывает графит и
`#6A1FD0` без нового цвета. Попутно `text-secondary` проходит AA на всех трёх
поверхностях — обход 7а больше не нужен (подпись шапки таблицы может остаться
`text-primary`, это решает Standards · Persefona).

Имена и Semantic-ссылки не меняются. Прежние ответы PD не задеты: акцент — тот же
графит.

## Пачка Б. Цвет: статусы одного семейства, бейджи без рамки

**Было.** Текст статусов: L 0.497–0.541, насыщенность 0.111–0.178; `amber-45`
`#8A6A00` — тон 88, оливковый. Фоны: L 0.963–0.980. Мягкий бейдж — фон + рамка + текст.

**Стало.**

1. Текст всех статусов — L 0.50, насыщенность до 0.15 (у зелёного и жёлтого — предел
   sRGB); фон — L 0.965, C 0.022. Жёлтый сдвинут к янтарю (тон 70), без оливкового.

   | Токен | Было | Стало | Текст на своём фоне |
   |---|---|---|---|
   | `malachite-50` | `#1F7A3F` | `#077739` | 5.15 |
   | `malachite-5` | `#EEF8F1` | `#E9F8EC` | |
   | `amber-45` | `#8A6A00` | `#895706` | 5.50 |
   | `amber-5` | `#FFF8E6` | `#FDF1E4` | |
   | `garnet-50` | `#B3261E` | `#A8372C` | 5.80 |
   | `garnet-5` | `#FDEFEF` | `#FFEFED` | |
   | `lapis-50` | `#1F5BC4` | `#2D5FB7` | 5.53 |
   | `lapis-5` | `#EEF4FF` | `#EDF4FF` | |

   Ступени в именах не меняются: пересчёт по `(1 − L) × 100` даёт те же 50 / 45 / 5
   (у `amber-45` — 50; переименовать в `amber-50` до релиза — по решению Standards ·
   Persefona).

2. Мягкие бейджи (статусы и `vivid`) — **без рамки**: фон уже отделяет бейдж от
   поверхности. Рамка остаётся у нейтрального бейджа на `bg-surface-muted`, где фон
   сливается. Токены `line-accent-status-*` и `line-accent-vivid` бейджу больше не
   нужны: а) ★ удалить до релиза (запаса не держим); б) оставить для будущих
   плашек-уведомлений.

**Почему.** Статусы — система: одинаковая светлота делает их равными по весу, и глаз
читает смысл по тону, а не по «какой ярче». Оливковый жёлтый выглядел грязным рядом с
чистыми зелёным и красным. Бейдж в один слой спокойнее в ряду из 4–8 штук (обложка,
таблицы changelog) и ближе к современным системам.

## Пачка В. Типографика: иерархия страницы

**Было.** Размеры `11, 12, 13, 14, 16, 18, 28, 48`. Обложка и заголовок раздела —
оба 28 (`heading-l`). Между 18 и 28 — разрыв ×1.56, между 13 и 14 — 7 %, глазом не
различимо. Код — вес 500, тяжелее основного текста.

**Стало.**

| Стиль | Было | Стало |
|---|---|---|
| заголовок обложки | `heading-l` 28/36 | `display-l` 48/56 · −0.02em (стиль есть, не применялся) |
| `heading-l` | 28/36 · 500 | 32/40 · 500 · −0.01em |
| `heading-m` | 18/24 · 500 | 20/28 · 500 |
| `heading-s` | 16/24 · 500 | без изменений |
| `body-m` | 14/20 | 14/22 |
| `code-m`, `code-s` | вес 500 | вес 400 |

Размеры: `11, 12, 13, 14, 16, 20, 32, 48` (18 и 28 уходят, 20 и 32 приходят).
Интерлиньяж: `16, 20, 22, 24, 28, 40, 56` (36 уходит). Трекинг: новый шаг
`type-tracking--0_3` (= −0.3 px ≈ −0.01em у 32; трекинг в Figma — в px, округление к десятым, как `--1` и `0_6`).

**Почему.**

- Страница гайда или changelog начинается с обложки — она должна быть главной.
  Обложка 48, раздел 32, подраздел 20, текст 14 — шаг ×1.5 / ×1.6 / ×1.43: каждая
  ступень заметна, при двух весах (400, 500) иерархия держится размером.
- Persefona — страницы для чтения (гайды, changelog, аудит). 14/22 (1.57) читается
  легче 14/20 в абзацах по 3–6 строк; в таблицах и карточках 22 не мешает.
- Моно 500 рядом с текстом 400 выглядит жирнее: у Google Sans Code глаз крупнее.
  400 выравнивает «серость» набора.
- 13 остаётся только в `body-s` и `code-m` — у моно это оптический аналог 14.

**Отход от прежних решений.** 32/40, 20/28 и 14/22 в черновике были помечены «уходит» —
это решение сборки по аудиту, не ответ PD (PD 5а — шрифт Google Sans, он не меняется).
Если Standards · Persefona считает это ответом PD — вопрос к PD через Standards ·
Persefona.

## Пачка Г. Глубина и фокус

**Было.** `shadow-1` — `0 8 24` 12 %, `shadow-2` — `0 12 40` 14 %, чистый чёрный,
один слой. Токена фокуса нет.

**Стало.**

| Стиль | Стало |
|---|---|
| `shadow-1` | `0 1 2` `graphite-100-a6` + `0 4 12` `graphite-100-a8` |
| `shadow-2` | `0 2 6` `graphite-100-a6` + `0 16 40` `graphite-100-a12` |
| `line-focus` ⁺ | → `graphite-70`; кольцо 2 px с зазором 2 px |

Core: `graphite-100-a6`, `-a8` — новые; `-a14` уходит. `graphite-100` остаётся чистым
чёрным — ступень 100 по `core-color-tokens-guide`.

**Почему.** Двухслойная тень — как в жизни: плотная контактная тень показывает, где
предмет касается поверхности, широкая — насколько он поднят. Один размытый слой даёт
«ореол» и выглядит дешевле. Фокус — требование доступности (WCAG 2.4.7): без него
Presentbook и плагины не читаются с клавиатуры. Графитовое кольцо — тот же основной
акцент, без нового цвета.

⁺ новый токен; имя — по `semantic-color-tokens-guide`, ветка `line-*`.

**Проверка кольца фокуса** (просьба приёмки; страница 7:22, блок 8:45). Кольцо 2 px с
зазором 2 px цвета поверхности; нетекстовый контраст (WCAG 1.4.11) — 3:1 к соседнему:

| Случай | Контраст кольца | |
|---|---|---|
| графитовая заливка (`bg-accent-main`) на `bg-surface-main` | 13.9 к зазору | ✓ — зазор отделяет кольцо от заливки |

Предложение: а) ★ `line-focus-inverse` → `graphite-0` (13.9 на `bg-inverse-main`) для
фокуса на инверсной поверхности; б) не заводить, пока в Kit нет фокусируемого на тёмном.

**Решение Standards · Persefona 2026-10-23: б)** — `line-focus-inverse` не заводится, пока в Kit
нет фокусируемого элемента на `bg-inverse-main`; появится вместе с первым таким компонентом
(тост с действием). Сборка проверена: 70 / 44, `type-tracking--0_3` = −0.3 px принят.
