Значения `Swatch` — что в слоте образца (слот 72×36, как у `Solid`; кроме `Sample`
и `None`, у них слота нет):

| Swatch | Слот | Что переопределяется в экземпляре |
|---|---|---|
| `Bar` | без рамки; полоса высотой 16 у левого края, по центру слота; `spacing-64` помещается без обрезки; у `spacing-0` полосы нет — только подпись `0 px` | ширина полосы → переменная `spacing-*` |
| `Corner` | рамка 72×36, `bg-surface-muted`, обводка `line-hover`, обрезки нет | все четыре угла → переменная `radius-*` или `shape-corner-*`; `pill` даёт капсулу |
| `Shadow` | слот 72×56 без рамки, на подложке `bg-surface-muted`, обрезка включена; карточка 40×16, `bg-surface-main`, `radius-s`, у верхнего края с отступом 8, по центру по горизонтали (5б) | стиль эффекта → `persefona/shadow-1` или `shadow-2` |
| `Sample` | только при `Table=Type`: вместо слота — текст на всю ширину ячейки | стиль текста → `persefona/*`; текст — формулировка «Где применять» слово в слово (1а; источник — §5.1) |
| `None` | слота нет, в ячейке только значение | — |

**Отход от В5 и от слоя `Swatch` #370 §7.2** (рамка `radius-s` + `line-default`,
обрезка). `Bar` и `Shadow` без рамки: рамка читается как часть шкалы или режет
тень. `Corner` без обрезки и с обводкой `line-hover`: скругление и есть образец,
обводка `line-default` на `bg-surface-muted` почти не видна (так сейчас у плиток
радиусов). Нужно «принято» по этому отходу — вопрос 1.

Тень в строке (5б). Без обрезки тень `shadow-2` уходит под следующую строку и
режется рамкой таблицы. Поэтому слот `Shadow` обрезает содержимое сам, а запас под
размытие даёт его высота: у `shadow-2` тень уходит вниз примерно на 36 px, карточка
40×16 с отступом 8 оставляет под собой 32 px. Критерий приёмки — скриншот строки
`shadow-2`: среза тени у края слота не видно. Если 56 мало — высота слота
увеличивается и указывается в итоге сборки.

Столбцы `Table=Type` (ширина 1116, как у Core и Semantic):

| Ячейка | Ширина | Содержимое |
|---|---|---|
| Token | 300 | Name — имя стиля `persefona/display-l`; Path — параметры «Google Sans Medium · 48/56 · трекинг −1 px» |
| Value | 464 | Sample — текст самим стилем, `text-primary`; строка растёт по высоте образца |
| Tokens (шапка «Токены») | 352 | токены стиля: `type-family-sans-1 · type-size-48 · …`, code-s, `text-secondary` |

Столбца «Где применять» у `Type` нет — отход от В2: назначение стиля написано
самим образцом («Заголовок страницы»), второй раз его не повторяем.

Выравнивание по верху и базовая линия первой строки — как в `TokenRow` (#370 §7.2).
У `Sample` первая строка не совпадает с Name по базовой линии: высота строки
стиля от 16 до 56. Образец стоит по верху ячейки. Тогда крупный стиль занимает
строку целиком и не сдвигает соседние ячейки.

### 5.1 Источник текста `Sample` (после приёмки)

Условие 1а — текст образца берётся из «Где применять» черновика токенов слово в
слово. В черновике #354 §3.3 у текстовых стилей такого столбца нет: есть «Было в
портале», и назначение из него читается только у `code-m` («блоки кода») и `code-s`
(«версии, инлайн-код»). У остальных восьми стилей формулировки в черновике нет.

| Стиль | Образец сейчас на `Typography` 24:459 |
|---|---|
| `display-l` | Persefona · UI Kit |
| `heading-l` | Заголовок страницы |
| `heading-m` | Заголовок раздела |
| `heading-s` | Заголовок блока |
| `body-m` | Основной текст: описания, абзацы, ячейки таблиц. … |
| `body-s` | Вторичный текст: подписи, подзаголовки, пояснения под образцами. |
| `label-s` | Подпись элемента · метка |
| `label-xs-caps` | Шапка таблицы · надзаголовок |
| `code-m` | `bg-surface-main → graphite-0 · #FFFFFF` |
| `code-s` | `graphite-70 · #2C2C2F` |

Варианты:

- а) ★ источник — описание текстового стиля в Figma (`description`, сейчас у всех
  десяти пустое): вписать туда формулировки «Где применять» (для `code-m`, `code-s` —
  из #354 слово в слово, для остальных — по столбцу выше, без «Съешь же…»), образец
  повторяет описание. Генератор (#367 п. 3) берёт данные из файла, как и
  «Используется в»; описание видит и потребитель библиотеки;
- б) дописать столбец «Где применять» в #354 §3.3 отдельным PR и брать оттуда.

Сборке вариантов `TokenRow` вопрос не мешает: текст `Sample` — переопределение в
экземпляре, он нужен только при перестройке `Typography`.

Отличия от §3, найденные при сборке:

1. **`Bar`: ширина полосы — отступ, а не ширина.** Привязку ширины к переменной
   Figma в экземпляре не переопределяет: вызов проходит без ошибки, ширина остаётся
   как в компоненте. Отступ переопределяется. Поэтому полоса — фрейм «по
   содержимому» с `bg-accent-vivid-main`, ширина = отступ слева, привязанный к
   `spacing-*` (по умолчанию `spacing-16`), внутри — прозрачный слой 0,01×16 для
   высоты. У `spacing-0` полоса шириной 0,01 — не видна. Скрипт перестройки
   переопределяет `paddingLeft` слоя `Fill`.
2. **`Shadow`: слот 72×72, а не 72×56.** При 56 у нижнего края слота тень `shadow-2`
   темнее подложки примерно на 4 из 255 — срез заметен на светлом мониторе. При 72 у
   края 246 против 245 у подложки — среза нет. Замер — по пикселям снимка строки.
3. **`Type`: столбец «Токены» — текстовое свойство `Core`.** Это то же, что `Core`
   у `Semantic`: на какие Core-токены ссылается стиль. Нового свойства нет. Шапка
   столбца — «Токены», цвет текста — `text-secondary`.

Сверка §6 п. 1, часть Components: отпечатки 8 прежних вариантов (структура,
размеры, заливки, обводки, привязки, тексты) до и после совпали; сырых заливок,
обводок и радиусов в новых вариантах нет. Проба в файле — экземпляры `spacing-0`,
`spacing-64`, `radius-pill`, `shadow-2`, `display-l`
(`changes/persefona/snapshots/token-row/probe-components-2026-10-23.png`), после
снимка удалена; снимок сделан до увеличения слота `Shadow` до 72.
