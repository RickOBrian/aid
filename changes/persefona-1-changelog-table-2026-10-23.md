## 1. Что плагин требует от таблицы

Сверено по коду Token Comparator (`src/lib/changelogTable.ts`, `src/changelogFlow.ts`).

| Требование | Где в коде | Что значит для образца |
|---|---|---|
| Корень таблицы — `FRAME`, внутри есть слой `Changelog Table Body` | `findChangelogTable` | Образец после вставки отвязывают |
| Строки — `FRAME` с именем `Changes Row`, прямые дети `Changelog Table Body` | `writeUnpublishedRow`, фильтр `type === "FRAME"` | Строка не может быть экземпляром. Подкомпонент строки после отвязки корня остался бы экземпляром, и плагин бы его не увидел («нет ни одной строки») |
| В строке ровно четыре ячейки по порядку: версия, изменения, дата, автор | `row.children` | Порядок колонок фиксирован |
| Ячейка изменений — `FRAME` | там же | Фрейм, не экземпляр |
| Ячейки версии, даты, автора — любой узел с текстом | `firstText` → `findOne(TEXT)` | Подходит экземпляр «Ячейки таблицы» Kit |
| В ячейке изменений: экземпляр `__Changelog Badge`, за ним два текста — фраза и значения | `findTemplates` | Порядок слоёв: бейдж → фраза → значения |
| Разделитель записей — `FRAME` с именем `{separator}` | `findTemplates` | Фрейм 1 px, есть хотя бы в одной строке образца — иначе записи пойдут без разделителя |
| У бейджа первое свойство-вариант принимает `Added` / `Removed` / `Edited`, подпись — первый текстовый слой внутри | `setBadge` | Новый компонент бейджа. «Метке» это не подходит: у неё вариант `Тон` с другими значениями |
| Таблица ищется по `figmaTable.nodeId` из JSON чейнжлога на `main`; `fileKey` сверяется, только если он доступен плагину | `handleChangelogLoad` | См. §4 о проверке |

## 2. Lookup

Источник — файл Kit `YDjPxFrW1yXqm9RzBGQXuc`, по одной странице на компонент
(`componentsRoot` у Persefona — `null`, компоненты живут только в Figma, как пять
блоков #344). Образец сравнения — таблица Rider `CHANGELOG` 31:66 на `✅ Colors`
файла токенов Rider.

| Часть таблицы | В Rider | В Kit | Решение |
|---|---|---|---|
| Заголовок таблицы (имя артефакта) | локальный `__Changelog Header`, карточка 166 px | HeaderSection 4:20 — heading-l и подзаголовок | **Переиспользовать** 4:20 |
| Шапка колонок | локальный `__Changelog Table Header` ×4 | TableCell 4:31, `Variant=Header` — label-xs-caps на bg-surface-muted | **Переиспользовать** |
| Ячейки версии, даты, автора | фреймы `__Changelog Table Cell` | TableCell 4:31, `Variant=Default` — body-s | **Переиспользовать** |
| Рамка таблицы | фрейм со скруглением 16 и обводкой | «Таблица сравнения» 4:32 — line-default, radius-m | Взять тот же вид, но фреймом: таблицу сравнения целиком плагин читать не сможет |
| Бейдж вида изменения | `__Changelog Badge`, вариант `Change Status` | Badge 4:19 — тона `Success`, `Error`, `Info` | **Новый** `BadgeChangelog`, внутри — экземпляр Badge |
| Образец таблицы целиком | нет, фрейм собран вручную | нет | **Новый** `TableChangelog` |

Итог lookup: два новых компонента (`TableChangelog`, `BadgeChangelog`), три
переиспользуются. Отдельные компоненты шапки и заголовка колонки, как в Rider, не
нужны: в Kit уже есть равнозначные, и таблица чейнжлога будет выглядеть так же, как
таблица «было | стало».

## 3. Анкета component-gate

### TableChangelog

```
Component: TableChangelog
Figma source: файл Kit YDjPxFrW1yXqm9RzBGQXuc, новая страница (§5, вопрос 4)
Tokens required: bg-surface-main, line-default, radius-m (рамка);
  spacing-24 (отступ между заголовком и таблицей);
  через TableCell: bg-surface-muted, spacing-12, spacing-16,
  label-xs-caps, body-s, text-primary;
  ячейка изменений: spacing-12, spacing-16 (отступы), spacing-8 (шаг),
  body-s + text-primary (фраза), code-s + text-secondary (значения);
  {separator}: line-default
Variants: нет
Modes: light (Kit только light — решение PD 2026-10-23)
Proposed path: только Figma, sourcePath null (как блоки #344)
Confidence: high — состав задан кодом плагина и §6.5
Naming exception: no — TableChangelog: PD назвал ChangelogTable, Role первым по naming-conventions §4 (#362 0.4.1)
Architecture exception: yes — образец, который всегда отвязывают; строка —
  фрейм, не подкомпонент (§1, отход от формулировки 7а — §5, вопрос 1)
Review at: release
```

Состав образца (имена слоёв — контракт плагина, §6.5):

```
TableChangelog                       компонент, вертикаль, шаг spacing-24, ширина 920
├─ HeaderSection                     экземпляр 4:20, текст = artifact, подзаголовок выкл.
└─ Table                             фрейм: bg-surface-main, line-default, radius-m, обрезка
   ├─ Table Header                   фрейм, горизонталь
   │  └─ TableCell ×4                Variant=Header: Версия | Список изменений | Дата | Автор
   └─ Changelog Table Body           фрейм, вертикаль
      └─ Changes Row                 фрейм, горизонталь — одна строка
         ├─ TableCell                Variant=Default, 120, «Не опубликовано»
         ├─ Changes Cell             фрейм, заполняет ширину, вертикаль, шаг spacing-8,
         │  │                        отступы 12/16, обводка снизу line-default
         │  ├─ __Changelog Badge     экземпляр BadgeChangelog, Change=Added
         │  ├─ Description           body-s, text-primary
         │  ├─ Details               code-s, text-secondary
         │  ├─ {separator}           фрейм 1 px, заливка line-default, ширина — вся ячейка
         │  ├─ __Changelog Badge     Change=Edited
         │  ├─ Description
         │  └─ Details
         ├─ TableCell                Variant=Default, 112, пусто
         └─ TableCell                Variant=Default, 140, автор
```

Ширины колонок: Версия 120 (вмещает `10.10.10` одной строкой, «Не опубликовано» —
в две), Дата 112, Автор 140, Список изменений — остаток (548 при ширине 920). Ячейки
по высоте растягиваются на строку. Вертикальных линий между колонками нет, как в
«Таблице сравнения». Во второй записи образца стоит `{separator}`: плагин берёт его
как образец разделителя, а без него записи слипнутся.

### BadgeChangelog

```
Component: BadgeChangelog
Figma source: файл Kit, рядом с TableChangelog на его странице
Tokens required: через «Метку»: bg-accent-status-success-main / -error-main /
  -info-main, text-success / text-error / text-info, label-s, spacing-4,
  spacing-8, radius-pill
Variants: Change = Added | Removed | Edited (первое и единственное свойство-вариант)
Modes: light
Proposed path: только Figma
Confidence: high
Naming exception: no
Architecture exception: no
Review at: n/a
```

| Change | Tone у Badge | Подпись по умолчанию |
|---|---|---|
| Added | Success | Добавлено |
| Removed | Error | Удалено |
| Edited | Info | Изменено |

«Исправлено» и «Устарело» плагин пишет подписью поверх `Edited`. Внутри варианта —
экземпляр Badge, поэтому вид бейджа меняется вместе с Badge и не расходится с
остальным Kit.

Новых токенов нет: все значения выше уже есть в `persefona-core` и
`persefona-semantic`. Анкета token-change-gate не нужна.

## 4. Проверка плагина

План «вставить в копию файла и нажать „Записать изменения“» в таком виде не
сработает:

- плагин показывает только таблицы, чей `figmaTable` записан в JSON чейнжлога на
  `main` (список отдаёт сервер). У Kit такого JSON ещё нет, поэтому ни файла Kit, ни
  его копии в списке плагина не будет. `fileKey` плагин сверяет, только если он ему
  доступен, а id узлов в копии те же — на эту сверку полагаться нельзя;
- «Записать изменения» отправляет запись на сервер (по описанию потока в
  `changelogFlow.ts` сервер открывает или обновляет PR). Это не проба.

Предлагаю проверять в два шага:

1. **До приёмки — прогон кода плагина в Figma.** На странице `Архив` файла Kit:
   вставить экземпляр образца, отвязать, затем выполнить скриптом `writeUnpublishedRow` из
   `changelogTable.ts`, перенесённую из TypeScript без изменений логики (убраны только
   типы; разница с исходником — в документе вместе со снимками). Две записи: (а) первая
   строка «Не опубликовано» пересобирается с тремя изменениями
   `added` / `fixed` / `removed`; (б) первая строка переименована в `1.0.0`, плагин
   добавляет новую строку сверху. Снимки до и после, проверка: бейджи сменили
   вариант, подписи «Исправлено» и «Удалено», разделители между записями, ячейки
   растянулись. Отдельно проверить то, что по коду не доказать: переименование и
   `setText` текстового слоя внутри экземпляра «Ячейки таблицы», пустая дата, порядок
   слоёв в ячейке изменений — по `children`, а не по панели слоёв. Пробу удалить после
   снимков. Сервер и репозиторий не затрагиваются.
2. **Первое настоящее применение** — первая таблица Kit с `figmaTable` (чейнжлог
   коллекции `persefona-semantic`). Это отдельная задача по `changelog-guide`, она
   откроет обычный PR чейнжлога.
