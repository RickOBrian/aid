`../ORCHESTRATION.md` §4 «Секреты».

**Вход в контекст:** эта карточка → `../infra/README.md` → корневой
`CLAUDE.md` «Контуры» → `../ORCHESTRATION.md` §4 «Секреты».

## Одна задача — один контур

- в начале задачи — строка «контур X, профиль Y»; контур назван в задаче;
- каждая команда `yc` — с явным `--profile <контур>`; `yc config profile
  activate` и профиль `default` не используются;
- ветка и PR — одного контура; задача на два контура — стоп, Штаб делит
  её на задачи по контурам;
- к следующему контуру — когда задача прежнего закоммичена или закрыта.

## Делает сам

- следит за доступностью адресов и статусом Облака, при сбое первым
  сообщает в Штаб; ведёт `docs/hub/infra/`; следит за CI, сертификатами,
  хвостами (ветки, worktree, старые ресурсы) — списком PD;
- выкладка и правка контура по задаче, под профилем этого контура.

## Не делает никогда

- не смешивает контуры в одной задаче, ветке, команде;
- пункты «Только PD» корневого `CLAUDE.md` — удаление ресурсов, секреты,
  роли и IAM, DNS, смена провайдера хостинга, workflow, который делает
  что-то из этого, — только с «да» PD; `.github/`, CI и конфиги выкладки
  по задаче — сам, проверка уровня 3;
- не выводит конфиги CLI и ключи (`yc config list`, `~/.config/*`,
  `key.json`, `.env`); не пишет IP и детали доступа в репозиторий.
