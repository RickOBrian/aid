# Архитектура компонентов дизайн-системы

> Статус: Draft · v1.0.0

---

## 1. Четыре уровня компонентов

Каждый компонент в системе живёт на одном из четырёх уровней. Уровень определяет, за что компонент отвечает — и за что **не** отвечает.


| Уровень | Название            | Суть                                      |
| ------- | ------------------- | ----------------------------------------- |
| 1       | **Item**            | Голый контент: иконка, текст, картинка    |
| 2       | **Surface View**    | Контент в оболочке: фон + форма + отступы |
| 3       | **Structural View** | Оболочка со слотами и составным макетом   |
| 4       | **Layout**          | Группа компонентов: расстановка и скролл  |


**Быстрый тест для нового компонента:**

1. Нет фона, нет формы, нет отступов — только контент? → **Item**
2. Есть фон или форма вокруг одного основного контент-элемента? → **Surface View**
3. Есть несколько именованных слотов или составной внутренний макет? → **Structural View**
4. Группирует набор компонентов? → **Layout**

---

## 2. Как это выглядит вместе

Прежде чем разбирать уровни по отдельности — вот как они складываются в реальный экран:

```
AppSurface (фон экрана)
│
├── VStack (Layout)
│   ├── IslandProduct (Structural View)
│   │   ├── SurfaceMedia (Surface View)
│   │   │   └── Image (Item)
│   │   ├── Text (Item)
│   │   ├── BadgeStatus (Surface View)
│   │   │   └── Text (Item)
│   │   └── ButtonIcon (Surface View)
│   │       └── Icon (Item)
│   └── IslandProduct (Structural View) ...
│
├── WidgetBalance (Structural View)
│   ├── Text (Item)
│   ├── Number (Item)
│   └── HStack (Layout)
│       └── ButtonIcon (Surface View)
│           └── Icon (Item)
│
└── NavBar (Structural View)
    └── HStack (Layout)
        ├── ButtonIcon (Surface View)
        │   └── Icon (Item)
        └── Avatar (Surface View)
            └── AvatarImage (Item)
```

Три правила, которые видны из схемы:

- **Item** не знает о своём окружении
- **Surface View** и **Structural View** не задают себе внешние отступы — это задача Layout
- **Layout** не вмешивается во внутренний дизайн вложенных компонентов

## 3. App Surface и фоновые слои

App Surface не входит в четыре уровня компонентов. Это отдельный фоновый слой — то, на что UI ложится **без промежуточной оболочки**.


| Слой                     | Описание                                                                |
| ------------------------ | ----------------------------------------------------------------------- |
| **AppSurface**           | Базовый фон приложения                                                  |
| **PageSurface / Screen** | Фон конкретного экрана                                                  |
| **Section / Zone**       | Логическая зона внутри экрана со своим фоновым токеном, но без карточки |


Когда говорят «поставить прямо на фон» — имеют в виду именно этот слой. Между компонентом и фоном нет никакой промежуточной оболочки.

---

## 4. Level 1 — Item

*Голый актёр без костюма. Знает только, кто он, но не знает, на какой сцене стоит.*

Item — это базовый компонент, который содержит только контент. Никакого фона, никаких отступов. Только размер, цвет через токен и тип содержимого.


| Компонент      | Что это                                    |
| -------------- | ------------------------------------------ |
| Icon           | SVG-иконка в семантическом размере         |
| Text           | Типографический элемент с цветовым токеном |
| Image          | Фото или иллюстрация без рамки             |
| Number / Count | Числовое значение как чистый контент       |
| Dot            | Точка-индикатор как чистый контент         |
| AvatarImage    | Фото / инициалы без рамки — основа аватара |


**Правила нейминга Item**

Называются по типу содержимого, **без суффикса**.

✅ Icon　✅ Text　✅ Image  
❌ IconItem　❌ TextItem　← в индустрии Item = элемент коллекции

Суффикс Item допустим только в составных компонентах как элемент коллекции: List.Item, Menu.Item, Accordion.Item.

---

## 5. Level 2 — Surface View

*Актёр в нашивке или значке. Появилась оболочка — это уже не голый контент.*

Surface View — это минимальная оболочка вокруг **одного основного контент-элемента**. **Как только появился фон — это уже не Item.**

Оболочка даёт: **фон + форма + отступы**. При необходимости добавляются border, elevation, варианты, состояния.

> **Уточнение по составу:** Surface View может содержать вспомогательные элементы (например, иконка-индикатор рядом с текстом в Badge), если они не образуют отдельных именованных слотов и не несут самостоятельной смысловой роли. Как только появляются два равнозначных именованных слота — это уже Structural View.

**Типы Surface View**


| Компонент                   | Когда использовать                                           |
| --------------------------- | ------------------------------------------------------------ |
| **Badge** / **BadgeStatus** | Статус или флаг сущности. Статичен.                          |
| **BadgeCount**              | Числовой индикатор                                           |
| **Tag / Chip**              | Интерактивный: фильтр, токен ввода, выбор с удалением        |
| **IconSurface**             | Иконка на декоративном фоне, без действия                    |
| **ButtonIcon**              | Иконка на интерактивном фоне, с действием и состояниями      |
| **Avatar**                  | Фото / инициалы в рамке, с опциональным online-badge         |
| **AvatarButton**            | Avatar как интерактивная кнопка                              |
| **ButtonText**              | Текст (+ иконка) в интерактивной оболочке                    |
| **Switch** / **Toggle**     | Переключатель с оболочкой — одно компактное визуальное ядро  |
| **Checkbox** / **Radio**    | Контрол выбора с оболочкой — одно компактное визуальное ядро |


> **Примечание по StatTile:** вынесен в Structural View, так как содержит два равнозначных именованных слота — Label и Value. См. раздел 6.

Интерактивные контролы (Switch, Checkbox, Radio) относятся к Surface View, если их визуальное ядро компактно и неделимо. Если контрол включает внешний Label как отдельный слот — это уже Structural View.

**Правило нейминга Surface View**

Если есть устоявшееся смысловое имя — используй его: Badge, Tag, Button, Avatar.  
Если компонент абстрактный, то есть просто контент в оболочке, — используй суффикс Surface: IconSurface, MediaSurface.

---

## 6. Level 3 — Structural View

*Актёр в полном костюме на сцене. Несколько зон, роль, сценарий.*

Structural View — это компонент с несколькими **именованными слотами** и внутренним макетом. Он организует несколько Item и Surface View в осмысленную структуру.

Structural View отличается от Layout тем, что не только размещает элементы, но и задаёт компоненту **смысловую роль**: row, island, widget, menu, dialog.

**Строчные компоненты**

Row — самый частый Structural View


| Компонент          | Описание                                   |
| ------------------ | ------------------------------------------ |
| **ListRow**        | Универсальная строка для списков, настроек |
| **BottomSheetRow** | Для шторок                                 |
| **IslandRow**      | Для островков                              |
| **MenuRow**        | Для контекстных и выпадающих               |


**Контролы с внешним Label**


| Компонент         | Описание                                                  |
| ----------------- | --------------------------------------------------------- |
| **StatTile**      | Плитка метрики: слоты Label + Value (+ опционально Trend) |
| **FieldCheckbox** | Checkbox + Label как отдельный именованный слот           |
| **FieldRadio**    | Radio + Label как отдельный именованный слот              |


**Island и Widget**

Два понятия, которые легко перепутать — но у них разная роль:


|                    | Island                                  | Widget                                    |
| ------------------ | --------------------------------------- | ----------------------------------------- |
| Сколько на экране? | Много (сетка, список)                   | 1–3 штуки                                 |
| Роль               | Представляет **одну сущность**          | Представляет уникальный **мини-сценарий** |
| Состав             | Однородный (заголовок, список, контрол) | Может быть сложносоставным                |
| Отношение к сетке  | Элемент коллекции, лежит в Grid/List    | Элемент макета страницы                   |
| Примеры имён       | IslandRules, IslandHotel                | WidgetBalance, WidgetSummary              |


**Практическое правило:** можешь представить 10 таких рядом в сетке? → Island. Это уникальный блок с ролью и сценарием? → Widget.

**Island** — повторяемый контентный блок: товар, пост, профиль, статья. Лежит в Grid или List.

**Widget** — штучный мини-сценарий: баланс счёта, блок акций, погода, быстрые действия. Обычно стоит на экране как отдельный самостоятельный блок.

**Системные и уведомительные компоненты**


| Компонент      | Описание-пример                                               |
| -------------- | ------------------------------------------------------------- |
| **Banner**     | Горизонтальный блок-сообщение с иконкой, текстом и действиями |
| **Toast**      | Временное уведомление поверх контента                         |
| **EmptyState** | Состояние пустого списка: иллюстрация, описание, действие     |


**Навигация и системные оболочки**


| Компонент       | Описание                               |
| --------------- | -------------------------------------- |
| **NavBar**      | Горизонтальная полоса вверху           |
| **TabBar**      | Навигация внизу                        |
| **Menu**        | Контейнер для набора MenuRow           |
| **BottomSheet** | Плашка снизу поверх контента           |
| **Dialog**      | Модальное окно: Header + Body + Footer |
| **SidePanel**   | Боковая панель                         |

## 7. Level 4 — Layout

*Труппа на сцене. Кто где стоит и на каком расстоянии.*

Layout управляет расстоянием (gap), направлением, переносом строк и прокруткой. Он никогда не трогает внутренний дизайн вложенных компонентов и не принимает решений о том, **что** рендерить.


| Компонент       | Описание                                        |
| --------------- | ----------------------------------------------- |
| **VStack**      | Вертикальный стек с gap                         |
| **HStack**      | Горизонтальный стек с gap                       |
| **List**        | Вертикальный список с разделителями             |
| **GroupedList** | Список с именованными секциями                  |
| **Grid**        | Сетка с колонками и gap                         |
| **Carousel**    | Горизонтальный скролл набора Island-компонентов |
| **Wrap**        | Ряд с переносом — для тегов, чипов              |


> **Важно:** Layout не управляет состояниями empty / loading / error. Решение о том, что показывать — данные, скелетон, EmptyState или ошибку — принимает **родительский экран или CollectionView**. Layout получает уже готовый набор дочерних компонентов и только расставляет их.

## 8. Поведение компонентов

### Состояния

**Item** — собственных состояний нет. Получает визуальные изменения (цвет, opacity) от родителя через токены.

**Surface View** — несёт **локальные** состояния одного визуального ядра:


| Состояние | Описание                   |
| --------- | -------------------------- |
| default   | Нормальное состояние       |
| hovered   | Наведение курсора          |
| pressed   | Момент нажатия             |
| focused   | Фокус (клавиатура)         |
| selected  | Выбранное состояние        |
| disabled  | Неактивное состояние       |
| loading   | Ожидание внутри компонента |


**Structural View** — несёт локальные состояния и дополнительно:


| Состояние            | Описание                                                                |
| -------------------- | ----------------------------------------------------------------------- |
| expanded / collapsed | Для аккордеонов, шторок, разворачиваемых блоков                         |
| loading (составной)  | Отдельные зоны компонента могут быть в loading независимо друг от друга |
| disabled (составной) | Отдельные слоты могут быть disabled, не переводя весь компонент         |


### Lifecycle Structural View

Компоненты с поведением появления/исчезновения (BottomSheet, Dialog, Menu, Toast) требуют явного определения, кто управляет их lifecycle.

**Правило:** компонент **не управляет собственным появлением**. Он принимает проп `isVisible` / `isPresented` и управляет только анимацией внутри себя. Решение показать или скрыть компонент — всегда на стороне вызывающего экрана или координатора.


| Зона ответственности              | Компонент | Вызывающий экран |
| --------------------------------- | --------- | ---------------- |
| Анимация появления / исчезновения | ✅         | ❌                |
| Решение когда показать            | ❌         | ✅                |
| Решение когда скрыть              | ❌         | ✅                |
| Передача данных внутрь            | ❌         | ✅                |

## 9. Нейминг

### Формула имени

**[Role] + [Entity] + [Qualifier]**

- **Role** → тип компонента, всегда в начале: Button, Badge, Island, Widget, Row…
- **Entity** → тип содержимого или сущности: Text, Icon, Product, Balance…
- **Qualifier** → уточняющий постфикс (опционально): Floating, Compact, Inline, Grouped…

**Примеры:**  
`ButtonText` → Role=Button, Entity=Text  
`ButtonIcon` → Role=Button, Entity=Icon  
`IslandProduct` → Role=Island, Entity=Product  
`WidgetBalance` → Role=Widget, Entity=Balance  

> **Почему Role стоит первым:** IDE-автодополнение группирует компоненты по типу. Набирая `Button`, разработчик сразу видит все вариации: `ButtonText`, `ButtonIcon`, `ButtonDestructive`. Это важнее алфавитной близости Entity.

> **Исключение — устоявшиеся имена:** компоненты с общепринятым названием не следуют формуле: `Avatar`, `Badge`, `Tag`, `Chip`, `Dialog`. Формула применяется, когда роль неочевидна из одного слова.

### Таблица Role-суффиксов


| Role   | Уровень         | Когда использовать                 | Примеры                      |
| ------ | --------------- | ---------------------------------- | ---------------------------- |
| Button | Surface View    | Интерактивная оболочка с действием | ButtonText, ButtonIcon       |
| Badge  | Surface View    | Компактный статусный индикатор     | BadgeStatus, BadgeCount      |
| Tag    | Surface View    | Статичная метка                    | TagFilter, TagCategory       |
| Chip   | Surface View    | Интерактивный компактный элемент   | ChipFilter, ChipInput        |
| Row    | Structural View | Строчный компонент                 | RowList, RowMenu             |
| Island | Structural View | Повторяемый контентный блок        | IslandProduct, IslandHotel   |
| Widget | Structural View | Штучный сценарный блок             | WidgetBalance, WidgetSummary |


### Именование слотов

Structural View должен явно декларировать именованные слоты. Стандартные имена:


| Слот       | Позиция         | Описание                              |
| ---------- | --------------- | ------------------------------------- |
| `leading`  | Левый / верхний | Иконка, аватар, медиа                 |
| `content`  | Центральный     | Основной контент: заголовок, описание |
| `trailing` | Правый / нижний | Контрол, кнопка, badge                |
| `header`   | Верхняя зона    | Заголовок блока                       |
| `footer`   | Нижняя зона     | Действия, дополнительная информация   |


Имена слотов должны быть одинаковыми на всех платформах (React props, SwiftUI ViewBuilder parameters, Compose content lambdas).

### Частые ошибки нейминга

**Называть оболочку айтемкой**  
Badge, BadgeCount, IconSurface, Tag, Avatar — всё это Surface View, не Item. Как только есть фон и/или форма — это уже не Item.

**Суффикс Surface там, где есть устоявшееся имя**  
Пиши Badge, не TextSurface. Avatar, не AvatarSurface.

**Суффикс Item не в коллекции**  
IconItem ничего не говорит — это просто Icon. Item зарезервирован для элементов коллекций внутри составных компонентов.

**Island вместо Widget или наоборот**  
Island — повторяемый контентный блок, который ложится в Grid или List.  
Widget — штучный сценарный блок, выполняющий конкретную роль.

## 10. Чеклист при создании компонента

**Уровень**

- [ ] Нет фона, нет формы — только контент? → Item
- [ ] Есть фон или форма вокруг одного основного контент-элемента? → Surface View
- [ ] Есть два и более именованных слота или составной макет? → Structural View
- [ ] Группирует набор компонентов? → Layout

**Нейминг**

- [ ] Имя начинается с Role, затем Entity, затем Qualifier (если нужен)?
- [ ] Суффикс Item — только для элементов коллекций?
- [ ] Island = повторяется в сетке; Widget = штучный сценарный блок?
- [ ] Имя уникально в рамках библиотеки?

**Свойства**

- [ ] Item: нет padding / background, есть typography-style и color-token?
- [ ] Surface View / Structural View: нет внешнего margin, есть variant / shape / size?
- [ ] Layout: задаёт только gap и направление, не принимает решений о контенте?

**Слоты (только для Structural View)**

- [ ] Все слоты именованы по стандартной схеме (leading, content, trailing, header, footer)?
- [ ] Имена слотов одинаковы на всех платформах?

**Lifecycle (только для Structural View с появлением/исчезновением)**

- [ ] Компонент принимает `isVisible` / `isPresented`, но не управляет решением показать себя?
- [ ] Анимация появления инкапсулирована внутри компонента?

**Состояния и анимации**

- [ ] Локальные состояния — на уровне Surface View / Structural View?
- [ ] Составные состояния (зоны независимы) — только Structural View?
- [ ] Анимации соответствуют уровню компонента?

## Глоссарий


| Термин              | Определение                                                                                        |
| ------------------- | -------------------------------------------------------------------------------------------------- |
| **Item**            | Компонент-контент без оболочки: нет фона, формы, отступов                                          |
| **Surface**         | Визуальная оболочка: фон + форма, отделяющая контент от окружения                                  |
| **Surface View**    | Компонент с минимальной оболочкой вокруг одного основного контент-элемента                         |
| **Structural View** | Компонент с именованными слотами и составным внутренним макетом                                    |
| **Layout**          | Контейнер для группы компонентов, управляющий только расстоянием и прокруткой                      |
| **App Surface**     | Фон экрана — слой, на который UI ложится без промежуточной оболочки                                |
| **Island**          | Повторяемый контентный блок для сетки или списка                                                   |
| **Widget**          | Штучный мини-сценарий, стоящий как самостоятельный блок на экране                                  |
| **Slot**            | Именованная точка вложения контента: leading, content, trailing, header, footer                    |
| **Variant**         | Семантическая вариация компонента: primary, secondary, ghost, danger                               |
| **Lifecycle**       | Управление появлением и исчезновением компонента — всегда на стороне вызывающего экрана            |
| **CollectionView**  | Родительский контейнер, принимающий решение что рендерить: данные, скелетон, EmptyState или ошибку |
