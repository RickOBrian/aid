Switch

Surface View medium

Карточка компонента с editable-слоем: component-side значения редактируются на месте (typed dropdown для токенов, инлайн — для прямых значений).

Preview

Уровень архитектуры

Surface View — «переключатель с оболочкой, одно компактное визуальное ядро», прямой пример из ds-component-architecture-guide.md (раздел 5, таблица «Типы Surface View», строка Switch / Toggle).

Нарушения

  • Gap

    width: 48px; height: 30px (трек) и 16px / 22px (knob, off/on) — захардкожены; semantic size-токена для габаритов Switch не существует, нужно предложить новый (например, size-control-switch-track, size-control-switch-knob), аналогично уже задокументированному пробелу у ButtonIcon.

  • Quality note

    30px высота трека меньше touch target 44px (Web), зафиксированного в правилах проекта.

  • Quality note

    Figma-референс использует мягкую тень (elevation) на knob — в реализации сознательно опущена: semantic-токена уровня shadow/elevation в системе пока нет, а хардкод box-shadow: rgba(...) запрещён no-hardcode-color-protocol.md. Нужен отдельный semantic-токен (например, shadow-control) — открытый вопрос Principal Designer.

  • Quality note

    Disabled-состояние реализовано с opacity: 40% по правилу проекта (.cursorrules: «Disabled = opacity 40%»), а не с 50%, как в Figma-референсе — конкретные значения гайда иллюстративны, не являются ограничением реализации (см. CLAUDE.md, «Design System vs UI Kit»).

Confidence

medium — уровень подтверждён прямым примером из architecture-гайда, но source of truth — Figma component set (4 варианта State × Disabled), не production-код; geometry (48×30, knob 16/22px, offsets 7px/4px) снята напрямую с Figma, цвета — смаплены на существующие semantic-токены по смыслу (accent main / card secondary / card main), не пиксель-в-пиксель с оригинальных hex.
