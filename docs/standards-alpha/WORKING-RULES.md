# Рабочие правила Стандартов

> Обновлено 2026-10-21 · standards-5 (AID-32, #282)

Правила, по которым работает роль Standards и любой Claude, который
применяет стандарты AID. До standards-5 они жили только в памяти чата на
машине PD; теперь канон здесь, в памяти чата — только указатели на этот
файл. Позиция и права роли — карточка `docs/hub/agents/standards.md`,
здесь не повторяются.

Правило PD 2026-10-21: «Его клод должен по стандартам знать и применять их
аналогично мне. Стандарты для этого и должны не у меня на компе быть, а
храниться в гите или на сервере». Отсюда — правило этого файла: **новое
правило работы сразу пишется в репозиторий** (сюда, в стандарт или в
`CLAUDE.md` продукта), а не в память чата.

---

## 1. Вход в контекст

В начале сессии, по порядку:

1. `docs/standards-alpha/PLAN.md` — волны, статусы, очередь задач;
2. `docs/standards-alpha/DECISIONS.md` — принятые решения (ADR);
3. `docs/standards-alpha/OPEN-QUESTIONS.md` — что ждёт решения PD.

Реестр стандартов с версиями — `standards-registry.json`. Состояние
корпуса — `node scripts/check-docs.mjs`: ноль ошибок и ноль
предупреждений.

Статусы в `PLAN.md` перед началом сверять с фактом — они уже дважды
отставали.

## 2. Записи

- Новое решение — новой записью ADR; старые не переписываются.
- Вопрос к PD записывается в `OPEN-QUESTIONS.md` **в момент появления**, а
  не когда о нём вспомнили; решённый закрывается ссылкой на ADR в тот же
  заход (ADR-034).
- Решение PD по аудиту макета — в JSON аудита (`decisions`), обобщаемое —
  коротко в `skills/_shared/notes/audit-precedents.md`.

Почему: проект живёт много сессий; решение, которое жило только в
переписке, дважды чуть не терялось.

## 3. Стандарт и продукт

- **Расхождение продукта со стандартом — не дефект.** Токены и стили
  продукта вправе отличаться от эталона. Аудит фиксирует расхождение как
  факт; приведение к стандарту — отдельным решением PD (ADR-036).
  Формулировки вида «блокирует, пока не приведено» — ошибка.
- Отклонение оформляется записью (`conformance-levels` §6), не молча.
- К каждой задаче — свои предложения, без запроса (карточка роли,
  «Позиция»).
- Продукты: ключевые — Driver и Rider; Flot и Taxi — временные, со
  статусом `transitional` и полем `mergesInto` в `products/registry.json`.
  Рабочие файлы Figma продукта — `figmaFiles` в
  `products/<id>/product.json`; папки — `figmaFolders` в
  `products/registry.json`.

## 4. Ссылки для людей

Подпись ссылки — по смыслу, ID — только в адресе
(`skills/_shared/protocols/guide-template.md` §6, решение PD 2026-10-19).
Действует и в ответах в чате, и в таблицах разбора с PD.

## 5. Чейнжлог правок в библиотеках

Решение PD 2026-10-20 (стандарт — `changelog-guide`, `release-gate`):

- правки Стандартов в библиотеках Figma по аудиту (например, новый токен)
  вносятся в чейнжлог **вручную с PD**: запись «Не опубликовано» в
  таблицу чейнжлога в Figma и в JSON;
- в `main` запись попадает **только с версией** — пока Presentbook не
  умеет показывать `version: null`;
- версию и запись в чейнжлог Стандарты не пишут вне границы релиза
  (корневой `CLAUDE.md`, три запрета).

## 6. Figma

- MCP подключён под аккаунтом «Sergey AI» (организация WB FZE). При 403
  первым делом — `whoami`: видно, жив ли доступ и какие планы.
- Ограничения `use_figma`: ответ ≤ 20 КБ, один файл за вызов, одна смена
  страницы за вызов.
- Компоненты и стили сверяются по префиксу ключа (8 символов), не по
  имени: имена в библиотеках меняются (публикация Rider Icons 2026-10-21
  переименовала часть иконок), ключ — нет.

## 7. Аудит макета для разработки

Решения PD 2026-10-18 — 2026-10-20 по пилоту rider-1. Подробный порядок —
`products/rider/audits/rider-1/tools/README.md` (ветка
`standards/rider-1-audit-navigation`, в `main` — с PR аудита); после
пилота — кандидат в протокол `skills/_shared/protocols/` (предложение
Стандартов, ждёт итога пилота).

- Исходник — только чтение; работа идёт в копии из
  `figmaFolders.handoff`.
- Аудит собирается в самом файле: страница «🔍 Аудит» в копии,
  «было → стало» глазами, находки карточками.
- **«Стало» принимается только по снимку «было | стало»**, не по
  структуре слоёв.
- Разбор с PD — по одному пункту, строго по номерам; простыми словами:
  что не так и что предлагаю, ссылки на слои с подписью по смыслу.
  Всплывшее по ходу — сразу пунктом чекпоинта. Задачи Designer — пачкой в
  конце чекпоинта, через Штаб.
- Страницу передачи разработчику не помечать Ready for dev; удалять её
  после приёмки — только спросив PD.

## 8. Git

Сверх «Git-полномочий» корневого `CLAUDE.md`:

- force-push даже в свою ветку — только с «да» PD; вместо rebase — merge
  `main` в ветку.
- правка файла, который входит в зеркало плагина `aid-standards`
  (`plugins/aid-standards/mirror.json`: `skills/`, `products/`, `tokens/`,
  реестр и другие), — в том же PR `node scripts/sync-plugin-mirror.mjs`
  и коммит копий; иначе инженеры получат устаревшие стандарты (#348).
