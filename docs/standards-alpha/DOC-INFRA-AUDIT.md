# Аудит документов как системы

> 2026-09-20 · охват: 40 файлов `skills/_shared/`, 17 правил `.cursor/rules/`,
> 8 скиллов, корневые инструктивные файлы

Аудит не про содержание гайдов — про то, как файлы названы, связаны,
проверяются и обрабатываются. Результаты сгруппированы по тому, насколько
они ломают работу.

---

## 1. Форма документов существует только на бумаге

Скилл `guide-lint` v1.0.0 проверяет форму по чеклисту. Фактическое
соответствие корпуса:

| Требование guide-lint | Соблюдают |
|---|---|
| Строка статуса под заголовком | 7 из 40 |
| Нумерация разделов | 3 из 40 |
| Раздел Changelog | 27 из 40 |
| `metadata.version` | 34 из 40 |
| Frontmatter вообще | 39 из 40 |
| `name` совпадает с именем файла | 39 из 40 |

Вывод: скилл написан, но по корпусу ни разу не проходил. Правило, которое
не исполняется, хуже отсутствующего — оно создаёт ложное ощущение контроля.

Отдельно: `claude-skills-guide.md` (29 КБ) вообще без frontmatter;
`tracks-2-3-draft-notes.md` объявляет `name`, не совпадающий с файлом.

## 5. Плоская папка смешивает четыре жанра

В `skills/_shared/` лежат вперемешку:

| Жанр | Примеры | Публикуется |
|---|---|---|
| Стандарты | `token-rules`, `component-standards`, `platforms`, `accessibility` | да |
| Процессные протоколы | `git-workflow`, `changelog-guide`, `claude-skills-guide` | нет |
| Архитектурные логи фич | `github-sync-architecture` (52 КБ), `token-comparator-release-guide` (32 КБ) | нет |
| Черновики и заметки | `tracks-2-3-draft-notes`, `ui-trends-2026`, `space-context` | нет |

Публикуется один жанр из четырёх, но отличить их можно только прочитав.
Инструмент, который захочет «взять все стандарты», не имеет признака,
по которому их отобрать.

## 6. Именование не системно, и это ломает аудит

Суффиксы в одной папке: `-guide` (14 файлов), `-standards`, `-conventions`,
`-strategy`, `-protocol`, `-context`, `-notes`, `-feature`, и вовсе без
суффикса (`platforms`, `accessibility`).

Последствие конкретное: `guide-lint` аудирует по маске `*-guide.md`.
Под неё не подпадают 26 файлов из 40 — включая `component-standards.md`,
главный документ, который мы собираемся публиковать.

Префикс `ds-` стоит у четырёх файлов без правила, когда он нужен.

## 8. Что предлагаю

### 8.1 Признак жанра во frontmatter — сразу, без риска

Добавить поле `kind`: `standard | protocol | architecture | notes`.

Ноль переездов, ноль сломанных ссылок. Сразу даёт: отбор «все стандарты»
для публикации и инструментов, маску аудита по жанру вместо имени файла,
явное разделение того, что читает пользователь, и того, что читаем мы.

### 8.2 Маска аудита — по жанру, а не по имени файла

`guide-lint` переводится с `*-guide.md` на `kind: standard`. После этого
именование перестаёт влиять на полноту проверки, и можно не переименовывать
файлы ради того, чтобы они попали в аудит.

### 8.3 Проверки становятся исполняемыми

Скилл запускается человеком и поэтому не запускается. Нужен скрипт
`scripts/check-docs.mjs`, проверяющий механически:

- форму (frontmatter, шапка, changelog, нумерация);
- живость каждой ссылки на файл;
- совпадение версий `.md` ↔ `.json` ↔ `standards-registry.json`;
- дубли по полю `name:`;
- соответствие реестра реальному состоянию папки.

Вызывается руками и в `prebuild` портала — там уже есть цепочка из четырёх
скриптов, встроиться дёшево. Публикация с битой ссылкой должна падать, а не
уезжать в прод.

### 8.4 Физическая раскладка по жанрам — после публикации альфы

```
skills/_shared/
├── standards/      публикуемые стандарты
├── protocols/      внутренние процессы
├── architecture/   технические логи фич
└── notes/          черновики
```

Почему не сейчас: мы одновременно переписываем содержание пяти гайдов.
Переезд 40 файлов в это же время превращает любой конфликт в ручной разбор.
Делать одной атомарной операцией после публикации альфы, со скриптом
переписывания ссылок и прогоном `check-docs` до и после.

### 8.5 Починить инструктивные файлы

`CLAUDE.md` — убрать `.claude/skills/`, описать реальную раскладку.
`PROJECT_STRUCTURE.md` — генерировать скриптом, а не поддерживать руками:
он протухает быстрее, чем его правят.

### 8.6 Устранить третий дубль

`skills/_shared/ds-component-spec.md` (v1.2.0) против
`skills/ds-component-spec/SKILL.md` (v1.3.0) — решить, что канон, второй
удалить. Скорее всего канон — SKILL.md: он новее и лежит в папке скилла.
Нужна сверка на предмет уникального содержания, как с архитектурным гайдом.
